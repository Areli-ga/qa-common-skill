需求背景

v1.32.0 已把"常规音频 AI 生成 + 音频组上传 Key + 双维度审核 + 音色预设"跑通。上线试用后暴露三个新需求：
上传模板是"提前一次性批量灌 Key"，但实际制作中有时需要补一个/几个新 Key（漏配、临时新增旁白），目前只能重新走模板，成本高；
导入 JSON 后表格 Key 顺序与 JSON 内容顺序不一致，音频组按顺序逐条审核/校对时频繁错位（比如少了某句语音/要改某几句语音时），影响效率；
音色预设目前只覆盖 Max 家族中的儿童/旁白角色，缺少家长与长辈角色（爸爸/妈妈/爷爷/奶奶），课程后续会用到。





产品目标

录入更灵活：Admin 支持在已有课程中直接新建单条语音 Key，并生成对应中文翻译/音频；
顺序可信：导入即所见——admin音频管理列表顺序严格跟随 JSON 内容顺序，音频组按序作业不再错位；
音色补齐：新增几个家庭音色预设，统一接入Admin

需求详情

新建 Key（English Review Tab）
入口与交互
English Review Tab 工具栏左组新增 「+ 新建 Key」 按钮（紧邻 Import）。
image.png

点击打开「新建语音 Key」弹窗。
弹窗底部按钮：
保存：保存当前条 → 关闭弹窗，列表定位并高亮新行。
取消：放弃当前未保存内容。
校验规则
Key 唯一性：与当前课程已有 Key 比对，重复则行内报错"该 Key 已存在"，阻止保存。
Key 命名：不符合字符规则时即时报错。
English Text 非空：空值阻止保存。
校验全部前端即时反馈 + 后端二次兜底（防并发重复建 Key）。
保存后行为
保存成功后，按确认口径执行 "EN 生成 → 同步 ZH 翻译+音频 → 其他多语种手动"：
排序落位：新建 Key 的 order = 当前课程最大order + 1，即追加到列表末尾
三个 Tab 表现：
EN Tab：立即出现新行。
ZH Tab：因已自动级联翻译，立即出现新行。
Other Lang Tab：暂不出现，待用户手动触发翻译后出现。

JSON 导入排序一致
导入即所见：JSON 内容里 Key 的先后顺序，就是表格展示、导出、ZIP 打包的顺序，形成"导入顺序 = 管理顺序 = 导出顺序"的闭环。
本期不支持导入后手动拖拽重排（已确认）；顺序唯一真相来源是导入的 JSON。
排序字段
新增字段order（整数，按课程维度，作用于 Key 粒度）。
表格默认排序：order 升序（EN / ZH / Other 三 Tab 一致）。
Other Lang Tab 每行是 (key, target_language)：主排序按所属 Key 的 order，次排序按 language 的固定既定顺序，保证同一 Key 的多语种聚拢且稳定。
导入解析规则
解析 JSON 时，按 Key 在 JSON 中的出现顺序依次赋值 order = 0,1,2,…。

新语音模型接入
音频组为每个家庭音色提供：
干净的音频样本（时长按 Ryan 要求）；
角色描述（性别 / 年龄段 / 性格 / 情感基调）或音色参数；
展示名。
Ryan 在 GiggleAITool 完成克隆，每个预设产出唯一 voice_model_id + 展示名 + 支持语言清单（如 ['en','zh',…]）。
后端拉取预设清单 → 三个 Tab 的 Voice Model 下拉自动出现新音色；"可用音色预设"信息弹窗展示新增项（展示名 + 支持语言）。
