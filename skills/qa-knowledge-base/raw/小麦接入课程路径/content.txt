需求背景

小麦拥有的场景能力、主对话能力，可以封装出来，放入课程路径上，包装为一个课程。

产品目标

以最小开发量将小麦对话能力接入课程路径，形成一个可排入路径的对话课节点。
以多图文的故事书为首期的接入内容。

主要特性

① 路径游戏流程：Onboarding 对话开场 -> Play 游戏 -> Closing 对话收尾 
② 接入消息列表最新的能力。

路径配置

鉴于我们现在有没有对印尼语之类的国家，没有做一些单独的课标或者课程路径。Mai 是使用母语跟用户进行沟通的。我们现在母语支持英语、中文以及印尼语。目标范围之内，进入 Mai 的当前支持的语言，非现在小麦目标语言的用户，我们指定 language 规则为英语。
路径上展示小麦形象的插图。
一个课程入口，我们暂定只绑定一个scene id。不走小麦推荐（即使在对话的视觉上，用户侧会认为是小麦推荐出来的）。

流程


按照：Onboarding 对话开场 -> Play 小麦游戏模版（比如对话课） -> Closing 对话收尾 流程执行。
Onboarding，包含的话题可以有：
询问姓名；
阶段性学习报告：小麦理解当前用户的学习状态，刚刚发生了什么，然后能够承接住学过的内容并进行总结，从而顺畅地过渡到一个总结课里面；
其他可以在主对话、并且可受 prompt 控制的玩法：角色扮演还、猜单词变形等等
课程：对应 scene id 
Closing，询问用户对于刚刚课程的体验，建立约定，进入 memory report 并埋点上报。
不需要 Word Play，不需要 Quiz。

查询一个 unit 下面有哪些课程（包含游戏、单词、课程... ）
每个课程在 admin 里配置的知识点或单词
查询完课状态：
用户对该课程的学习进度（对应出他的星级）
Lesson Material: 文本框可填入场景 ID
提供是否启用 Lesson Material 的选项
当启用（为on）的时候：
Prompt：需要在 Prompt 中强调小麦的目标以及工作流程：以引导用户学习一节课为目标，通过 Conversation - greeting 到 Lesson，再回到 Conversation - closing。
🌟 完成概念：以 Lesson Material （当前为多图故事书）的课程完成为目标，映射用户访问多图故事的页码进度，从 0 到 max_page,  read_page 映射为 1-3星。向下取整。
未进入scene：0
0-33%: 🌟
33%-66%：🌟🌟
66%-100%：🌟🌟🌟
当不启用（为off）的时候：
Prompt：需要在 Prompt 中强调小麦的目标，需要定义结合当前场景的 prompt，比如可以快速地总结学习句子练习。
完成概念：不定义明确的完成概念，按照对话轮次，产生完整的一轮对话，即定义为“三星”。
其他：

不消耗电量，UI上不显示电量组件。
