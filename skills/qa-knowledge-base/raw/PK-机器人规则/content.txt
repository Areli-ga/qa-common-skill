PK 机器人规则
以下内容，我描述需求后让 AI 帮忙生成，如有错误，望开发老师海涵哈哈哈哈😄


范围：只覆盖机器人（对手生成）。计分/题型/结果页见《随机 PK PRD》。
得分规则引用：单题得分 = 20 ×（10 − 用时），前 2s 内答对计 160，最后 4s 内答对计 80，末题 ×2，答错 0 分。每局 6 题。



1. 机器人是什么

匹配成功时，服务端为本局生成一个机器人对象：

Robot {
  nickname      // 从昵称资源池随机
  avatar        // 从头像资源池随机
  outfit        // 从饰品池随机 3 件（≤300 Giggles 的饰品）
  behaviors[6]  // 6 道题的逐题行为，开局一次性生成
}

behaviors[i] = { isCorrect: bool, answerTimeMs: int }

客户端拿到 behaviors[6] 后本地回放：第 i 题开始计时后，到 answerTimeMs 时刻展示机器人作答动画；isCorrect=true 则按计分规则给机器人加分并推进其进度条，false 不加分。

本局中机器人行为不再变化，不读用户实时表现（唯一例外见 3.4 陪练档）。

3. 选档规则（每局开始时定档）
3.1 输入
streakWin：用户当前 PK 连胜场数
streakLose：用户当前 PK 连败场数
用户近 20 局 PK 胜率 wr20（不足 20 局按实际局数；一局没打过按 0.5）

3.2 规则（自上而下命中即停）

规则 3 中"上一局对手不是 L4"：L4 不允许连续出现两局。
新用户第 1 局：固定 L1 陪练；第 2–3 局：固定 L2 普通；之后走上表。

3.3 行为生成（开局一次）


for i in 0..5:
  isCorrect    = rand() < P
  answerTimeMs = isCorrect ? uniform(T.min, T.max) : uniform(E.min, E.max)

3.4 唯一的实时规则（防碾压兜底）

仅 L1 陪练档生效：回放到第 4 题开始时，若机器人总分 − 用户总分 ≥ 300，则第 4/5/6 题的 isCorrect 强制改为 false。其他档位无任何实时调整。

4. 硬性约束（违反即 bug）

answerTimeMs ≥ 1800ms，任何档位、任何题。
除 3.4 外，禁止根据用户本局表现修改机器人行为（禁止末题反超、禁止跟随放水）。
同一局内 6 题用时不得全部相等（生成后校验，全等则对第 2 题重新采样）。
昵称/头像资源池不得直接使用真实用户资料；使用预置资源池（昵称池 ≥ 500 条，已过敏感词审核；头像池 = 官方 Avatar 组合）。
机器人身份对用户不暴露（无"机器人"标识）；埋点中必须带真实档位。

5. 结果与状态更新

本局结束按总分正常判胜负（无特殊逻辑）。
更新 streakWin / streakLose / wr20（平局：两个 streak 都清零，计入 wr20 分母，胜场不变）。

6. 边界情况



场景

处理

用户中途退出


本局作废：不计胜负、不更新 streak / wr20；计一次当日 PK 次数（防反复退出刷对手）

用户某题超时未答

该题用户 0 分，机器人行为照常回放

本局题数因词库不足 < 6

断网/杀进程

本局作废：不计次数、不计胜负、不更新 streak
