知识体系后台改造方案
需求背景
产品侧遇到的问题：
我们在做学习效果外化和整体知识体系搭建时，需要用到最底层的数据是一个知识点（单词、句式、短语）的学习掌握度。
目前的单词数据分散在各个业务后台数据库，无法把掌握度等数据归到同一个数据源（比如在课程的red 和 闪卡的red）
单词的数据不存在id，全靠文字匹配，那么apple 和 Apple是两个单词。

长期来看，用户体验层希望有一个更明确的知识体系来牵引用户学习，做绘本推荐、单词训练；学习报告能展示级别的上升。
所以做一套知识库的后台，串起后台内容和用户的学习数据。
image.png

需求目的
让单词成为一个实体 —— 多业务引用同一份知识点 ID，消灭自由文本和冗余文本列。
P1 优先级（量最大的课程内容）：主路径课程、绘本、
P2 优先级 （目前新上用户比较喜欢的功能）：游戏大厅、小Mai、每日复习等
P3 优先级：闪卡、MiniPlan
打通反查 —— 从知识点能查到哪些内容在用它。

1.4.3 素材
一行四个槽位，与现有创建弹窗一致：图片  / 音频 / 动画 / 音效。每槽是「预览框 + 从素材库选择 + 清除」，不在此上传。
「音频」槽 = 原形的标准发音，也就是完整度查的那一条。迁移时现有单词卡那条音频导成「原形 · 标准发音」。
各变体的发音在详情页按变体维护，不在这里。
动画与音效不进完整度判定 —— 质量项，缺了不影响孩子端正确使用这个词。

1.4.4 必填项
保存门槛 = 知识点 + 知识点类型 + 所属体系 + 图片+主题+发音，其他可以留空保存。
必填项未填写完整不可以保存。

1.4.5 历史数据
现存 322 条里，68 条存在缺漏，本次需要补上（缺主题 12 / 缺图片 21 / 缺原形发音 59，去重后 68）。其中 49 条已上架 —— 意味着有人只想改一个错别字，也得先把发音补上才能保存。
本次需要补上
这 68 条恰好就是当前的不完整集合（不完整 68 条，且不存在「只差级别」或「只差变体发音」的记录）。所以这条规则的真实效果是：任何一次编辑都会顺手把这条知识点变完整。
如果这个代价不划算，替代方案是「必填只对新建强制，编辑历史数据时给警告但允许保存」—— 需要拍板，见 §待拍板。

1.4.6 保存
保存不改状态：新建 → 待上架；编辑 → 保持原状态。上下架只在详情页发生。
保存不做完整度校验。
改主题需二次确认：编辑一条已上架且有引用的知识点的主题时，弹窗列出受影响引用条数，确认后才写入。原型此处为占位。
变体在编辑页只读，底部按钮是「到详情页管理变体与音频」。变体的增删改带引用校验与音频挂接，两处都能改会出现同一条变体两个入口两套校验。

顺序与新增/编辑页一致：知识点类型 / 词性 → 主题 / 所属体系 → 级别 / 蓝思等级 → 剑桥体系 / 变体 → 标签 / 素材 → 更新时间。
变体数不含原形。
标签在此可增删：每个带 × 摘除，末尾「＋ 标签」新增。列表页只读。这个标签主要是做辅助备注，不一定是成体系的。
素材：图片 / 音频 / 动画 / 音效，已配显示绿底。
