需求背景


多图故事内容运营最大的痛点是流程控制—— Claude Code Demo 无法快速且准确地搬到 App 端。🐛 AI Tutor Issues and Bugs
不准确 case 集中在：① 流程、状态、时序控制；② 小麦 narration 执行准确度。
解决这些 bad case 的过程中，运维需要花费大量精力反复调试与测试。

产品目标


运营在 Claude Code 中直接完成内容生成与流程编排；
电脑上调试的结果即部署到 App 之后的结果（机制：两端消费同一份课程配置真源，不存在"搬运"）；
经过校验后一键发布 QA。

主要特性


① 内容生成与一键发布 QA（校验 0 警告为发布硬门槛）；
② 课程路径新增「直进玩法」内容节点（绕过 AI course chat）；
③ Mai chat 节点显式结束信号 + 道别 TTS 播完自动关闭。

功能描述
内容生成与一键发布
机制（修正）：不做"demo 搬运"。Claude Code 与 App 消费同一份课程配置（唯一真源）；Claude Code 本地播放器与 App 播放器都是这份配置的执行端——调试改的是配置，发布发的也是这份配置，不存在第二份格式，"调试结果 = 线上结果"由机制保证而非人工比对。
链路：制作（Claude Code 内容生成 + 流程编排）→ 本地预览调试 → 自动校验（复用现有 verify / R1–R9 校验器，0 warning 为发布硬门槛）→ 一键发布 QA → 人工确认晋级生产。
 发布治理：每次发布记录版本与配置 diff，支持一键回滚；QA 一键直发，生产需人工确认；发布权限：QA = 运营，生产 = 待定（见 D2）。
存量收敛：基于现有 demo → 场景配置管线（含校验闭环）收敛为唯一官方链路，不新起并行方案。

课程路径 · 直进玩法节点
形态（修正）：Mai Node 新增内容节点开关 direct_play，配置目标玩法 scene_id；
入场衔接：无 course chat 开场时由玩法自身 opening 承担引导；节点配置项：是否播放玩法开场白。
完成判定：以玩法自身的完成事件回写课程路径进度；中途退出 = 未完成，不误记。
电量口径：课程路径环节不消耗电量（与临场生活课口径一致）。
Mai chat 节点 · 显式结束状态
机制：prompt 约定教学目标达成、或语义分析进入道别时，模型调用 end_session toolcall；App 收到信号进入结束流程。
结束流程：end 信号 → 播道别 TTS → 无弹窗 → TTS 播放完毕自动触发关闭事件（等价于左上角关闭按钮）→ 返回课程路径并回写完成态。
可撤销边界：道别 TTS 播放期间用户再次说话 → 取消本次结束、正常接续对话。
