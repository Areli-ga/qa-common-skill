需求背景


现在多图故事里的形象都是"死"的，没有接入 AI。希望接入 AI 后可与用户纯英文沟通——另一个层面相当于 M Town Talk 支持了多图。


产品目标


多图故事中的画面角色接入 NPC 对话体系，用户可与故事角色纯英文对话。


主要特性


① Bbox 绑定 NPC；
② 进入页面 / 点击 NPC 两种激活方式（html config 可配置）；
③ 同一时刻仅与一个 NPC 对话，点击可切换；小麦本身也是一种 NPC。

规则 / 逻辑说明

Bbox 绑定NPC


bbox 只绑 npcId；人设 prompt、形象、音色一律读 NPC 资产登记表（统一真源），不在故事配置内重复定义


NPC激活方式


进入页面自动激活 / 点击 NPC 激活，按 html config 逐页配置


激活NPC后


暂停与小麦的对话，小麦待机（视觉方案见 D2）；语音输入发往当前激活 NPC（原文"登录之后"疑为"录音之后"，见 D1）


切换与召回


同一时刻单一对话对象；点击其他 NPC 即切换；小麦亦为 NPC，可点击召回


NPC 台词


遵循对话课 NPC prompt 标准结构与课程句子难度原则（词汇简单、句子完整、语法统一简单，感知内容）；台词服务页面教学目标。
感知内容侧，比如：翻页会代表场景的变换以及时间的变换（比如说三天以后、一周以后），NPC需要感知翻页，进行符合逻辑的连续对话

风险与待决策（2026-09-03 审核补充）
先说结论：方向成立且复用度高——本需求本质是打通两条已有资产线：多图故事的画面 / bbox / 角色帧 × M Town Talk 的 NPC 对话体系。风险集中在原文歧义、低龄体验与上下文规则三处。


编号


风险 / 决策点


建议


D1


原文两处疑似笔误，开发无法执行："登录之后，对话会跟激活对象的对话"（疑为"录音之后"）；"小麦为NPC的一种，首以上点击行为断掉和重新激活"（疑为"适用以上"）。


澄清后回写需求范围第 3、5 条。


D2


小麦"变为问号"的低龄体验：小麦是孩子的情感锚，问号态可能引发困惑；且待机视觉不该像"故障"。


改为小麦退至画面角落旁观（点头 / 欢呼小动效），点击即召回；避免问号符号。


D3


NPC 定义重复建设风险：若在故事配置里内联人设，将与 NPC 资产登记表（统一真源）漂移。


bbox 只绑 npcId；人设 prompt / 形象 / 音色运行时读登记表；prompt 遵循对话课 NPC 标准结构（Driver / Follower）。


D4


上下文切换规则未定义：切换 NPC 时对话历史如何处理？切回小麦是否恢复此前话题？


建议共享场景事实 + 各 NPC 独立人设上下文；切回小麦恢复待机前话题。


D5


依赖与成本口径：NPC 对话必然多轮，依赖《用户和小麦的对话升级》；是否计电量未定（现状电量仅覆盖 main_chat）。


排期挂依赖；电量口径与对话升级、贴纸岛两需求一并决策。


D6


教学一致性：纯英文自由对话易漂移出页面教学目标。


NPC 台词按页面教学脚本服务教学目标，句子难度遵循课程统一原则；自由聊天设轻引导回正。

进入开发前需补齐：D1 两处原文澄清、激活 / 切换状态流转图、NPC 上下文规则、电量计费口径、埋点评审。
