需求背景

历史迭代产生了多条并行学习路径，多路径导致:维护成本高、老用户仍未体验到优化后的结构。同时819(拆分单元 + 早期交付优化)已验证为数据表现最稳的路径。





产品目标

存量老用户全部迁移到目标路径，学习进度根据level+index迁移;
被迁移用户收到一次性弹窗提示，知悉课程结构已优化;
路径配置收敛为 3 2 条，旧路径全部删除（产品admin操作）。

需求详情

1. 用户迁移(后端)
1.1 迁移范围
除 3 2 条保留路径（819564819857413、810179729922629、823064397629317）外，所有路径上的存量用户
已在保留路径上的用户不迁移、不打标记
迁移目标路径：819564819857413
1.2 进度映射规则
迁移时按用户在原路径的 level ID 和Unit index，在新路径中定位解锁位置:
映射匹配: 新路径存在相同 level ID → 解锁至该 level+对应Unit index。因主路径与旧路径同源克隆，level ID 大面积一致（Unit不同，但是走index影响不大），预期迁移用户大部分进度不会丢失
兜底匹配: level ID 不存在时，按用户在原路径已解锁的 level 数量，在主路径按序解锁相同数量的 level
越界处理: index 超出目标 level 长度时，解锁至该 level 末尾。
1.3 迁移标记
用户维度服务端字段(如 pathway_migration_notice)，迁移成功时写入，含迁移时间戳;
存储在服务端，支持跨设备提示。
1.4 迁移记录
落表记录:user_id、from_pathway、原 level+index、新 level+index、匹配方式(精确/兜底)、迁移时间。供数据核对与后期出现问题的排查。

2. 迁移提示弹窗(Unity)
image.png

2.1 触发链路
冷启动 → 启动/用户信息接口返回迁移标记 → 标记为真 → 用户进入App后展示弹窗。
2.2 互斥与优先级
同一次冷启动最多展示一个引导类弹窗，优先级:
迁移提示弹窗 > sunny 家园弹窗 > 功能广场引导气泡
迁移标记为真时，本次冷启动优先展示迁移弹窗，sunny 家园弹窗与功能广场引导气泡延期至下一次冷启动;标记消费后，后续冷启动恢复原有弹窗优先级。
2.3 展示与清除时序
用户点击「去看看」按钮后,调用清除接口消费标记
清除失败:静默重试一次，仍失败则留待下次冷启动(可能重复展示一次，可接受)。
2.4 跨设备
标记在服务端，任一设备展示并消费后，其他设备不再展示。两台设备同时冷启动导致的并发重复展示，为可接受边缘情况，不做额外处理。
2.5 弹窗内容
新结构示意:展示单元主题内 5 步课型 —— 引入课 → 重复课 → 练习课 → 口语课 → 单元测试;
按钮「去看看」:关闭弹窗，定位到地图当前解锁位置;
点击「去看看」视为已消费，清除标记。
2.6 版本兼容
老版本 App 不识别标记字段 → 不展示、不清除。用户升级后仍可展示。

3. 旧路径清理(Cloud)
前置条件(全部满足才可执行):
后端迁移完成后确认旧路径剩余关联用户 = 0;
