四、需求背景
当前小麦主推印尼市场（印尼语言用户占小麦总用户 80%–90%）；而印尼语中穆斯林人口占比约 86%–87%。印尼国家也是是全球穆斯林人口最多的国家。
宗教用户有每天固定的生活节拍（五次礼拜），用户调研发现深度用户会主动跟小麦聊仪式中、聊和宗教相关的事情。
小孩子礼拜很容易开小差。
希望小麦可以融入不同民族、不同宗教信仰用户的生活，跟随他们的习惯与生活节奏，快速找到最合适的话题，与孩子建立更深的情感连接，并以此提升留存。
五、产品目标、原则与关键决策
5.1 目标
情感连接 → 留存（主指标 = prayer_based 组）：prayer_based 用户获得跟随宗教时间的仪式感，其次日 / 7 日留存与日均会话数较上线前基线显著提升：+10个/3个百分点。
5.2 原则
目标群体优先：本模块服务全平台约 80% 的印尼穆斯林用户；当体验、资源或规则冲突时优先满足目标群体。
包容性强：包容全球不同地区、不同宗教信仰的用户。
绝对不挑战、不违背用户的宗教理念，符合各自宗教文化价值观。
小麦从来不会拒绝用户：睡觉状态不构成使用门槛，任何时刻进来都被好好承接。
学习优先：任何话题完成后，快速引导至 word play / game play。

② 系统引导探测（系统语言命中）


手机系统语言 = 印尼语 → 小麦在话题切入中主动探测：直接、主动地询问宗教相关关键词，引导孩子说出判定词汇。
探测问题时机感知（AI 已知当地日期与时间，按上下文措辞），如：「今天你祷告了吗？」「今天和家人一起去清真寺了吗？」
主动询问和宗教相关关键词；
当用户明确拒绝表达自己不属于穆斯林群体的时候，标记为 非穆斯林！
此项为系统引导，仅适用于印尼语言。

探测句嵌入正常话题、保持自然；
持续探测直到出终态——信号命中 → 穆斯林（见 ③）；
用户明确拒绝 / 表达不属于穆斯林群体 → 标记非穆斯林（sun_based + done），探测永久停止；


③ 用户主动告知信号 → 直接打标


对话中（含探测回答）出现宗教生活信号（冻结词表：安拉 / Allah、礼拜 / sholat / 祈祷、清真寺 / masjid、斋月 / puasa、开斋节…）。打标条件：第一人称提及自己 / 家人的宗教生活 ≥1 次、跨 ≥1 个自然日（转述他人不计）→ 直接写入 prayer_based
此项为用户主动，适用于所有语言，比如“我是中国人，我信奉安拉”
支持用户主动切换“rhythm_mode”，比如用户可以主动说“我不再信仰伊斯兰教了！”

静默打标；小麦作息随即切换，后续以 prayer_based 节奏沟通；


④ Push 订阅邀请（与打标解耦）


已打标 prayer_based 后，在话题自然收尾处邀请：「今晚念完经，要不要小麦提醒你来练 5 分钟英语呀？」用户同意 → 拉起系统通知权限弹窗 → 开通傍晚学习提醒（Maghrib + 60–90 分钟发送，延迟可配置）
和Push需求上线，不在该期范围内。


数据依据：Fajr 时段（4–5 点）30 日仅 1,174 次打开，不做 Fajr 推送；傍晚 18–20 为全天流量峰 + 双祷告窗（礼拜 + mengaji 后的家庭练习槽），是推送主战场。邀请只管 Push、不影响标签；同意后写入推送白名单；拒绝 / 沉默 = 不开推送，7 天冷却后可再邀 1 次

8.6 互动 · 约定系统（最简版：只有「下次见面」一种约定）
做什么：把每一次离开变成下次见面的期待。约定只有一种——道别时和孩子说好「下次什么时候见」。它天然带情感：是聊天聊到要走时，两个好朋友之间自然说定的事。
怎么引入（三步，全部发生在道别语境，见 8.7）：
① 孩子表达要走（或到点该睡了）
② 小麦从对话推断去向，顺势把重逢时间说成约定 
③ 道别的最后一句，从静态变为动态的复述约定（钩子句）。
