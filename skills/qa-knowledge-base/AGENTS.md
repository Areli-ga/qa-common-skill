# QA 测试用例知识库 — 项目规则

> 本文件 Codex 进本目录时自动加载。**规则细节看 `SKILL.md`,当前进度/待办看 `RESUME.md`,设计看 `docs/`。**

## 这是什么

本地、纯文件的知识库:把飞书产品需求文档「编译」成结构化笔记,供 QA 在写测试用例**之前**,检索出往期相关功能、历史逻辑与该重点回归的点。最终形态 = Codex Skill。

当前解决 `读取产品文档 → 写测试用例` 流程的**前半段(读取/沉淀)**;「写测试用例」是下一阶段。

**v1 全流程(进 / 存 / 取)已建好并验证,已 ingest 46 篇 / 24 模块(覆盖 V1.29–V1.33)。** 详细进度与待办见 `RESUME.md`,全量目录见 `index/INDEX.md`。

## 目录结构

- `SKILL.md` — 技能工作流(ingest / 检索规则) · `taxonomy.md` — 功能模块清单(边 ingest 边长) · `RESUME.md` — 进度交接
- `docs/` — 设计文档(01 MVP / 02 架构 / 03 选型;**改需求或架构先改这里,再改实践**)

- `raw/`(原料,只读) · `notes/`(笔记) · `index/INDEX.md`(脚本生成) · `wiki/`(编译层,v2 空)
- 笔记文件名:`日期-功能模块-标题.md`;frontmatter:模块 / 版本 / related / 原链接 / 日期。

## 核心设计决策(红线级;背景见 docs/ 与 SKILL.md)

- **只收飞书产品需求文档**;往期测试用例暂不纳入;不接其他来源。
- 抓取**保表格行列 + 下载图片 + 读图转文字**(纯文本会丢测试金矿);**超大图(>1900px)转 `.read` 缩放副本读,原图保留**。
- **不上向量库 / RAG、不上数据库**——纯文件。
- **不直接生成测试用例**(那是下一阶段)。
- **编译层(模块主题页 / 往回织)留 v2**,v1 预留位置、不实现。
- **分类只靠「模块」**(taxonomy 边长:新功能→新建一级、已有→归二级);**不设通用类型标签**(通用词无区分度)。
- **版本来源**:你给「版本 + 链接」时用你的(权威);没给才从文档提取(冲突标"待确认")。
- **关联 related**:只看 同模块 或 共享功能标识符;**排除通用词 + 通用埋点公参**(level_number / unit_number 等)。
- 数据安全:**原料层只读、永不覆盖**;笔记 / 索引可由上一层一键重建。

## 工程约定

- **所有脚本 / 模块必须带详细日志(logging)**,便于排查。
- **机械活归脚本、语义活归 Codex**(扫文件/统计/索引/关联打分 → 脚本;读懂/判断/读图/提炼 → Codex)。
- 依赖**项目级安装**,禁止全局 `-g` / `--break-system-packages`(见上级 AGENTS.md)。
- 优先轻量:能不上的组件就别上,能用文件就别上库。
