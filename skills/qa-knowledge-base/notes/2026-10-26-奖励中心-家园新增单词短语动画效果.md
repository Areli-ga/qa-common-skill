## 摘要
家园一篇里塞了四件事（**全部由 H5 实现**）：① **IP 打电话老用户领取场景**——AB `reward_get_calls` 灰度到的、已完成前两个单元的老用户，进家园弹 `A gift for you!` 礼物弹窗，`Claim Now` 领取电话机，首次领取有新手引导，关闭后电话机落到家园固定位置；② **好友串门支持访问新空间**（厨房、浴室及未来新空间），访客默认进起居室、**主人跟着访客进入其他空间**，Avatar 在家园里可点击行走并避开落地家具，拍照相机在其他空间也能拍、可拍多次只发一张；③ **家园家具点读新增单词 / 短语动画**（以马桶为例分 A 物品名 `Toilet!` / B 描述 `A clean toilet.` / C 动作 `Flush the toilet.` / D 情境 四层，随机出现，音频说到关键词时动画才起，如 flush 处开始冲水）；④ **家具发音对接知识库**——Admin 家具配置新增「关联知识体系」，**优先播知识库关联单词的音频 → 兜底原配置朗读词 → 都没有不播**，存量自动关联 + 人工审核上架。新增埋点 `reward_furniture_audio` / `reward_furniture_animation`，复用电话领取三事件（补 `entry_source=home_gift`）和 `reward_space_switch`（补 `is_visitor`）。

### 1. IP 打电话：老用户新增领取场景
- **ABkey：`reward_get_calls`**（V1.38《IP打电话增加孩子亲密度》同一个 key：新用户完成第二单元路径掉落电话机）。
- 对象：**灰度到的老用户（已经完成了前两个单元）**。
- 流程：家园中引入电话机 → **新增礼物打开弹窗**，点击领取电话机 → **首次获得在家园中有新手引导** → 关闭后电话机放在家园的对应位置。

**UX Spec（图 2，小字裁剪放大读取，原图略糊）**
| 状态 | 操作 | 响应 |
|---|---|---|
| T01 待领取 | 进入家园 | 命中灰度、已完成前两个单元且尚未领取电话机的老用户，显示 `A gift for you!` 礼物弹窗 |
| T01 待领取 | 点击 `Claim Now` | 进入 T02 领取中：按钮显示加载反馈，播放礼物打开动画 |
| T02 领取中 | 开始领取 | 礼物打开并弹出电话机，按钮显示加载反馈（按钮变为 `···`） |
| T02 领取中 | 领取成功 | 衔接已有的电话机首次体验 / 新手引导流程 |
| T02 领取中 | 关闭首次体验 | 电话机落到家园对应位置并保留，后续使用沿用已有流程 |
- **待确认（T01）**：未领取就关闭或离开后，**何时再次弹出领取提示**？
- **待确认（T02）**：**领取失败或超时的提示与重试方式**，以及领取中能否关闭、离开或再次点击。
- 领取动画：礼物盒点击 → 弹出电话机（1.5x），动画由设计同事支持。

### 2. 好友串门支持访问新空间
1. 可访问空间：**目前新增的厨房、浴室**，**未来新增空间也要支持访问**。
2. **自己的 Avatar 在家园以及好友访问家园时，都支持在家园中点击移动行走，并且识别物品、避开落地的物品**。
- **好友访问默认去到起居室**；**好友进入其他空间，主人跟着进入其他空间**。
- **拍照相机出现在其他空间，可以拍多次，发送一张**。
- 埋点：沿用现网空间编码 `LIVING_ROOM` 起居室 / `KITCHEN_ROOM` 厨房 / `SHOWER_ROOM` 浴室；已有 `reward_friendsvisit_photo`、`reward_friendsvisit_shot` 保留原语义，本次不改为「发送成功」。
- ⚠️ 「主人跟着进入」：主人跟随换房**不算一次新的好友访问**（埋点 `is_visitor="false"`）。主人不在线 / 离开时访客能否自由换房未写。

### 3. 家园家具点读的单词 / 短语动画
- 「**随机出现以下单词和短语**」。以马桶为例（内嵌表 blVax8）：
| 内容层 | 音频示例 | 配套动画 | 教学目的 |
|---|---|---|---|
| A：物品名称 | `Toilet!` | 马桶轻微跳动或高亮 | 把声音与物品对应起来 |
| B：简单描述 | `A clean toilet.` | 马桶出现干净的闪光 | 在熟悉名词上增加一个意思 |
| C：动作表达 | `Flush the toilet.` | 冲水动画 | 理解物品可以做什么 |
| D：情境表达 | `Please flush the toilet when you finish.` | 角色如厕结束后，等待孩子冲水 | 理解语言在生活中的用途 |
- **音画同步**：例如播放 `Flush the toilet` 时，**说到 flush 附近开始冲水**；**冲水声适当降低，避免盖住人声**。
- 效果图（图 3、图 4）：气泡里关键词高亮，如厨房冰箱 `open the fridge`（`open` 绿底高亮）、浴室马桶 `Close the toilet lid`（`Close` 高亮）。
- 埋点口径：音频和动画分别在各自真实起播时记录，**动画延后到 flush 等关键词才出现时，不能在音频开始处提前报动画**；循环动画一次触发只报一次。
- ⚠️ 未定义：每件家具配哪几层、「随机出现」的随机规则（每次点读随机一层？）、D 层「等待孩子冲水」的交互（孩子要点什么、等多久）、哪些家具首批配置（只给了马桶一个例子，「家园单词」表未抓到）。

### 4. 家具发音对接知识库
- **关联知识库中的单词 id**（对接后端），**H5 取知识库中配置的音频**。
- **播放优先级**：**优先取知识体系关联的单词 → 若没有关联则兜底取原配置朗读词 → 若没有兜底配置就不播放音频**。
- 关联方式：**根据名称中的单词先自动关联**，并把关联的单词展示在列表中，**产品检查后人工审核点击上架**，有问题可修改（或者导出 Excel 人工筛选出知识库中的单词和 id）。
- **存量单词洗数据**；**新单词走创建接口**。
- 待定：「**两个单词的逻辑确认**」（如 `body wash` 这类两词名称怎么关联）；「**句式先不配置**」。
- Admin「家具配置」（图 5、图 6）：Tab `家具物品 / 家具主题 / 空间场景`，列表列 `编码 / 名称 / [新增：关联知识库单词] / 图片 / 主题 / 获取方式 / 摆放面 / 排序 / 状态 / 操作（编辑 / 下架）`，右上 `导出配置 / 导入配置`、`+ 新建家具`。「编辑家具」弹窗字段：状态、主题*、编码*（只读，如 `FURNITURE_049`）、名称*、名称 key（i18n key）、图片*、**[新增：关联知识体系]**、朗读词、音频（「拿起 / 放入家具时播放，替代 TTS；为空则回退 TTS」）、动态图（WebP/GIF/PNG ≤2MB，为空则为静态家具）、音效 BGM。
- ⚠️ **兜底口径冲突**：本篇规定「都没有就不播放」，但 Admin 现有音频字段说明是「为空则回退 TTS」——知识库与原配置都没有时，到底不播还是走 TTS 未统一。埋点 `audio_outcome=missing` 按「不播」设计。
- 关联：知识库单词 ID 体系见 V1.39《知识体系后台改造方案》（让单词成为实体、多业务引用同一知识点 ID）。

### 5. 数据埋点（2026-10-14 研发测试执行表）
- 待实施方案，**未向生产注册或上报**。**新增 2 个业务事件**（共 7 项属性配置、5 个不同属性名），电话领取与空间切换**复用已有事件**。只看四项：**领取转化、新空间使用、单词 / 短语实际播放、知识库音频使用覆盖**。不为走路、避障、动画每一帧、后台人工审核新增埋点。
- 公共孩子身份、设备、版本、实验分组沿用统一出口，**不得重复定义 `user_id` / `kid_id` 或 AB 分组**；新增属性只有 `audio_outcome`、`audio_source`；**历史空间编码和 `is_visitor` 的 String 类型不改写**。

**电话领取：复用已有事件（内嵌表 lx7I0q）**
| 事件 / 属性 | 实施与验收 |
|---|---|
| `calls_reward_expose` 电话奖励曝光 | 满足灰度与老用户资格，家园电话礼物弹窗**首屏真实可见**时报；只判断资格或弹窗未显示不报，同一次展示重绘不重复报 |
| `calls_reward_click` 电话奖励领取点击 | 点击可操作的领取按钮、开始处理领取请求时报；禁用按钮和同一请求处理中连点不重复报 |
| `calls_reward_receive` 电话奖励领取成功 | H5 收到服务端确认，且**电话机权益从未拥有变为已拥有**时报；点击、加载动画、失败、超时、仅查询到历史已拥有都不报；重复回调只报一次 |
| `entry_source`（String，本场景必填） | 三事件都补本场景值 **`home_gift`**，与原领取场景区分；其他场景原值不改 |
| 实验 | ABkey `reward_get_calls`，用已有公共属性 `abt_reward_reward_get_calls` 原值分析；**不给未命中用户伪造 treatment**；新手引导和实际电话使用沿用既有事件 |

**好友新空间：页面浏览与空间切换（内嵌表 63lELw）**
| 事件 / 属性 | 实施与验收 |
|---|---|
| `$pageview` | 进入本人或好友家园、目标空间完成渲染且可见时报（首次进起居室也报）；切到不同空间报一次；重绘、同空间重复点击不报。`$title`：家园-起居室 / 家园-厨房 / 家园-浴室 |
| `reward_space_switch` 家园空间切换 | 复用既有事件及 `from_space`、`to_space`（String）；本次**扩展到好友家园**：成功切到另一空间、目标可见后报一次；未完成切换不报；**首次进家园用页面浏览，不伪造 from_space** |
| `is_visitor`（String，本场景必填） | 两事件都补：`"true"` = 当前孩子在访问别人家园；`"false"` = 在自己家园。**现网锁定为 String，不能改 Bool**；**主人跟随换房属于 false** |
| 普通点击与拍照 | `$WebClick` + `$element_name` 沿用既有映射；`reward_friendsvisit_photo` / `reward_friendsvisit_shot` 保留原语义 |

**新增事件**
| 事件 | 触发 | 属性 |
|---|---|---|
| `reward_furniture_audio` 家园家具发音结果（H5，休闲娱乐 / 家园） | 点读选定单词或短语后，**音频首次实际起播、确认无音频或起播前失败**时报一次；未触发点读、取消、重复回调不报 | `item_code`（家具配置编码，不传名称 / 摆放实例 ID / 坐标）；`content_type` = `word` / `phrase`（**按配置类型判断，不按空格数**，如 `body wash` 可以是 word）；`audio_outcome` = `played` / `missing` / `failed`；`audio_source` = `knowledge_base` / `legacy`（played / failed 必填，missing 不传）；`word_id`（用知识库词条音频时必填真实 ID；原配置音频与未配知识库的短语不传；**禁止填家具编码、词面或拼接多个 ID**） |
| `reward_furniture_animation` 家园家具动画起播（H5） | 点读触发的动画**第一帧实际显示**时报一次；仅点击、发播放指令、环境动画、循环帧、重复回调不报 | `item_code`；`content_type`（与触发它的点读内容类型一致） |
- 发音规则：已起播后被打断**不补报 failed**；正常播完不报第二次；用户重新主动点读算新一次；预加载和后台重试不单独计数；**未开始前取消不算播放失败**。
- 粒度：**一条实际音频一条记录**；若最终多词方案播多条音频，各条记自己的词条 ID。短语 / 句式本期不接知识库时走原配置，不强填 `word_id`。
- 两事件**不加关联 ID**，不承诺逐次音画配对或同步率分析。

**四项指标（内嵌表 shTQLq）**
- 电话领取转化：限定 `entry_source=home_gift`，曝光 → 领取点击 → 领取成功，按同一孩子、同一灰度批次做有序漏斗；成功不能由点击推算。
- 好友新空间使用率：访问好友厨房 / 浴室的孩子 UV ÷ 访问过任意好友家园空间的孩子 UV，均取 `$pageview` 且 `is_visitor="true"`；换房次数另取 `reward_space_switch`；主人跟随不计入访客。
- 单词 / 短语与动画使用：音频只取 `audio_outcome=played`，按 `content_type` 分组看 UV/PV；动画取实际起播事件；可按 `item_code` 看家具分布；**不当作学习效果**。
- 知识库音频使用覆盖：played 中 `audio_source=knowledge_base` 次数 ÷ 全部 played，按 word / phrase 分开；另看 missing、failed 占全部音频结果比。**这是使用覆盖，不是后台家具配置覆盖**。

**测试验收表（内嵌表 W7V8lq）**
| 场景 | 应看到的结果 |
|---|---|
| 老用户电话礼物 | 符合资格并显示弹窗：expose 1 次；点领取：click 1 次；真实首次领取成功：receive 1 次；三者 `entry_source=home_gift`；重复回调、不符合资格、历史已领取不得增加成功数 |
| 好友从起居室到厨房 | 首次进好友起居室 pageview 1 次；厨房可见后 pageview 1 次、space_switch 1 次；`is_visitor="true"`、`from_space=LIVING_ROOM`、`to_space=KITCHEN_ROOM`；**主人跟随不得报成访客** |
| 知识库词条音频 | 实际起播：`played` + `knowledge_base` + 真实 String `word_id` + 家具编码 `item_code`；对应动画稍后出现，**第一帧才报 animation** |
| 原配置短语 / 无音频 | 未关联知识库但原配置可播：`played` + `legacy`，省略 `word_id`；都没有：`missing`，省略 `audio_source`；没有动画第一帧则不报 animation |
| 加载失败与重复点击 | 有音频但起播前失败：`failed` 并带实际所选 `audio_source`；重复回调不重复报；正常起播后中断不再报 failed；重新主动点读可再报 |
| 类型与范围 | ID 与 `is_visitor` 为 String；不满足必填条件的可选属性省略，不传空串 / null；普通点击不新增事件；自动采集与手动补报二选一；新事件不带用户姓名、音频 URL、坐标、设备等 |
- 实施前边界：「两词逻辑」和句式知识库配置**尚未定稿**，埋点不替产品定义播放顺序或新增句式 ID。

### ⚠️ 待确认 / 测试关注点
