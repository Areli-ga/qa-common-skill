## 摘要
把小麦已有的**场景能力 + 主对话能力**封装成**一个可排进课程路径的对话课节点**，首期接入内容是**多图文故事书**。节点内固定跑 **`Onboarding 对话开场 → Play 小麦游戏模板（如对话课）→ Closing 对话收尾`** 三段流程，**不需要 Word Play、不需要 Quiz**；对话复用《小麦的消息列表和消息气泡》的连续对话能力。Admin 侧**新建一种课程类型 `Content type: Mai Node`**，下含两个配置：**Conversation Guide（Prompt 文本框，可用参数含母语 / 年龄 / 学习等级 / level-unit / 已学单词或教学大纲 / 完课状态）**与 **Lesson Material（填场景 ID，带启用开关）** —— **启用时以「多图故事书读到第几页」映射星级（0 / 0–33% 1★ / 33–66% 2★ / 66–100% 3★，向下取整）**，**不启用时不定义明确完成概念、走完一轮完整对话即判三星**。关键约束：**一个课程入口暂定只绑定一个 scene id、不走小麦推荐**；**非小麦目标语言的用户一律指定 language 为英语**；**不支持离线，且不消耗电量、UI 上不显示电量组件**。

- 产品 Owner：**Libin**；优先级**待定**；UI 稿 figma `1.39.0` node `56001-79682`（与《消息列表和消息气泡》同一份稿）。
- **关联需求：《用户和小麦的对话升级》**（即本批的《小麦的消息列表和消息气泡》）。
- 修订记录：**2026-08-25** 按规范重排、补「风险与待决策」；**2026-09-08** **增加 admin 配置 `Content type: Mai Node`**（详见 Admin 模块）。
- 背景：**小麦拥有的场景能力、主对话能力，可以封装出来，放入课程路径上，包装为一个课程。**
- 产品目标：**以最小开发量把小麦对话能力接入课程路径，形成一个可排入路径的对话课节点**；**以多图文的故事书为首期接入内容**。
- 主要特性：① **路径游戏流程：Onboarding 对话开场 → Play 游戏 → Closing 对话收尾**；② **接入消息列表最新的能力**。

### 1. 路径配置
- **语言规则**：目前**没有为印尼语之类的国家单独做课标或课程路径**；**Mai 使用母语与用户沟通，母语目前支持英语、中文、印尼语**；**目标范围内、非小麦当前目标语言的用户，指定 `language` 规则为英语**。
- **路径上展示小麦形象的插图。**
- **一个课程入口暂定只绑定一个 scene id**；**不走小麦推荐**（即使在对话的视觉上，用户侧会认为是小麦推荐出来的）。
- **过渡动画：小麦吃豆人。**

### 2. 节点内流程
**`Onboarding 对话开场 → Play 小麦游戏模板（比如对话课）→ Closing 对话收尾`**
| 段 | 内容 |
|---|---|
| **Onboarding** | 可包含的话题：**询问姓名**；**阶段性学习报告** —— 小麦理解当前用户的学习状态、刚刚发生了什么，**承接住学过的内容并进行总结，从而顺畅地过渡到一个总结课里面**；**其他可在主对话中、且可受 prompt 控制的玩法**（角色扮演、猜单词变形等） |
| **课程（Play）** | **对应 scene id** |
| **Closing** | **询问用户对刚刚课程的体验，建立约定，进入 memory report 并埋点上报** |
- **不需要 Word Play，不需要 Quiz。**

### 3. 接入消息列表连续对话
- 直接复用《用户和小麦的聊天界面升级》（= 本批《小麦的消息列表和消息气泡》）的能力。

### 4. Prompt
- 原文只给了一句占位：**「你是用户的专属导师，热情。你今天的任务是跟用户玩一个游戏。。。」**（未定稿）。
- 课程路径主 prompt 的完整职责在《消息列表和消息气泡》那篇的 prompt 表里：**负责 AI 课程前后的转场、了解历史学习内容并推荐下一节 AI 课程、玩游戏过程通过 Scene 驱动不进主 Prompt、要总结用户学过的课程并建立下次约定**。

### 5. Admin：新建课程类型 `Mai Node`
入口：`admin.qakjukl.net/course/`，**新建一种课程类型，Content type: `Mai Node`**，下属两个配置：

**① Conversation Guide** —— 文本框供输入 Prompt，**可用参数包括但不限于**：
- 用户的**母语（界面语言）、年龄、学习等级**；
- **level 和 unit**；
- **方案一**：用户在 unit 下面**已学的单词** + **日志**（**看（出现）/ 听 / 读**）；
- **方案二**：**教学大纲（固定内容）** —— 查询一个 unit 下面有哪些课程（含游戏、单词、课程…）、**每个课程在 admin 里配置的知识点或单词**；以及**查询完课状态** —— 用户对该课程的学习进度（**对应出他的星级**）。
> ⚠️ 方案一 / 方案二**并列列出，原文没有说选哪个**。

**② Lesson Material** —— 文本框可填入**场景 ID**，**提供是否启用的选项**：
| 状态 | Prompt 要求 | 完成概念 |
|---|---|---|
| **启用（on）** | Prompt 中需**强调小麦的目标与工作流程：以引导用户学习一节课为目标，通过 `Conversation-greeting → Lesson → Conversation-closing`** | **🌟 以 Lesson Material（当前为多图故事书）的课程完成为目标**：**映射用户访问多图故事的页码进度，从 0 到 `max_page`，`read_page` 映射为 1–3 星，向下取整** —— **未进入 scene：0**；**0–33%：🌟**；**33%–66%：🌟🌟**；**66%–100%：🌟🌟🌟** |
| **不启用（off）** | Prompt 中需**强调小麦的目标，并定义结合当前场景的 prompt**（例如快速总结学习句子练习） | **不定义明确的完成概念**；**按照对话轮次，产生完整的一轮对话即定义为「三星」** |

**其他约束**：**不支持离线**；**不消耗电量，UI 上不显示电量组件**。

### ⚠️ 待确认（写用例前需拉齐）
1. **电量口径自相矛盾**：正文写「不消耗电量、不显示电量组件」，D1 又把「本课对话是否计电量」列为待决策。而《消息列表和消息气泡》那篇写「**消息列表中的对话消耗电量（课程路径中的接入除外）**」—— **三处表述要统一**，且同一条消息列表里混着计费与不计费轮次时的展示逻辑没人写。
2. **中途退出算不算完成**（D1 原文列的问题，未答）：星级按 `read_page` 算，**中途退出是否保留已达成星级、再次进入是续上还是重来**，都没写。
3. **Conversation Guide 的参数方案一 / 方案二没有结论**，两套取数逻辑成本差别很大（方案二要查教学大纲与完课状态），必须先定。
4. **星级映射的边界**：`0–33% / 33%–66% / 66%–100%` 三段的**端点归属**（33% 属于 1★ 还是 2★）没写，且「向下取整」与百分比分段的关系要给精确公式；**`max_page` 取故事书总页数还是有效阅读页数**也未定义。
5. **「不启用 Lesson Material 时走完一轮完整对话即三星」** —— **「一轮完整对话」的判定**（轮次数？Closing 是否必须完成？）完全没定义，等于没有验收标准。
6. **一个入口只绑定一个 scene id 是「暂定」**：一个 Mai Node 内能否配多个 scene、路径上能排几个 Mai Node、同一 scene 被多个节点复用时进度如何区分，均未写。
7. **非目标语言用户一律用英语**：那么**界面语言是印尼语但被判为英语**时，Onboarding 的姓名询问、故事书文案、TTS 是否也全英文，孩子能否听懂，没有说明。
8. **离线与弱网**：明确「不支持离线」，但**路径上其他节点支持离线（见《课程加载 / 离线模式》）**，因此**离线状态下 Mai Node 在路径上如何展示（置灰 / 隐藏 / 点了才报错）**必须定义。
9. **Prompt 尚未定稿**（正文只有一句占位），Onboarding 的话题清单也是「可以有」的口吻，**本期到底做哪几种 Onboarding 话题**要拍板。
10. **Closing 的 memory report** 写进哪里、与主对话的记忆层是否同一份、**埋点上报哪些字段**，都指向未写的《Mai - AI Tutor 埋点》。
11. **星级与路径既有星级体系的一致性**：路径上其他课程的星级规则（正确率等）与这里的「读到第几页」口径不同，**混在同一条路径上如何解释给用户**没写。
