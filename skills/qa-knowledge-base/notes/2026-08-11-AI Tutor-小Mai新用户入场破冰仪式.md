## 摘要

V1.35.0 用「**睡着 → 麦克风检测 → 唤醒**」三态破冰仪式改造小Mai 新用户 Onboarding:小Mai 闭眼打呼、**点不醒**,逼用户改用声音;唤醒判定只看 **RMS 音量阈值**(不做语音识别、与语言无关),在剧情内自然完成**麦克风授权(硬依赖、不可跳过)**;唤醒后接首句 + 姓名采集进主流程。目标是救回**首日 0 轮层**(21.8% 用户一句没说,其中 91% 次日消失)。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 0. 基本信息与背景数据

- 产品 Owner:**Libin**;优先级:**高**(首日 0 轮层为最大留存黑洞);文档版本号字段 `v1.35.0`(与用户给定一致)。
- **数据诊断(06/27–07/01,合计 4,034 人,总体 D1 = 21.2%)**:

| 首日行为 | 人数 | 占比 | 次日留存 D1 |
|---|---|---|---|
| **0 轮(一句没说)** | 879 | **21.8%** | **8.9%** |
| 只在入口、没进 game | 408 | 10.1% | 11.0% |
| 只玩到老 I Spy | 549 | 13.6% | 20.4% |
| 碰到新模块 | 2,198 | 54.5% | 28.3% |

- **0 轮层每周约 1,500+ 人,91% 次日消失**;其中**6 成 <3 秒秒退**、**36% 待了 3–30 秒没开口** —— 判定为**入口首句引导问题,不是内容问题**。
- **问题分析**:① Greeting 第一问「你叫什么名字」对小朋友没吸引力;② 用户不知道怎么打招呼(不知道说什么、不熟悉、害羞);③ 系统麦克风权限可能没开(小概率)。
- **产品目标**:1 秒内产生兴趣(首帧可玩,对抗 <3 秒秒退)/ 剧情内完成麦克风授权 / 完成一次「开口」——**不识别内容,音量达阈值即算首次发声成功**;指标:0 轮层占比下降、破冰完成率、FirstVoice 率、该层 D1 从 8.9% 向 21.2% 靠拢。

### 1. 范围

**范围内**:三态流程;睡觉/抖动/沉睡/睁眼动效与音效(呼噜、点击);音量监控条 + 唤醒阈值线;**RMS 声控唤醒判定**;**麦克风硬依赖**(未授权停在固定权限引导页直到打开,其余异常有剧情兜底不卡死);唤醒后承接首句 + 姓名采集;破冰漏斗全链路埋点。

**范围外(本期不做)**:
- **摄像头自拍、拉勾交朋友**(原欢迎仪式 stage3 / stage4,**本期删除**);
- **语音识别「Hi」这个单词**(唤醒只看音量,不做 ASR);
- 老用户 / 回访用户的每日仪式变体。

- 参考实现:companion-app 欢迎仪式 stage1/stage2(app.js),**删掉其摄像头与拉勾阶段**;交互 Demo `https://maimai-companion.pages.dev/`(参考入场仪式前两节);UI Figma `1.35.0` node `44116-130940`。

### 2. 状态机

| 状态 | 触发条件 | 下一步 |
|---|---|---|
| **睡着态 `sleep`** | 进入 onboarding | **点击 ≥ 1 次 → 麦克风检测态** |
| **麦克风检测态 `mic`** | 从睡着态过渡 | 授权 + **音量持续 ≥ 阈值 → 唤醒态**;**未授权 → 停留固定权限引导页(不可跳过)** |
| **唤醒态 `awake`** | 音量达标 / 兜底触发 | 承接首句 → 姓名采集 → 主流程 |
| 异常分支 | 超时 / 拒权 / 静音 | 拒权 → 停在权限引导页直至授权;**安静 / 超时经剧情兜底后进入唤醒态** |

- ⚠️ **点击次数口径冲突(已入待确认)**:状态机与 8.1 都写「**点击 ≥ 1 次 / 1 次点击后**」过渡到麦克风态,但**验收标准写「点击 ≥ 3 次自动过渡」**。

### 3. 状态一 · 睡着态(sleep)

- **视觉**:小Mai 闭眼、**缓慢呼吸(scale 微缩放)**、头顶 **ZZZ 上浮**;伴随**呼噜音效**。
- **交互**:视觉引导「点一下它」;点击 → **轻微抖动 + 点击音效 + 伸懒腰**;**连点 / 疯狂点只算节奏,不会醒**。
- **递进**:点击后**「沉睡更深」**(更小更暗、呼吸更慢),文案转向「**点是叫不醒的,想想别的办法**」→ 过渡到麦克风态。
- **目的**:制造「戳不醒」的轻挫败,自然引出「用声音」;**首帧 1 秒内可读可玩,无加载空屏**。
- 设计稿细化(img-02):**点击弹动,在两种状态之间切换;不触发全局的动画抖动**;**点完之后「嗷」的一声,然后呼噜声更大了**。

### 4. 状态二 · 麦克风检测态(mic)

- 出现**麦克风图标 + 音量监控条**(含**唤醒阈值线「喊到这里」**);屏幕出现**大大的「Hi!」**作示范;文案「对它大声说 Hi!」。
- **权限已授**:音量条实时反映当前音量;**小Mai 的光晕 / 缩放随音量「被震动」(保持闭眼)**。
- **权限未授**:麦克风图标变**禁用态** + 「开启麦克风权限」按钮引导;授权后进入检测。
- **唤醒判定**:**RMS 音量阈值(参考值 0.15–0.18,需真机调参)**,**连续数帧超阈值才触发,防误判**。
- **关键**:**声控而非识别单词** —— 任何足够大的声音都能唤醒,**与语言无关**;「Hi!」只是示范(规避"全球小孩是否都会喊 Hi"的不确定性)。
- **此状态下仍可持续点击触发抖动 / 伸懒腰**。

### 5. 状态三 · 唤醒态(awake)

- 小Mai **睁眼、变大变亮、上浮**,表情惊喜;**音量条满格后隐藏**。
- **承接首句(小Mai 音色 TTS)**:「嗨,我是小Mai,是谁把我吵醒了呀?我真的好困呢…你可以告诉我你的名字吗?」(English / 中文 / 印尼语)。
- **立即进入姓名采集 → 主流程**,承接「我叫醒了它」的成就感。
- ⚠️ **首句文案与设计稿不一致**:设计稿(img-05)气泡为「**是谁把我吵醒了呀?我是小Mai,你可以告诉我你的名字吗?我们可以做好朋友。**」——语序不同且多一句「我们可以做好朋友」。

### 6. 数据埋点

> 原文 9 节表格给出 3 个事件,但**二、修订记录(2026-07-22)明确**:「**删除 2 个埋点;`mai_ritual_woke` 增加 `wake_duration_ms`;埋点重命名,增加 `mai_` 前缀**」,详见《Mai - AI Tutor 埋点》。

| 事件名称(表格原值) | 触发时机 | 参数 | 说明 |
|---|---|---|---|
| `ritual_start` | 进入 onboarding、展示睡着的小Mai | — | **漏斗分母**;完成动画资源加载,展示"睡着态" |
| `ritual_first_tap` | 首次点击睡着的小Mai | — | 首个可玩交互;点击后触发**打哈欠动画**,并**自动转场至"麦克风检测态"** |
| `ritual_woke` | 小Mai 被唤醒 | `wake_volume_rms`(Number)、`wake_duration_ms` | 记录**语音唤醒的最大分贝**;进入主对话页面,开始播放 greeting 音频 |

- ⚠️ **事件命名口径待确认**:修订记录要求加 `mai_` 前缀(即 `mai_ritual_start` / `mai_ritual_first_tap` / `mai_ritual_woke`),但**表格仍是无前缀旧名**;且"删除 2 个埋点"删的是哪两个,表格已无从对照。以《Mai - AI Tutor 埋点》为准。
- 📌 `ritual_first_tap` 的说明写「**点击后自动转场**」,进一步支持「≥1 次」而非「≥3 次」的口径。
- 数据观测方式:首日 0 轮层占比、破冰完成率、FirstVoice 率、**已授权麦克风的比例**;对比该层 D1(基线 8.9%)。

### 7. 其他要求

- **多语言**:引导文案默认母语;**「Hi!」示范图形 / 文案按地区本地化验证**。
- **性能**:**首帧 1 秒内渲染完成**;动效与音频资源**预加载或轻量内联**;**在与小Mai 互动过程中,后台加载主对话界面乃至游戏内其他资源**。
- **数据兼容**:**仅对新用户触发**,老用户不受影响;**跳过 / 完成状态持久化,不重复打扰**。

### 8. 验收标准(原文给出,可直接转用例)

1. 睡着态**首帧 1 秒内**可见动效与「点一下它」引导,**无加载空屏**。
2. **点击 ≥ 3 次自动过渡**到麦克风检测态(⚠️ 与状态机的 ≥1 次冲突);权限未授时给出引导。
3. **音量持续达到阈值即可唤醒**;唤醒为**声控、与语言 / 具体单词无关**。
4. **麦克风未授权时停留固定权限引导页(无跳过、无旁路)**,授权成功后才继续;**安静 / 超时 / 狂点有剧情内兜底**,任何已授权路径都能进入主流程。
5. 唤醒后**立即播承接首句并进入姓名采集**。
6. 埋点齐全,可回算 0 轮层 D1 变化。

- **麦克风授权链路**与 [语音识别 / 麦克风授权与跟读反馈优化](2026-06-30-语音识别-麦克风授权与跟读反馈优化.md) 共用系统授权弹窗:本次是**硬依赖、不可跳过**,与跟读场景「拒权后仍可继续」的既有策略不同,**同一用户先后遇到两种策略时的表现要验**。
- **RMS 阈值判定**与 [语音识别 / 降噪增益](2026-06-30-语音识别-降噪增益.md)、[自适应跟读计时与会话统计](2026-07-13-语音识别-自适应跟读计时与会话统计.md) 的 VAD / 增益链路可能互相影响:**降噪增益会改变实际 RMS 值**,阈值 0.15–0.18 需在开启降噪后重新调参。
- **仅对新用户触发**,与 [新用户引导 / Onboarding价值传递](2026-06-30-新用户引导-Onboarding价值传递.md) 的首启流程、以及同版本 [解锁规则和学习顺序测试](2026-08-11-学习路径-解锁规则和学习顺序测试.md) 的 Hello 课流程**同处新用户首日路径**,顺序与互斥需确认。
- 姓名采集结果影响 [账号与设置](2026-06-30-账号与设置-注册登录优化.md) 的昵称字段,而同版本 [排行榜细节优化](2026-08-11-排行榜-排行榜细节优化.md) 新增了**昵称敏感词审核**——破冰仪式采集的名字也应过审。
