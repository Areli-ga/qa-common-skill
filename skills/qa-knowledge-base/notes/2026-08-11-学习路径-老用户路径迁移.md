## 摘要

V1.35.0 把**所有存量老用户从历史并行学习路径迁到目标路径 `819564819857413`**(819 拆分单元 + 早期交付优化,数据最稳),进度**按 level ID + Unit index 映射**(带兜底与越界规则);迁移成功写**服务端标记**,用户冷启动时弹一次性「Curriculum Upgrade!」提示,点「去看看」后消费标记;最后由产品 admin 删除旧路径。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 0. 背景与目标

- 历史迭代产生**多条并行学习路径** → 维护成本高、老用户仍未体验到优化后的结构;**819(拆分单元 + 早期交付优化)已验证为数据表现最稳的路径**。
- 目标:① 存量老用户全部迁移,**进度按 level + index 迁移**;② 被迁移用户**收到一次性弹窗**;③ 路径配置**收敛,旧路径全部删除**(产品 admin 操作)。
- 产品 Owner:Cloud;优先级:高;UI:Figma `1.35.0` node `44368-29959`。
- ⚠️ **保留路径条数口径不清(已入待确认)**:正文两处均写成「收敛为 ~~3~~ 2 条」「除 ~~3~~ 2 条保留路径」(有修改痕迹),但**括号内实际列了 3 个路径 ID**:`819564819857413`、`810179729922629`、`823064397629317`。

### 1. 用户迁移(后端,本期需求)

**1.1 迁移范围**
- **除保留路径外,所有路径上的存量用户**都迁移。
- **已在保留路径上的用户:不迁移、不打标记**。
- **迁移目标路径:`819564819857413`**。

**1.2 进度映射规则**(按用户在原路径的 **level ID** 和 **Unit index** 在新路径定位解锁位置)

| 情况 | 规则 |
|---|---|
| **映射匹配** | 新路径存在**相同 level ID** → **解锁至该 level + 对应 Unit index**。因主路径与旧路径**同源克隆**,level ID 大面积一致(Unit 不同,但走 index 影响不大),预期**大部分进度不会丢失** |
| **兜底匹配** | level ID 不存在时,按用户在原路径**已解锁的 level 数量**,在主路径**按序解锁相同数量的 level** |
| **越界处理** | **index 超出目标 level 长度时,解锁至该 level 末尾** |

**1.3 迁移标记**
- **用户维度服务端字段**(如 `pathway_migration_notice`),**迁移成功时写入,含迁移时间戳**。
- **存储在服务端,支持跨设备提示**。

**1.4 迁移记录(落表)**
`user_id`、`from_pathway`、**原 level+index**、**新 level+index**、**匹配方式(精确 / 兜底)**、**迁移时间** —— 供数据核对与后期排查。

### 2. 迁移提示弹窗(Unity,本期需求)

**2.1 触发链路**
冷启动 → **启动 / 用户信息接口返回迁移标记** → 标记为真 → 用户进入 App 后展示弹窗。

**2.2 互斥与优先级(测试重点)**
- **同一次冷启动最多展示一个引导类弹窗**,优先级:
  **迁移提示弹窗 > sunny 家园弹窗 > 功能广场引导气泡**。
- 迁移标记为真时,本次冷启动**优先展示迁移弹窗**,**sunny 家园弹窗与功能广场引导气泡延期至下一次冷启动**;**标记消费后,后续冷启动恢复原有弹窗优先级**。

**2.3 展示与清除时序**
- 用户点击「**去看看**」按钮后,**调用清除接口消费标记**(先展示后清除)。
- **清除失败:静默重试一次**;仍失败则**留待下次冷启动**(**可能重复展示一次,可接受**)。

**2.4 跨设备**
- 标记在服务端,**任一设备展示并消费后,其他设备不再展示**。
- **两台设备同时冷启动导致的并发重复展示,为可接受边缘情况,不做额外处理**。

**2.5 弹窗内容**(img-01)
- **新结构示意**:展示单元主题内 **5 步课型 —— 引入课 → 重复课 → 练习课 → 口语课 → 单元测试**(设计稿英文:**Intro → Review → Practice → Speaking → Unit Quiz**,副文案 `Brand New Structure • 5 Steps Per Unit`)。
- **按钮「去看看」**(设计稿为 `Let's Go!`):**关闭弹窗,定位到地图当前解锁位置**;**点击视为已消费,清除标记**。

**2.6 版本兼容**
- **老版本 App 不识别标记字段 → 不展示、不清除**;**用户升级后仍可展示**。

### 3. 旧路径清理(Cloud)

- **前置条件(全部满足才可执行)**:后端迁移完成后**确认旧路径剩余关联用户 = 0**。
- ⚠️ 原文「前置条件(全部满足)」只列出 1 条,其余条件缺失。

### 4. 数据埋点

| 事件 | 时机 | 属性 |
|---|---|---|
| `migration_popup_show` | 弹窗曝光 | `pathway`:当前路径 id |
| `migration_popup_click` | 点击按钮 | — |

- ⚠️ `migration_popup_click` **无属性**,只有一个按钮时可接受;但**弹窗被延期/未消费**的场景无上报,查不到"展示失败/清除失败"的量。

### 5. 数据核对与验收(原文给出的验收清单,可直接转用例)

**迁移正确性**
- 抽样比对迁移结果;
- **是否存在进度倒退用户**。

**功能验收**
- 弹窗**仅对被迁移用户展示**,**保留路径用户不展示**;
- 迁移弹窗**优先于** sunny 家园弹窗与功能广场气泡展示,**被延期的引导在下一次冷启动正常恢复**;
- **先展示后清除**;**清除后所有设备不再展示**;
- **展示中断(进程被杀等)时标记未被消费,下次冷启动可再次展示**;
- **老版本 App**:迁移后学习正常、不展示弹窗、不消费标记。
