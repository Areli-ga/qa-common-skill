## 摘要
把散在 Google Sheet、和后台打不通的**神策埋点字典**收进 Admin，做成可定义、可查询的「**用户行为系统**」。任务系统、学习报告、家长中心 2.0、用户标签以后都从这里取数。一期正文只写清了**行为分类体系（9 个主分类）**和 **Admin 事件定义**：事件列表的检索、筛选和启停，导入 JSON（主路径）或手工新建（兜底），编辑和查看；再加**属性字典**：属性类型分 4 种，来源分「主动创建 / 事件反写」，能看到每个属性被哪些事件引用。关键规则：**事件名用小写 snake_case、以字母开头、全局唯一、创建后永久不可改**；**新建事件默认未启用**；公共属性由统一上报出口自动附加，不在事件里重复定义；事件属性以 JSON 存进**行为事实表的 `data` 列**。⚠️ 需求范围里的「行为查询（按 user_id / kid_id）」「数据导出」「业务系统接入」「埋点盘点与迁移」4 项**正文没有任何细节**，交互原型 HTML 附件也**未入库**。

### 2. Admin · 事件列表
**检索与筛选**（多个条件之间是 **AND**；无结果显示「没有符合条件的事件」）
| 控件 | 类型 | 说明 |
|---|---|---|
| 搜索框 | 文本输入 | 对**事件名和事件显示名**做包含匹配，**输入即过滤**；事件名匹配**不区分大小写** |
| 主分类 | 单选下拉 | 全部主分类 / 9 个主分类 / **未分类** |
| 二级分类 | 单选下拉 | 随主分类联动；**未选主分类时下拉为空，只有「全部二级分类」** |
| 来源 | 单选下拉 | 全部来源 / 客户端 / 服务端 / Unity / H5 |
| 状态 | 单选下拉 | 全部状态 / 已启用 / 未启用 |

- ⚠️ 新建事件时主分类**必填**，筛选里却有「未分类」。哪些事件会是未分类（导入？迁移？事件反写？）没有说明。

**列表字段**
| 列 | 内容 | 说明 |
|---|---|---|
| 事件名 | 英文唯一标识 | **首次上报后类型锁定，保存后不可修改**；小写 snake_case |
| 事件显示名 | 中文名称 | — |
| 主分类 | 标签 | 9 个主分类之一 |
| 二级分类 | 标签 | 「46 个」二级分类之一（实际表里 41 个，见上） |
| 来源 | 标签 | 客户端 / 服务端 / Unity / H5 |
| 属性 | 数字 | 该事件已定义的属性字段数，**可为 0** |
| 状态 | 标签 | 已启用 / 未启用 |
| 操作 | 链接 | 查看 / 编辑 / 启用·禁用 |

**行内操作**
- 查看 → 跳只读详情页；编辑 → 跳编辑页。
- **启用 / 禁用**：**就地切换，不跳页**，切换后列表即时刷新并给出提示；文案跟随状态（已启用显示「禁用」，未启用显示「启用」）。
- 没有删除操作。

**页面入口**（右上角两个按钮，主次有别）
| 按钮 | 样式 | 定位 |
|---|---|---|
| ⤒ 导入 JSON | **主按钮** | 常规路径：开发产出 JSON 后粘贴导入 |
| ＋ 新建事件 | 次按钮 | 兜底路径：导入不适用时手工录入 |

### 3. 新建 / 编辑 / 查看事件
**基本信息**
| 字段 | 必填 | 控件 | 规则 |
|---|---|---|---|
| 事件名 | 是 | 单行输入 | **小写字母、数字、下划线，且以字母开头；全局唯一；创建后永久不可修改** |
| 事件显示名 | 是 | 单行输入 | 中文名，用于列表、查询结果、报表 |
| 主分类 | 是 | 单选下拉 | 9 个主分类，默认「请选择」 |
| 二级分类 | 是 | 单选下拉 | 随主分类联动，默认「请选择」；**切换主分类时重置** |
| 来源 | 是 | 四选一 | 客户端 / 服务端 / Unity / H5 |
| 触发时机 | 是 | 多行文本 | 描述在哪一步上报；开发按这句话定位代码插入点，**必须写到可执行的程度** |
| 状态 | 否 | 开关 | **默认关闭** |

**属性自定义**
| 列 | 必填 | 说明 |
|---|---|---|
| 字段名 | 是 | 英文标识，小写 snake_case；**同一事件内不可重复** |
| 显示名 | 否 | 中文名 |
| 类型 | 是 | String / Number / Bool / Datetime / List，默认 String |

- **属性整体可以为空**，即只统计上报次数的事件。
- 「＋ 添加字段」新增空行：**四个列都不预填默认值**（⚠️ 表里只定义了 3 列，且类型「默认 String」与「不预填默认值」矛盾），焦点自动落到字段名输入框。
- 字段名为空的行，输入框标红；每行末尾有删除按钮。
- **公共属性**（设备型号、App 版本、渠道、归因等）由统一上报出口自动附加，**不在这里重复定义**。⚠️ 手工填了公共属性名时是拦截、提示还是放过，没有说明。
- 这里定义的字段以 **JSON 形式存进行为事实表的 `data` 列**。

**编辑事件**：事件名只读，其余字段可编辑；按钮「保存」；**校验与新建一致，但不做事件名重复校验**。

**查看事件**
| 项 | 规则 |
|---|---|
| 所有输入框 | 只读 |
| 所有下拉 | 禁用 |
| 状态开关 | 不可点击 |
| 属性表 | 只读，**不显示「＋ 添加字段」和删除按钮** |
| 无属性时 | 显示「**该事件没有定义属性，只统计上报次数**」 |
| 上报代码 | 正常展示，**可复制** |
| 右上角按钮 | 返回列表、编辑；**不显示保存** |

- ⚠️ 「上报代码」只在查看页出现一次，生成规则、按来源（客户端 / 服务端 / Unity / H5）区分的代码形态都没有定义。

### 4. 属性字典
定位：**定义时可复用**（从字典联想选择），**使用后可追溯**（看到每个属性被哪些事件引用）。

**属性类型**
| 取值 | 含义 | 示例 |
|---|---|---|
| 公共属性 | 统一上报出口自动附加，事件里不用重复定义 | `user_id`、`app_version`、`device_model`、`channel` |
| 学习场景通用属性 | 学习相关事件间复用 | `lesson_id`、`unit_id`、`quiz_id`、`duration_ms` |
| 故事阅读通用属性 | 绘本阅读相关事件间复用 | `story_id`、`page_count` |
| 自定义属性 | 单个或少数事件专属 | — |

**检索与筛选**：搜索框对属性名和显示名做包含匹配；属性类型（全部 / 上述 4 种）；数据类型（全部 / String / Number / Bool / Datetime / List）；来源（全部 / 主动创建 / 事件反写）。

**列表字段**：属性名（英文唯一标识，小写 snake_case）/ 显示名 / 属性类型 / 数据类型 / **被引用**（被多少个事件引用，「**改名、停用前必须看这个数字**」）/ 来源 / 操作（引用 / 编辑）。

**新建 / 编辑属性**
| 字段 | 必填 | 新建 | 编辑 |
|---|---|---|---|
| 属性名 | 是 | 可填，走命名校验 | **只读** |
| 显示名 | 是 | 可填 | 可改 |
| 属性类型 | 是 | 默认「自定义属性」 | 可改 |
| 数据类型 | 是 | 默认 String | **可改，但需警示** |

- 点「引用」：列出引用该属性的事件（事件名、事件显示名、主分类）；无引用时提示「**还没有事件引用这个属性**」。
- **事件反写**：定义事件时手填了字典里没有的属性，**保存时自动在字典里创建**，来源标「事件反写」，属性类型默认「自定义属性」。
- ⚠️ 「改名、停用前必须看被引用数」，但属性名编辑态**只读**，操作列也**没有停用**，两处对不上。
- ⚠️ 反写时，如果同名属性已在字典里但**数据类型不同**（事件里填 Number、字典里是 String）怎么处理，没有定义。
- ⚠️ 事件名「首次上报后类型锁定」与属性数据类型「可改，但需警示」，对**已上报属性改类型**的口径不一致；警示内容和改类型后历史 `data` 的处理都没写。

### 5. 导入 JSON 格式（取自同版本《社交广场新增舞会》，本篇未定义）
本篇只写了「开发产出 JSON 后粘贴导入」，**没有给 schema**。舞会篇的「新事件登记 JSON」是库内唯一样例：
- 事件级：`event_name` / `display_name` / `category`（主分类，如「休闲娱乐」）/ `sub_category`（二级分类，如「社交广场」）/ `source`（如「H5」）/ `trigger_timing` / `business_intent`
- 属性级 `properties[]`：`name` / `display_name` / `type` / `required` / `description` / `enum`
- 舞会篇原文说明「`business_intent`、`enum` **即使导入界面忽略**，也须作为研发取值依据保留」。
- ⚠️ `required` / `description` / `enum` / `business_intent` 在本篇 Admin 的属性表和事件表里**都没有对应字段**，导入后是丢弃、报错还是另存，没有说明。导入时事件名重复、分类名不在 9 + 41 枚举内、批量导入部分失败的处理也都没定义。

### 测试关注点（基于正文，供写用例参考）
1. **事件名校验**：大写、数字开头、中划线、空格、`$` 前缀、中文、超长、与已有事件重名（含大小写不同但同名）；编辑态只读、编辑保存不做重名校验。
2. **筛选联动**：二级分类随主分类联动、未选主分类时只有「全部二级分类」、切换主分类后二级重置；多条件 AND；搜索对事件名不区分大小写，对显示名用包含匹配；无结果文案。
3. **启用 / 禁用就地切换**：不跳页、即时刷新、提示、按钮文案随状态翻转；切换后再按状态筛选的结果。
4. **新建默认未启用**：未启用事件的上报会不会落库、查询能不能查到，**正文没定义**，需要和研发对齐后再测。
5. **属性表**：空属性事件（列表属性数 = 0、查看页文案）；字段名为空标红；同事件内字段名重复；删除行。
6. **属性字典**：事件反写自动建属性（来源、默认类型）；被引用数与引用列表准确；编辑时属性名只读、数据类型改动的警示。
7. **查看页**：所有控件只读 / 禁用、无保存按钮、上报代码可复制。
8. **与旧体系并存**：结合《邀请同桌1.4》，App ≥ 1.41.0 报新平台、旧 App 报神策旧事件，验收时要按 App 版本区分数据去向。
