## 摘要

奖励中心 V2.0 + 用户虚拟形象装扮(V1.29 起对新游客开放,与 1.0 **并存**)。用单元套装/勋章/虚拟形象穿扮替代单纯扭蛋贴纸,建立情感链接、提升次日留存。奖励与单元学习进度绑定,含补发逻辑。后端 abtest key `new_reward_center_2`。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 新老奖励中心区分
- V1.29 新游客 → 2.0;老用户/已进过奖励中心 → 沿用 1.0。V1.30 引导老用户切 2.0 并按完课进度补发。
- 1.0 保留:贴纸/Giggles/保护道具继续发;Max 服装五月起不再配置/发放。2.0:屏蔽贴纸发放、不展示贴纸入口;保护道具不对新用户开放;本次新增奖励**不可重复获取**。

### 模块1 路径引入奖励
- 首次进地图未完 Hello → 顶部菜单栏隐藏;完成 Hello、下一节领扭蛋 → 扭蛋飞入奖励中心 → 菜单栏出现。
- Hello 未完 → 晃动引导,后续课摇晃不可点;**杀进程/冷启动 → 直接显示菜单栏,可跳过 Hello**。实验组进图等 2 秒直接进 Hello。

### 模块2 虚拟形象引入
- 首次进奖励中心展示默认形象;若先获服装 → 先定位换装 tab、穿衣引导 → 再进形象编辑 tab。
- 形象编辑页:**4 项属性逐项选(各有默认值,改在意的即可)**,实时预览;每选一项随机动画(歪头/眨眼/微笑);3 秒无操作小手引导;**左上角关闭 = 保存并同步头像**。
- 异常:编辑中断网 → 本地缓存,恢复后同步;存储失败 → toast「保存失败,请重试」。
- 路径/头像(2.4/2.5):路径进度定位标 **替换为虚拟形象头像**(指向下一节待学);左上角头像更新;**去掉选头像页面**(创建孩子档案/新增小孩)。老数据优先级:**自定义头像 > 虚拟形象 > 系统默认**;已传自定义头像者首次编辑形象后通知"头像已更新"。

### 模块3 奖励2.0 装扮
- **单元套装(3.1)**:每单元 1 套(上衣/裤子/鞋子);完成 section 扭蛋随机开出;单元完成额外发 1 个勋章头饰(非扭蛋直接发)。
  - 展示:新用户默认解锁 L1,展示全部 8~9 单元服装(1-8 排序);**最新获取置中**;未解锁=**灰色剪影(可见不可点)**;超出已上线范围=**「即将解锁」占位卡(不展示剪影)**。
  - 补发:升级 L2 但奖励未上线 → 提示"等上线补发";**重复开扭蛋(已集齐)→ 出 Giggles 不重发**;跨级别 → 只发当前已上线级别,其余记补发状态。
- **单元勋章(3.2)**:按 Level 分组(Lv1/2/3 各一行),单元 1-8;**同一时间只能戴 1 个**,佩戴后实时更新地图头像;领取:单元全部完成 → 地图节点可点 → 打开动画 → 勋章+证书同步领取。
- **非课程挂钩服装(3.3)**:Giggles 积分抽奖;默认不显示入口,获取后才显示(小红点);分类 上衣/下装/鞋子/配饰;单元套装(扭蛋)vs 基础款(Giggles 购买)分 tab。

### 模块5 补发逻辑
- 进奖励中心判断"已完成单元 but 未领奖励" → **补发弹窗**;定位优先勋章头饰,其次套装位置。

### 后端抽奖逻辑
- abtest key `new_reward_center_2`;单元路径 3 个扭蛋出三件套(三件套与 Giggles 随机),其余 section 扭蛋出 **20 Giggles**;完成单元发 1 勋章;普通款走 Giggles 抽奖页。

### ⚠️ 课程变更与奖励的关系(易漏回归点)
- 按**单元 ID** 识别:ID 不变 → 单元下课程怎么改都不影响奖励;ID 变 → 算新增一套;**未配置 → 路径扭蛋出 Giggles 兜底**。

- `h5_button_reward_exit`(奖励中心退出,h5;用于算使用时长)。
- V1.29 单元结算埋点(**与《新单元奖励》同套**):`app_unit_reward`/`rewardopen`/`rewardequipped`/`myworkshare`/`share_completed`/`finish_leave`,带 `Level_Number`/`Unit_Number`。
