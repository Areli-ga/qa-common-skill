## 摘要

V1.37.0 修一个**让单元测验形同虚设的漏题 bug**：答题页原来固定取「线索」配置的单词文本展示，导致 L5 起的**字母认读题把答案字母直接印在提示区**（提示「n」、选项也是 n/l/p，孩子看一眼就能选对）。本期改为**严格按 Clue 配置类型渲染**（Text / Audio / Text + Audio 三种本期实现），字母题只给提示音，并在上线时对存量题库 Clue 字段做**可回滚的批量迁移**。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 0. 基本信息

- 产品 Owner：Aaron；**优先级：高**；文档「版本号」字段 **v1.37.0**（与主人给定一致）；文档日期 2026-07-29。
- UI 设计稿：Figma `1.37.0` node-id=49139-36766（与《调研问卷》同一个 node）。

### 1. 需求背景

- 用户反馈来源：**家长群，6 岁孩子家长** —— 「单元测试好多这种题，小朋友看着题目就直接选出来了，感觉不太能起到测试效果」（图 1 微信群截图，题目提示区显示 `n 🔊`，选项 `n` / `l` / `p`）。
- 根因：当前单元测验答题页的逻辑是「**取『线索』配置对应的单词进行展示**」，**并未区分线索的配置类型**。
- 触发点：**自 L5 起新增了字母教学**，随之出现字母认读题；若线索里直接展示字母「n」、选项也是字母，**孩子仅凭视觉匹配即可答对**。

### 2. 主要特性 / 需求范围

| # | 说明 |
|---|---|
| 1 | 答题页「提示区」渲染改造：**严格按题目 Clue 配置类型展示**，不再固定取单词文本展示 |
| 2 | **本期支持三种类型**：Text（仅文本）、Audio（仅语音：**喇叭 + 波形控件**）、Text + Audio（文本 + 语音） |
| 3 | 后台题库 **Clue 字段批量迁移**（两条规则见下） |
| 4 | **迁移前置校验**：改为 Audio / Text + Audio 的题目，须校验提示音频（及文本）齐备 |

- 归属约定：**字母认读题用 Audio**（仅提示音，不展示字母）；**考察单词的题目用 Text + Audio**。

### 3. App 答题提示渲染规则（流程一 + 原型 B）

| Clue 类型 | 本期 | 渲染 / 行为 | 适用 |
|---|---|---|---|
| **Text** | ✅ 是 | **仅文本，无语音；点击无声** | 有文字辅助、无需发音的题 |
| **Audio** | ✅ 是 | **仅语音：进入自动播一次、可点击重播；不展示任何字母/文字** | ★ **字母认读题（核心修复）** |
| **Text + Audio** | ✅ 是 | 文本 + 语音；**点击喇叭播放** | 考察单词的题（**选项为图片**） |
| **None** | ❌ 否 | **不展示提示区**；本期不做专门设计 | — |
| **Image / Image + Audio** | ❌ 否 | **端上无图片展示区**：`Image` **视同不展示**；`Image + Audio` **仅播放语音（兜底）**。**不报错** | — |

- 渲染流程：进入测验题 → 读取该题 Clue 配置类型 → 判断类型分支渲染 → Audio / Text + Audio 展示喇叭 / 波形控件可点播 → 用户选择选项并提交 → 进入下一题。

### 4. 答题页布局（原型 A）

- **本产品为类似马里奥的横版闯关游戏**，玩家跳跃闯关、过程中触发答题；答题页整体布局固定，**本次改造仅影响「① 线索提示区」**。
- 区域划分：① **线索提示区**（本次重点，按 Clue 类型变化）；② 选项区（**图片 / 字母**）；③ 玩家角色（小麦）；④ 跳跃键（闯关操作）。
- 顶部信息：Giggles 计数（如 `30/30 ✓`）、题目进度（如 `0/4`）。

### 5. 后台批量迁移（流程二，上线时一次性执行）

| # | 步骤 | 说明 |
|---|---|---|
| 1 | **备份** | 迁移前**备份现网所有受影响题目的原 Clue 字段值，支持回滚** |
| 2 | **规则 1** | 将**所有【已启用】题目**的 Clue 字段改为 **Text + Audio** |
| 3 | **规则 2** | 在此基础上，将**【已启用 且 线索对应单词库中为「字母」】**的题目 Clue 改为 **Audio**（**覆盖规则 1**） |
| 4 | **前置校验** | 对将改为 Audio / Text + Audio 的题目校验**提示音频（及文本）是否齐备**；**缺失者告警拦截、人工补齐后再迁，不静默上线** |
| 5 | **抽样验证** | 迁移后抽样核对：**字母题 = Audio 且不展示字母；单词题 = Text + Audio 且展示正常** |

### 6. 验收标准（原文给全，可直接转用例）

1. 答题页严格按 Clue 类型渲染：Text / Audio / Text + Audio 三种展示均正确；**Audio 类型不展示任何字母或文本**。
2. 字母认读题：提示区**不再出现字母文本，仅提供语音**。
3. 迁移正确：所有已启用题目 Clue = Text + Audio；已启用且线索词为字母的题目 Clue = Audio；**抽样核对通过**。
4. 音频兜底：所有改为 Audio 的字母题**均有可播放提示音**；**无音频的题目被拦截而非静默上线**。
5. 容错：遇到 None / Image / Image + Audio 时**端上不报错**，按兜底策略处理。
6. **可回滚**：迁移有备份，**可一键回滚**到迁移前状态。

### 7. 待确认项

1. **「线索词是否为字母」的判定依据**：只写「线索对应单词库中为『字母』」，是靠单词库的类型字段、长度 = 1，还是白名单？**多字母组合（如 `sh`、`th`）算不算字母**未定义 —— 自然拼读体系里这类线索很常见。
2. **未启用（Disable）题目不迁移**：迁移两条规则都限定【已启用】，那么**存量未启用题目后续被启用时 Clue 仍是旧值**，会重新暴露字母。是否需要在启用动作上加校验未说明。
3. **新建题目的默认 Clue 类型**未定义（迁移只覆盖存量），后台新增字母题若默认 Text + Audio 会重现同一 bug。
4. **提示音频缺失的拦截口径**：「告警拦截、人工补齐后再迁」—— 是**整批阻塞**还是**跳过该题继续**？跳过的题最终是什么 Clue 值？
5. **Audio 类型的「进入自动播一次」与闯关节奏**：本产品是横版跳跃闯关，答题被触发时角色仍在场景中，自动播放与背景音/跳跃音效是否会互相打断未说明。
6. **无数据埋点**：全篇没有埋点需求 —— 改动后**答对率变化**（这才是「恢复真实考核效果」的验证指标）无法量化，也无提示音点击/重播次数。
7. **Image / Image + Audio 兜底为「端上无图片区」**：说明当前 Clue 已支持图片类型但端上没实现，**后台是否要禁止选这两个类型**未说明，否则运营仍可配出无提示的题。
8. **回滚触发条件与责任人**未写（只说可回滚）。
9. 原文两处引用「详见规则表」，**正文并没有独立的规则表**，规则实际在原型 B 图里（本笔记已转成第 3 节表格）。
