## 摘要

V1.37.0 把聚合入口的 **Songs 改名为 Giggle TV**，播放页右上新增「更多」菜单提供**童锁**（开启后屏幕控件全部消失、toast `Child Lock is On`），并加上**播放结束自动续播**（重播按钮 + 按列表顺序的后 5 个视频 + **5s 无操作自动进入下一个、整列表循环**）；**投屏放到下一期**（走系统自带投屏 + 分品牌教程页），设置-屏幕时间底部加护眼投屏引导。目标：验证能否提升**单次观看时长与投屏使用率**。

> ⚠️ **原料补抓说明**：本篇有 **1 个内嵌 Sheet（`block_type=30`）**，装着**全部 5 个埋点定义**，fetch.py 抓不到。已用 `sheets/v2` API 补抓（code=0）落 `raw/Giggle-TV-改名-+-自动播放/sheets.json`。正文「数据埋点」标题下在文档里是空的。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 1. 背景与目标

- 背景：**优化 song 的使用体验，支持自动播放和投屏**。
- 目标：**验证能否提升单次观看时长与投屏使用率。**
- 竞品参考：原文附 `飞书20260723-093925.mp4`（录屏，未在本库存档）。

### 2. 本期：改名 + 童锁 + 自动播放

**① 入口改名**
- 聚合入口中 **song 的入口修改为 `Giggle TV`**（图 1，粉底电视图标）。
- **进入后主页不变**（图 2：`Songs` 页 + `Nursery Rhymes` tab + 视频卡网格）。

**② 更多菜单与童锁**
- 用户点击一个视频进入播放页面，**右上角展示「更多」按钮（`…`）**。
- 更多展开 → 菜单项：**`Cast to TV`** + **`Child Lock`（开关）**。
- ⚠️ **本次不修改课程的视频播放器**（仅 Giggle TV 播放器）。
- **点击开启童锁后**：
  - **屏幕其他信息消失**；
  - **右上角有锁定童锁（图标变橙色锁）**，点击后可以关闭童锁；
  - 同时 toast：**`Child Lock is On`**。

**③ 播放与自动播放**
- 选择任一歌曲进入播放，**和目前的播放器保持一致**。
- **专辑播放时，右上角支持投屏和童锁操作。**
- 播放结束后：
  - **视频支持重播**；
  - **按列表顺序展示后 5 个视频**（`Up Next`，带各自时长）；
  - **5s 页面无操作自动进入下一个视频**；
  - **不足 5 个时，取列表最早的补足**；
  - **整个视频列表循环**。

### 3. 下一期：投屏

- 播放页「更多」→ **投屏到电视**：点击后**弹窗告知用户使用系统自带投屏**；点击 **`How to cast`** 进入**投屏操作指南**。
- ⚠️ **具体最终版以产品给到 UI 的文案为准。**
- 投屏说明页（图 8）：按手机品牌分 tab —— **Oppo / Vivo / 小米 / 华为 / 苹果 / 三星**，每 tab 给分步操作；左侧固定卡片「一键投屏 大屏更精彩」。示例：
  - **Oppo**：打开设置 → 点击「其它无线连接」→「多屏互动」开启 → 选择电视设备名称 → 通过屏幕镜像选择对应投屏方式 → 投屏成功。
  - **苹果**：从屏幕右上角（或底部）上拉打开控制中心 → 点击「屏幕镜像」→ 选择电视设备名称 → 投屏成功。
  - **三星**：下拉通知栏（如未看到 SmartView，再下拉一次展开完整面板）→ 点击 `Smart View` 图标 → 选择电视设备名称 → 投屏成功。
- **设置 - 屏幕时间底部增加文案和投屏教程**（图 9）：
  - 文案：**`To protect your eyes, try casting to a TV for learning.`**
  - 链接：**`How to cast?`**

### 4. 数据埋点（全部来自内嵌 Sheet `pNv0xx`，5 个事件）

均为 **客户端 / Event 类型**；「新增日期」字段原始值为 Excel 序列 **46230**（≈ 2026-07-27，文档未转换）。

| 事件名 | 显示名 | 触发位置 | 属性 | 属性值 |
|---|---|---|---|---|
| `giggletv_tab_click` | 推荐/专辑 tab 切换 | 点击切换推荐 / 专辑 tab 时 | `giggletv_tab` | `recommend` / `album`（切换到的 tab） |
| `giggletv_cast_click` | 投屏点击 | 点击右上角投屏按钮时 | `giggletv_cast_from` | `feed` / `player`（触发投屏的页面上下文：Feed 页／播放器内） |
| `giggletv_cast_guide_view` | 投屏教程查看 | 投屏弹窗点「How to cast」或**设置-屏幕时间页**点「How to cast?」进入教程时 | `giggletv_guide_from` | `cast_popup` / `screen_time_settings` |
| `giggletv_childlock_toggle` | 童锁开关切换 | 点击开启或关闭童锁按钮时 | `giggletv_lock_action` | `on` / `off` |
| `giggletv_end_screen_click` | 播放结束页按钮点击 | 播放结束展示重播按钮及后 5 个视频列表后，用户点击其中任一按钮时 | `giggletv_end_action` | `replay` / `select_video` |

- 事件定义里写明的分析意图：tab 切换用于「评估用户对**算法推荐**与**专辑浏览**两种内容分发方式的偏好」；投屏点击用于「评估投屏对**家庭场景**使用率提升的贡献」；结束页点击用于「评估结束页引导对**下一次观看留存**的拉动效果」。

### 5. 待确认项

1. **章节与标题不符**：文档标题是「改名 + **自动播放**」，但正文小节标题只有「**本期：童锁**」和「下一期：投屏」，自动播放规则塞在童锁小节里。自动播放是否本期交付需确认（影响提测范围）。
2. **埋点跨期混装 + 有正文没覆盖的功能**：
   - `giggletv_cast_click` / `giggletv_cast_guide_view` 属于**下一期投屏**，本期是否先埋未说明；
   - **`giggletv_tab_click` 的「推荐 / 专辑 tab」正文完全没有**（正文明确「进入后主页不变」，设计稿是 `Nursery Rhymes` tab）。**「算法推荐」这个内容分发方式在本文档里没有任何需求描述**，是漏写还是别的需求文档，必须确认。
3. **童锁的锁定范围未定义**：「屏幕其他信息消失」是否也锁返回键、进度条、系统手势？**锁定期间能否退出 App、能否被 5s 自动播放切走**都没写 —— 童锁的核心价值就是防误触，这些是必测边界。
4. **童锁的持久化未定义**：切下一个视频、退出播放页再进、杀进程重进，童锁态是否保持。
5. **自动播放 × 屏幕时间 × 童锁 三者交互未定义**：设置里 Screen time 到点会「all games and stories pause」，**列表循环自动播放是否受屏幕时间限制**？童锁开启时自动切下一个是否仍生效？
6. **循环逻辑是否与 GiggleCast 共用**：同版本《故事书使用方式引导和 gigglecast 升级》给 GiggleCast 定义了 `single` / `list` 两种循环（`gigglecast_loop_mode`），本篇的「整个视频列表循环 + 不足 5 个取最早补足」是另一套 —— 两个播放器的循环规则是否要对齐、Giggle TV 是否也要单曲循环，需确认。
7. **「投屏使用率」这个目标指标测不准**：投屏走**系统自带投屏**（不是应用内 Cast），App 只能埋到「点了投屏按钮」（`giggletv_cast_click`），**实际是否投屏成功、投了多久都拿不到**。
8. **投屏教程覆盖不全**：6 个品牌 tab 的文案「以产品给到 UI 的为准」尚未定稿；且**未覆盖机型无兜底**（印尼市场常见的 Infinix / Tecno / Realme / 一加等都不在列）。
9. **改名的影响面需一并回归**：Songs → Giggle TV 会牵动 —— V1.36《离线模式》的「歌曲离线下载」与 Downloads 资源管理、V1.37《WA 推送体系接入》深链 `paramValue=Songs`、功能广场入口配置与 `tab_name` 枚举、多语言文案（Tolgee key）。
10. **埋点「新增日期」是未转换的 Excel 序列值 46230**，且缺少「专辑播放」维度（正文强调专辑播放时才有投屏/童锁，但埋点无 `is_album` 之类字段）。
11. **无验收标准**；无视频加载失败、弱网、自动播放时应用切后台、投屏中断的兜底描述。
