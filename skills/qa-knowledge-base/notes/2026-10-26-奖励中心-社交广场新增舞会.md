## 摘要
V1.39 社交广场的续作：广场「看到真人在场」成立但**没事可做**，本期给广场加一个**常驻、不用等人、带轻教学**的集体活动——**舞会**：广场常驻舞台（Max 一直在台上跳），点舞台选 **Solo Dance（单人跟 Max 跳）/ Group Dance（多人，每场 5 席、先到先得）**；多人场**创建后统一 5 秒招募窗口**，期间他人点多人会**自动并入待开场舞会**（倒计时按发起者开场时间、不重计），广场内其他孩子收到邀请弹窗 `Tom invites you to dance! · 1/5 joined · Join 5S`；**5 秒无人应答则用历史真实答题数据补位**。玩法：**Max 领舞出题（动作动画 + 语音动词）→ 选项面板亮起 → 3 秒内选对应动词**，答对 Avatar 做同款动作、连击 +1，答错尴尬踩脚、连击清零；**先只上简单模式（每回合 1 个动作）**；谢幕结算展示「完成回合数 / 答对回合数 / 最高连击」后回广场。另含**国家信息介绍**：广场与排行榜点国旗弹**国家气泡并自动播英文国名发音**，广场 / 家园 Avatar 下新增「国旗 + 昵称 + 主线等级」。**舞会全部由 H5 实现**，新增 3 个埋点事件 `plaza_dance_invite` / `plaza_dance_session` / `plaza_dance_answer`，并扩展 `plaza_enter` / `plaza_exit`。

- 前置：V1.39《P1 功能广场入口（Giggle World 社交广场）》已上线的广场（房间分配、Avatar 展示、表情动作商店、好友名片）。

### 2. 舞会入口与发起
**正文原始流程**
- 广场**常驻一个舞台**，孩子点击舞台发起并选择舞会模式：
  - **单人模式**：自己跟着 Max 跳舞；
  - **多人模式**：向广场中的其他人发起跳舞邀请，同时在社交广场中的用户可以收到舞会邀请；**每场舞会只有五个席位，先到先得**。
- **多人模式超过 5 秒无用户应答 → 随机匹配假数据参加舞会；假数据来源 = 存储的真实用户答题数据**（埋点称「历史数据补位角色」，仅用于呈现，**禁止模拟真实孩子上报**）。
- 发起邀请流程：
  - 广场里已有人发起舞会、正在 5 秒倒计时中，其他用户再点多人模式 → **直接加入当前多人舞会**；
  - 当前舞会已满员 → 点击**重新发起**舞会邀请。

**正文中的交互改进建议（原文标注「这里需要修改交互流程，要仔细考虑一下」）**
1. **舞台是稳定入口，不让邀请追着用户走**：舞台保留循环跳舞动画，旁边始终有「**一起跳舞**」按钮；有人招募时入口附近轻量显示 `Mia 正在招呼舞伴 · 已有 2 人`，没有招募时显示 `Max 准备好啦！`；位置和按钮保持不变；**不要遮罩、提示音、连续闪烁，也不用用户点「拒绝」**，不点就是继续做自己的事。社交感由舞台上的人物、实际加入的舞伴和一起开场体现。
2. **点击后优先加入待开场舞会，否则自己开一场**：点「一起跳舞」→ 有尚未开场且仍有席位的舞会就加入，没有就创建 → **最多准备 5 秒** → 开始跳舞。
   - **正在招募的舞会可以合并参与者**（避免几人同时发起被拆散）；**已经开场的舞会不阻止别人新开一场**（随时能玩）。
   - 例：A 第 0 秒点击、B 第 1 秒点击 → B 进入 A 的待开场舞会；**倒计时仍按 A 的开场时间结束，不能因有人加入而重新计时**。
   - 准备期间角色跟音乐摇摆、舞伴陆续入场，减少「进房间干等」的感觉。
- ⚠️ 这套建议（无弹窗、不用拒绝、「一起跳舞」单按钮）与设计稿（单人 / 多人选择弹窗 + 邀请 Modal + `Not now`）及埋点章节「**产品已确认保留单人／多人选择及邀请弹窗**」冲突——以埋点章节的「产品已确认」为准推断**最终保留选择弹窗与邀请弹窗**，但「合并待开场舞会」「倒计时不重计」两条规则在 UX Spec 里也有体现，应仍然生效。

**发起规格（图 3 UX Spec 2-1 广场 · 发起舞会 · 主交互）**
| 操作 | 响应 |
|---|---|
| 广场入口 | **舞台作为统一入口**。**不同舞会独立计时、独立占位；广场可以同时存在多场舞会** |
| 点击舞台 | 弹出创建 modal（`Choose Your Dance Mode`：`Solo Dance` / `Group Dance`，右上 × 关闭），**提交创建请求防连点**；成功后**本人自动占位**，进入 3-1 并**向当前广场可参与的孩子发送邀请**；本场**接受邀请窗口为 5 秒** |
| 参与互斥 | **一个孩子同时只能参加一场**；**候场、舞蹈和恢复连接期间均不可再创建或加入另一场**；加入成功后**撤下其他邀请** |
| 创建失败 | **不占席位、不发送邀请**；显示 4-1，可重试；**返回结果不明确时先核对是否已创建，避免重复开场** |
- 舞台标识控件（待设计）：Max 一直在舞台上进行唱跳动作，可点击加入。

### 3. 收到邀请（被邀请者）
**邀请规格（图 4 UX Spec 2-2 孩子邀请 · 主交互，继承 2-1 参与互斥）**
| 操作 | 响应 |
|---|---|
| 收到邀请 | 展示**真实发起者头像和昵称**；**Max 是领舞，不是本场发起者**。复用 Modal（`.modal-overlay`） |
| 5 秒窗口 | **以本场创建成功后统一截止时间为准，显示实际剩余秒数**；**晚收到的邀请不重新计满 5 秒** |
| 点击 Join | **先申请占位，期间按钮显示 `Joining…` 并避免重复提交**；确认成功才进入舞台；**优先占位，再加载 Webview**（3-4） |
| 已满 / 已截止 | 不进入该场，分别显示 4-3 / 4-2；**可发起自己的舞会，不延长旧场邀请** |
| 点击 Not now | 关闭本次弹窗，留在当前场景；**有效邀请可在 3-2 再次选择**；**本场不重复弹窗** |
| 到期 / 参与其他场 | **立即撤下该场加入入口**；**已在候场或跳舞的孩子不再收到其他场的邀请弹窗** |
- **待确认（设计稿原文）**：多份邀请——推荐**同一时刻只弹一份**，其余保留在邀请列表、**各自计时**；**不叠加 Modal**。新稿 3-2 展示此建议。
- 邀请弹窗样式：`Tom invites you to dance!`，下方 `1/5 joined` 进度胶囊，右侧按钮 `Join 5S`（倒计时秒数）。
- 失败态（两套样式并存，见图 4）：
  - 轻提示：`Dance started!` + `OK`（**已截止：不能再接受原邀请；点 ok 关闭**）；`Stage is full!` + `OK`（**已满：不抢占他人席位；点 Start a dance 创建自己的新场**——⚠️ 图注写「Start a dance」，但该提示条上只有 `OK` 按钮）。
  - Modal：`This dance has started` / `This dance is full`，副标题 `You can start your own dance!`，下方 `Solo Dance` / `Group Dance` 两张卡直接发起新场，右上 × 关闭。
- 正文「好友接受舞会邀请流程」三分支：**抢占到席位 → 正常进入舞会准备开始**；**满员未抢占到 → 引导自己开一局**；**超时未抢占到 → 引导自己开一局**。

**被邀请者参与全流程（正文 3.3）**
1. 收到邀请弹窗 → 接受；
2. 画面转场：**进入舞台，舞台放大为主视觉区，广场退为背景**；
3. 站位 → **5 秒倒计时 Ready Go** → 舞会开始，播放背景音乐；
4. 每回合：Max 先做动作（**语音单词音频线索 + 动作动画播放线索**）→ **动作做完后选项面板亮起** → 3 秒内作答；
5. 一轮舞会结算弹窗 → 点击确认回广场。
- **参与舞会不离开广场**，只在广场侧给该用户挂一个**【舞蹈状态】**（新增状态，原文 @ 了同事跟进设计）。
- **广场内未参与舞会的孩子**：能看到正在参加舞会的 Avatar 处于【舞蹈状态】；**舞台始终有 NPC 在跳**，保证「这里一直有热闹」；点舞台依然可以发起不同模式的舞会。

### 4. 玩法与判定
- 入场：背景音乐 + 默认动作（**左右摇晃**）。
- Max 领舞出题（音频 + 动作），孩子在 **3 秒内**选出对应动词完成同款动作，结算连击。
- **Max 做动作时播放跳舞指令（告诉孩子正在跳的动作），同时背景音乐音量降低；指令音频播完后音量恢复**。

**判定规则（内嵌表 cp1KWy）**
| 项 | 规则 |
|---|---|
| 出题 | Max 做动作 + 语音报动词（如 "jump"） |
| 答题 | **动作播完后选项面板亮起，3 秒内点选动词** |
| 简单模式 | 每回合 1 个动作 |
| 困难模式 | 每回合 2–3 个连续动作，**顺序也必须一致** |
| 答对 | 角色做出同款动作，**连击 +1** |
| 答错 | 播「尴尬踩脚」动作，**连击清零** |
| 超时未答 | **本回合跳过，播 idle 动画**（视觉上就是「别人都在跳，你站着」） |
| 难度选择 | **先只上简单模式** |
- ⚠️ **超时表现两处不一致**：正文写「**选错或者超时未作答（3 秒）后，Avatar 做出错误尴尬的踩脚动作**」，内嵌表写「**超时未答 → 本回合跳过，播 idle 动画**」。超时是否清零连击，表里也没写。
- 3 秒起算点：埋点口径为「**答题面板可答后满 3 秒未答**」= timeout。
- **动作词库：后台可配，复用现有 emote 动作库（jump / clap / turn 等）**。⚠️ 但图 5 现有 emote 库里是 Heart Hands / Sleepy Nap / Happy Kick / Moonwalk / Robot Dance / Hip Wiggle / Swing Dance，**没有 jump / clap / turn**，正文「动画需求」小节只放了这张图、没写要新增哪些动作。

### 5. 谢幕结算
- 舞台中央：**全对的孩子站中间庆祝**；两侧：NPC 观众鼓掌；**答错的真实玩家不被赶到台下**。
- 结算面板：**完成回合数 / 答对回合数 / 最高连击**。
- 点击确认后返回社交广场（埋点口径：正常结算回广场**不报 `plaza_exit` / `plaza_enter`、不换广场访问 ID**）。

### 6. 运营配置
- **上线时上 3 首曲目**。
- 可配置项：**歌曲 BGM / 每场动词题库 / 单场时长 / 舞台容量**。
- 背景音乐卡点：**每一轮动作随机，音乐需要通用节奏**，可适配不同动作。
- ⚠️ 「**舞台容量**」可配 vs 正文「**每场只有五个席位**」；「单场时长」可配但**每场回合数 / 题数**未定义（埋点 completed = 「配置要求的最后一题判定完成」）。
- 文中未给后台配置页原型。

### 7. 数据埋点（2026-10-15 研发与测试执行表）
- 依据：GiggleAcademy 埋点规范；已核对 production 当前事件与属性；**以下为待实施方案，尚未向生产注册或上报**。
- **新增 3 个业务事件**（邀请 / 舞会过程 / 单题结果），普通 H5 点击复用 `$WebClick`，广场进入 / 退出和 APP 活跃复用已有事件。**不上报可推导字段**（完成率、正确率、主动 / 被动标签、真人数量、首次 / 再次）。
- 身份：沿用广场现有公共孩子标识 **`kidId`（String）**，**不新增另一套 `kid_id`**，**不把 `distinct_id` 默认当孩子 ID**。
- 时长：**现网 `duration_ms` 已是 String，本次不能改成 Number**；复用字典中 Number 类型的 `stay_duration_ms` 与 `play_duration_ms`。缺少退出回调（如进程被杀）**不能补 0 或凭最后一次点击猜退出时间**——该访问不进完整时长样本，并展示有效时长覆盖率。

| invite | `shown` | 接收者的有效邀请弹窗**首次真实可见** | 消息到达但未展示、已失效未展示、重绘 |
| invite | `accepted` | 点击接受，且开始处理一次有效入场请求 | 禁用按钮、同一请求处理中连点 |
| invite | `failed` | 接受后得到明确满员、过期或错误结果；传 `fail_reason` | 未接受、拒绝或弹窗自然消失；成功入场 |
| session | `joined` | 创建或加入成功得到确认，进入该场准备区；同时确定 `play_mode`、`entry_source` | 点击模式或发送请求 ≠ 成功；入场失败 |
| session | `started` | **首题已展示且选项可操作** | 准备区、背景预热舞蹈、单纯播开场动画 |
| session | `completed` | **配置要求的最后一题判定完成**时 | 不等孩子点结算确认；点确认 / 正常返回广场**不再报 exited** |
| session | `exited` | 已 joined、未 completed，孩子明确主动退出 | 临时切后台、重连过程、正常结算返回 |
| session | `failed` | 已 joined、未 completed，明确不可恢复错误终止 | 短暂断线恢复；进程被杀**不伪造 failed** |
| answer | `correct` / `wrong` / `timeout` | 本题**首次锁定判定**时；`timeout` 只用于**选项可答后满 3 秒仍未作答** | 中断未判定的题；**NPC、Max、历史补位角色不报**；重复点击 / 回调 |

**去重**：邀请按「孩子 × `dance_id` × `invite_state`」；舞会过程每孩子每场 `joined`、`started` 各一次，**`completed` / `exited` / `failed` 三个终态只允许一个**；单题按「孩子 × `dance_id` × `round_index`」一次。**重连保留原 ID 和已报状态**。

**属性字典（内嵌表 HNx2Ev）**
| 属性 | 类型 | 必填范围 | 取值与定义 |
|---|---|---|---|
| `dance_id` | String | 所属事件必填 | 同一场的邀请和所有参与者用**同一真实场次 ID**；**单人场也有 ID**；重新开场生成新 ID；**重连不换 ID** |
| `plaza_visit_id` | String | `plaza_enter`、`plaza_exit`、邀请、舞会过程 | H5 每次**真正进入**广场生成；进入舞会、返回广场、切后台再回来**不换**，真正离开后再进才换 |
| `invite_state` | String | 必填 | `shown` / `accepted` / `failed` |
| `fail_reason` | String | **仅 `invite_state=failed`** | `full`=满员；`expired`=舞会已开场或邀请失效；`error`=网络或其他错误。未点接受不报 failed |
| `play_mode` | String | 必填 | `solo` / `multiplayer`；**多人用历史数据补位后仍为 multiplayer** |
| `entry_source` | String | 必填 | `create`=主动创建本场；**`self_join`=从舞台主动加入已有场**；`invite`=通过邀请弹窗加入。入场成功后固定不变；**单人仅 create** |
| `dance_state` | String | 必填 | `joined` / `started` / `completed` / `exited` / `failed` |
| `wait_duration_ms` | Number（毫秒） | **仅 `started`** | 入场成功到准备倒计时结束、正式首题领舞开始的**前台累计**时间，**不含首题演示 / 语音**；用于检验 5 秒准备规则；未开场不填 0 冒充 |
| `play_duration_ms` | Number（毫秒） | **仅 `completed` / `exited` / `failed`** | 从 started 起累计前台实际游玩时间；**未 started 即退出为 0**；切后台、准备等待、结算停留不计 |
| `round_index` | Number | 必填 | 本场从 1 递增；重连、重绘保持原序号 |
| `action_id` | String | 必填 | 复用现有动作库 ID，**记录本题正确答案对应的动作，不是孩子误选的动作**；不重复传动作名 |
| `answer_result` | String | 必填 | `correct` / `wrong` / `timeout`（答题面板可答后满 3 秒未答）；中断未判定不伪造 timeout |
| `stay_duration_ms` | Number（毫秒） | `plaza_exit` | 本次访问从进入到真正离开的前台可见毫秒数，**包含舞会和等待、排除后台**；历史 `stay_duration` 口径不变 |

**参与来源判定**：从舞台点多人后**自动加入已有待开场舞会 = `self_join`**；成功创建新场才是 `create`；通过邀请弹窗进入才是 `invite`。**邀请满员或过期后孩子另开一场 → 新场 ID、`entry_source=create`，不能延续为 invite**；重连后保留原来源。
**准备等待与开场口径分开**：`wait_duration_ms` 不含首题领舞演示；joined→started 的时间差是「到能作答的总等待」，**不能直接用它判定 5 秒准备超时**。

**指标与口径（内嵌表 BWLFIS，摘要）**
- 广场单次停留 / 舞会用时：有效退出样本 `stay_duration_ms` 总和 ÷ 完整访问数 + 中位数；舞会用时 = 该访问各场终态 `play_duration_ms` 之和；等待和结算停留归「广场其他用时」；有效时长覆盖率 = 有效退出访问数 ÷ 进入访问数，**时长缺失不计 0**。
- 广场回访 / APP 留存：以某日可体验舞会版本的广场进入孩子为一组，看次日 / 随后 7 日广场回访、APP 次日 / 第 7 日活跃，只统计走完整观察窗口的人群。
- 舞会参与率 = 当天 started 孩子数 ÷ 当天可体验版本广场进入孩子数，按 `play_mode` 分组。
- 邀请转化：shown→accepted；joined→started 只取 `entry_source=invite`；failed 按 `fail_reason` 拆。
- 开场率 = started 人次 ÷ joined 人次；完成率 = completed ÷ started；再玩率 = 同次访问完成后又 started 的孩子访问数 ÷ 完成过的孩子访问数；**人次 = 孩子 × dance_id，不按事件条数**。
- 主动发起 / 主动加入 / 受邀加入：按 create / self_join / invite 分别计 joined 与 started 孩子数；**三类 UV 不能相加当总人数**。
- 真人同场率：按 `dance_id` 聚合实际 started 的不同真实孩子，**≥2 人的场数 ÷ 全部多人已开场场数**；**1 个真人 + 历史补位不算真人同场**。
- 正确率 / 超时率：correct / timeout 题数 ÷ 全部已判定题数，可按 `action_id` 拆；**不是学习掌握率**。
- 国家介绍使用率：国旗可见页面中点国旗孩子数 ÷ 页面孩子数，广场、排行榜分开。
- 所有 UV 按统一孩子身份去重；**已开场但缺终态的记录仍进完成率分母，显示「终态缺失」**。

**测试验收清单（内嵌表 OBh67n）**
| 场景 | 预期结果 |
|---|---|
| 单人正常完成 | `create` + `solo`；joined→started→completed；每题一次 answer；点结算确认不多报终态 |
| 主动发起与自动加入 | 发起者 `create`；从舞台点多人被合并入已有场的孩子 `self_join`；**二者 `dance_id` 相同** |
| 收到邀请并成功开场 | shown→accepted→joined→started，后两项 `entry_source=invite`，同一孩子 / 场次可串联 |
| 邀请未接受 / 满员或过期 | 未接受只有 shown；接受后失败有 accepted、failed 及原因，**没有 joined**；随后自开新场为新 ID + `create` |
| 真人 + 历史补位 | 仅真实孩子上报；同场 2 个真实 started 算真人同场；1 真人 + 4 补位不算 |
| 答错 / 超时 / 中断 | wrong 与 timeout 分开；**3 秒从选项真正可答开始**；中断未判定不补题，已判定结果保留 |
| 等待退出 / 游戏中退出 / 异常 | 等待退出有 joined 和 exited、无 started、`play_duration_ms=0`；游戏中退出有 started 和 exited；明确异常 failed；**终态只报一个** |
| 切后台 / 重连 / 正常回广场 | 后台不累计时长；**重连不重报开始、不换 ID**；正常结算回广场不报 `plaza_exit`、`plaza_enter` 或新的访问 ID |
| 重复回调 / 进程被杀 | 重复状态和题目均去重；进程被杀缺退出**不伪造时长或终态** |
| 身份 / 类型 / 预置采集 | 同一孩子跨邀请与舞会身份一致；String ID、Number 毫秒；**不把 `duration_ms` 改类型**；`$WebClick` 自动与手动不重复 |
