## 摘要

V1.33.0 优化注册登录,解决游客数据丢失问题:① **登录界面标注上次登录方式**(第三方标"上次登录"、邮箱/手机自动回填);② **Token 自动延长**(最多 90 天);③ **day2 起引导注册** + 已注册账号校验,避免误登老账号清掉游客学习记录。产品 Owner: Leah;优先级:高。(文档无版本字段,figma 1.33.0,按主人指定 **V1.33.0**。)

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 背景与数据
- 痛点:注册想同步游客数据却误登老账号致游客数据丢失;退出后不确定用哪个账号登;切设备发现没同步。
- ⚠️ 微信登录后**是否引导绑手机号:本次不做**(用户量不大)。
- 数据(5月,排除学校账号):同一设备多账号 10,482(**7.2%**,其中 6.7% 是 2 账号);同一账号多设备 1,212(0.7%)。**99.6% 是单向交接**(A 停用→B 出现,A 不再回来;81% 在 1 天内),新账号几乎都是全新注册而非登回老账号 → 印证"丢账号重新注册"假设。

### 1. 上次登录标注
- Token 过期或用户退出后回登录界面,**标注上次使用的登录方式**:
  - 第三方账号(微信/Google/Apple/学校)→ 底部标「**上次登录**」。
  - 邮箱或手机号 → **自动回填到输入框**,用户可手动删除。
- **Token 时长**:目前 15~30 天;**登录后自动延长有效期,最多延到 90 天后过期**。

### 2. 引导注册(测试重点)
- **day2 起**,用户点击主路径课程 → 弹引导登录弹窗;出现时播语音「请家长帮忙注册,避免丢失学习数据哦～」(弹窗文案:已经学了 X 节课,注册以免丢失学习进度)。
- **输入账号点【箭头】按钮时**:判断游客课程学习数是否 **> 5 节课**:
  - **> 5 节课** → 先校验该账号是否已注册:
    - **未注册** → 下发验证码,走原有流程。
    - **已注册** → 弹窗提示「该账号已注册,登录后将使用账号原有进度、清除当前游客记录。想保留当前进度?请更换账号注册」,询问是否确认登录。
  - **≤ 5 节课** → 不需判断。
- 已注册弹窗的两按钮:
  - **【更换注册账号】** → 关弹窗,停在注册页,**不清除已输入账号**。
  - **【仍要登录】** → 进入下发验证码流程正常登录;**登录老账号后游客数据可保存**(退出登录可再回到游客数据)。
