## 摘要

V1.37.0 把竞技场升级为 **App 内社交游戏化模块「Game Arcade 游戏大厅」**：聚合入口新增 Game Arcade（替换家庭游戏入口）、上线 **6 个单人 + 2 个本地多人小游戏**、**每局统一消耗 20 Giggles** 形成「参课 → 获得 Giggles → 竞技场消耗」正向循环，单人游戏各自独立**全国 / 全球榜（前 100 名）**，并支持**分享到 WhatsApp / 微信生成免登录试玩落地页**驱动传播与回访。依据是 PK 实验组在**非首日用户**上留存全面优于对照组（次日 +0.37pp ~ 第 6 日 +0.86pp，人均 3.7 次）。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 1. 需求背景（PK 上线数据复盘）

- **新用户**：首日就去 PK，**没有提升，数据有波动** → 后续还是以课程学习为主。
- **非新用户（大盘数据）**：**PK 功能实验组的留存明显好于对照组**（目前已到**万人级别**，趋势稳定，比较可信）。
- 结论：**有一定产品使用基础后才接触 PK 的用户 → 更容易形成多次使用习惯（人均 3.7 次）→ 留存表现明显更好。**

**核心目的**
1. 给孩子提供**轻量、可重复玩**的小游戏，**消耗课程环节产出的 Giggles**，形成「**参课 → 获得 Giggles → 竞技场消耗**」的正向循环。
2. 通过 **Study Buddy（同桌）机制**提升结伴学习留存（**单开需求，不在本篇**）；**邀请同桌 1.2 支持游戏挑战**。
3. 通过**排行榜和分享机制**驱动传播与回访。

### 4. 单人游戏（本期暂定上线 6 个）

| 游戏 | 状态 | 玩法 |
|---|---|---|
| **单词 PK** | 已有 | 匹配机器人和历史真人数据，进行对战 |
| **单词 PK 无尽模式** | **修改** | 基于目前的单词 PK，一直出题目，**错 3 次结束**；**开扭蛋的功能下掉** |
| **点名连连看** | 新增 | 听 Max 播音频，**连线两块牌**，得分越多 |
| **托盘打包台** | 新增 | 听 Max 播音频，选择 quiz 图片，**三消玩法** |
| **钓鱼钩卡** | 新增 | 听 Max 播音频，选择 quiz 图片，从海里勾起正确的卡；**一轮答对后可以延长鱼钩长度，进入下一组** |
| **听音跑酷** | 新增 | 玩家在**并排的门**中选择读音对应的正确门跑过去。**答对时角色所带人群数量 ×2，答错时 ×0.7**；沿途设有**留有缺口的障碍（对手 / 敌对角色躲不掉）**；终点有「**巨人天降**」结算演出。**按胜利次数排名（单位：胜）** |

**单词 PK 无尽模式细则**
- 复用目前的单词 PK，**出题规则保持**，**不限制题目数量**；**3 分钟内**，只要用户没有错 3 次就可以一直答。
- **只有 3 次错误机会。**
- 结束答题展示：**分数、学习单词数量、最大 combo、本局单词卡**。
- 出题规则：基于**用户所在 level 及 level 以下**随机出单词库题目；**优先出学过的单词，再出未学过的；若学过的不足，以未学过的补足**；**干扰项从同级别单词中随机出**。
- **限时 3 分钟，得分越多排名越高。**

**点名连连看细则**
- 核心玩法参考 Cloud 文档 `PRD_点名连连看.md`。
- 难度选择：**简单 = 4 个单词（1 板）/ 中等 = 8 个单词（2 板）/ 困难 = 16 个单词（3 板）**。
- 出词规则同单词 PK；⚠️ **单词的出题判定单独基于游戏记录**（不与课程学习记录混用）。

**其余三个新增游戏**
- 托盘打包台（`PRD_托盘打包台.md`）：出词规则同点名连连看。
- 钓鱼钩卡（`PRD_钓鱼钩卡.md`）、听音跑酷（`PRD_听音选门跑酷.md`）：出词规则 = 基于用户所在 level 及以下随机出题 + 优先学过 + 干扰项同级别随机。

### 5. 线下多人游戏区（本地多人，本期 2 个）

**单词飞船**（`PRD_单词飞船.md`）
- 出题规则：基于用户所在 level 及以下随机出题；优先出学过的单词；干扰项从同级别单词随机出。

**抢答游戏**（`PRD_抢答游戏.md`）—— 三种题目类型

| 类型 | 规则 |
|---|---|
| **单词** | **本次仅支持「听音看文字选文字」「听音看图选文字」两个题型**；出词规则同上 |
| **百科常识** | **题目需本地化**；提供 **1000 题 excel**，表结构 = 题干 / 正确答案 / 干扰项；**选项随机展示，不固定排序**；**题干自动 TTS 播放**；**本期题目都是纯文本**；**用户答完 1000 题以前不重复出题**；**Admin 可能需要配置** |
| **口算** | 随机出题，**100 以内的加减法，本期不支持乘除法**；随机出现**两个数加减、三个数加减**；选项 = 正确答案（系统计算）+ **2 个干扰项（随机生成）** |

- 结束时：**赢的用户头像放大，并展示 `Victory`**。

### 6. 分享链路

**发起分享**
- 点击单人游戏的**右上角**生成分享链接。
- 展示文案：`Share this link with your friend.` / `Your friend can tap it to start playing right away.`
- 渠道：**WhatsApp / 微信 / 复制链接**。

**WhatsApp 链接预览（Open Graph）**
- WhatsApp 的链接预览读取网页的 **Open Graph 元标签（`og:title` / `og:description` / `og:image`）**，与 Facebook / Messenger 同一套机制。
- 只要落地页正确写好这几个 meta、**页面公开可访问（不能有登录墙）**，预览卡片就会自动生成，**没有任何审批流程**。
- ⚠️ **`og:image` 建议尺寸 1200×630，图片链接要能被外部抓取。**
- title / description **五组候选（任选一条，未定稿）**：

| # | Title | Description |
|---|---|---|
| 1 | Listen & Match · A Challenge from Giggle | A quick listening game — tap and play, no login needed. |
| 2 | Beat My Score in Listen & Match | Can you top my score? Play now, no sign-up required. |
| 3 | Listen & Match · Surprisingly Addictive | Listen, match, repeat — harder to put down than it looks. |
| 4 | A 3-Minute Brain Break | One quick round of Listen & Match. Just tap and play. |
| 5 | Listen & Match · Free to Play | No login needed — download Giggle Academy for more games. |

- `og:image`：**直接用游戏的封面**。

**分享落地页（从 WhatsApp 点链接打开）**
- **竖版**游戏介绍页：游戏封面 / 游戏名称 / 游戏一句话介绍 / **点击开始游戏，直接开始**。

  - adjust 跳转链接：`https://app.adjust.com/21pj288c`

### 8. 待确认项

1. **游戏数量口径不一**：介绍页写「**所有 9 个游戏**统一 20 Giggles/次」，但正文只列 **6 单人 + 2 多人 = 8 个**；排行依据表也只有 6 行。第 9 个是谁。
2. **同一游戏两个名字**：正文叫「**单词 PK 无尽模式**」，排行依据表叫「**单词谁记得多**」，而正文「不支持选难度」那句又用了「单词谁记得多」。上线前必须统一（影响榜单标题与埋点枚举）。
3. **排行榜单位设计稿与规则表冲突（重要）**：规则表说单词 PK 单位是「**胜**」，但全国榜设计稿显示 `27 Lessons / 18 Lessons / 17 Lessons / **15 score**`（同一榜单里 Lessons 与 score 混用，且 Lessons 与游戏无关），全球榜显示 `Scores`。三种单位并存，需以规则表为准重画。
4. **本篇没有埋点方案**，只有 3 个开发提问 + 外部 `mini-game-tracking-review.md`。而开发提问本身已点出两个硬缺口：**分享按钮无埋点**、**单机游戏三个入口（课程路径 / 大厅 / 分享外链）不区分来源** —— 不解决就无法评估「分享驱动传播」这个核心目的。
5. **强前置依赖未闭环**：入口改造依赖 `homepage_toplearners` **AB 实验组全量**。若该实验未全量，本期入口方案（Deskmate 回位、排行榜移位、Game Arcade 替换家庭游戏）全部不成立 —— 需确认实验全量时间点与本期上线的先后。
6. **「替换掉家庭游戏入口」= 家庭游戏下线还是移位**未说明；Family Games 在功能广场与离线模式篇均有涉及，需一并回归。
7. **4 个新增单人游戏 + 2 个多人游戏的判定/计分/失败条件全在外部 PRD md**（`PRD_点名连连看.md` 等），本文档不含 —— **写用例前必须另取这 6 份 PRD**，否则只有玩法一句话。
8. **20 Giggles 的扣费时机与兜底全缺**：进入前扣还是结束扣、**余额不足如何提示**、中途退出/闪退是否退款、多人游戏由谁扣，均未定义。（注意与 V1.36《Mai 电量系统》是**两套不同货币**，勿混淆规则。）
9. **钓鱼钩卡排名单位「米」**与其他游戏的「胜」「分」不同量纲，同一套榜单 UI 如何复用（数字格式、排序方向）需确认。
10. **百科常识 1000 题细节未定**：本地化覆盖哪些语言、Admin 配置是「**可能**需要」、**答完 1000 题之后的行为**（是否开始重复、是否补题）未定义。
11. **抢答游戏是本地多人（同一设备）**，但**「赢」的判定规则、双方按键/触点如何分配**不在本文档。
12. **免登录试玩的数据归因未定义**：落地页「不能有登录墙」+「点击开始游戏直接开始」，游客成绩是否计入排行榜、如何与后续安装的账号打通、是否有防刷，均未说明。
13. **两处「待定：等 bolin 设计完第一个再敲定」**（浏览器外横屏提示、游戏结束页），本期是否交付未定；且横屏提示对纯 H5 分享页是必需项（游戏都是横版）。
14. **分享文案未定稿且写死了单个游戏**：5 组 title/description 全部围绕「Listen & Match（点名连连看）」，**其余 5 个单人游戏的分享文案未给**。
15. **Study Buddy / 邀请同桌 1.2 支持游戏挑战是单开需求**，本篇不含 —— 但核心目的第 2 条依赖它，本期能否形成「社交」闭环需确认。
