## 摘要
多图故事里的角色现在都是「死」的、没有接入 AI，本期把**画面角色接入 NPC 对话体系**，让孩子能与故事角色**纯英文对话** —— 本质是**让 M Town Talk 的 NPC 能力支持多图故事**。做法：**bbox 只绑 `npcId`，人设 prompt / 形象 / 音色一律读「NPC 资产登记表」这个统一真源**，不在故事配置里重复定义；**激活方式两种（进入页面自动激活 / 点击 NPC 激活），按 html config 逐页配置**；**同一时刻只与一个 NPC 对话，点其他 NPC 即切换，小麦本身也是一种 NPC、可点击召回**，NPC 被激活时**小麦暂停对话进入待机**；**NPC 台词遵循对话课 NPC prompt 标准结构与课程句子难度原则，并要感知翻页带来的场景 / 时间变化做连续对话**。埋点建议两个事件 `npc_talk_start` / `npc_talk_end`（**待评审**）。**存量无 NPC 字段的多图故事按现状运行，配置向后兼容**。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 基本信息
- 产品 Owner：**Libin**；文档版本号字段 **V1.39.0**（与用户给的一致）。
- **前置依赖：《用户和小麦的对话升级》（连续对话为本需求前置）** —— 即本批《小麦的消息列表和消息气泡》。
- 资源：Demo `gw_e02_delivery.zip`；**NPC 统一真源 = NPC 资产登记表（人设 prompt / 形象 / 音色）**。
- 修订记录：**2026-09-03** 按产品文档规范重排、文末补「风险与待决策」（审核意见）。
- 背景：**现在多图故事里的形象都是「死」的，没有接入 AI**；接入后可与用户纯英文沟通 —— **另一个层面相当于 M Town Talk 支持了多图**。
- 目标：**多图故事中的画面角色接入 NPC 对话体系，用户可与故事角色纯英文对话。**
- 主要特性：① **Bbox 绑定 NPC**；② **进入页面 / 点击 NPC 两种激活方式（html config 可配置）**；③ **同一时刻仅与一个 NPC 对话，点击可切换；小麦本身也是一种 NPC**。

### 1. 功能明细
| 元素 | 规则 / 逻辑 |
|---|---|
| **Bbox 绑定 NPC** | **bbox 只绑 `npcId`**；**人设 prompt、形象、音色一律读 NPC 资产登记表（统一真源），不在故事配置内重复定义** |
| **NPC 激活方式** | **进入页面自动激活 / 点击 NPC 激活**，**按 html config 逐页配置** |
| **激活 NPC 后** | **暂停与小麦的对话，小麦待机**（视觉方案见 D2）；**语音输入发往当前激活的 NPC**（⚠️ 原文写「登录之后」，**疑为「录音之后」的笔误**，见 D1） |
| **切换与召回** | **同一时刻单一对话对象**；**点击其他 NPC 即切换**；**小麦亦为 NPC，可点击召回** |
| **NPC 台词** | 遵循**对话课 NPC prompt 标准结构**与**课程句子难度原则**（词汇简单、句子完整、语法统一简单、感知内容）；**台词服务页面教学目标**。感知内容举例：**翻页代表场景变换与时间变换（比如三天以后、一周以后），NPC 需要感知翻页，进行符合逻辑的连续对话** |

### 2. 数据埋点（原文标注「建议」，**完成情况 = 待评审**）
| 事件 | 触发时机 | 参数 |
|---|---|---|
| **`npc_talk_start`（建议）** | **NPC 被激活、开始对话** | `npc_id`；`story_id`；**`activate_source` = `page_enter` / `click`** |
| **`npc_talk_end`（建议）** | **切换对象 / 离开页面 / 退出** | `npc_id`（同上）；**`round_count`（本段对话轮次）** |

### 3. 其他功能需求
- **多语言**：**NPC 对话为纯英文**；**周边 UI 文案需支持多语言（印尼语为主）**。
- **数据兼容**：**存量多图故事无 NPC 字段 —— 未绑定 NPC 的故事按现状运行，配置向后兼容**。

### 4. 风险与待决策（原文 2026-09-03 审核补充）
> 原文结论：**方向成立且复用度高 —— 本需求本质是打通两条已有资产线：多图故事的画面 / bbox / 角色帧 × M Town Talk 的 NPC 对话体系。风险集中在原文歧义、低龄体验与上下文规则三处。**

| 编号 | 风险 / 决策点 | 建议 |
|---|---|---|
| **D1** | **原文两处疑似笔误，开发无法执行**：「**登录之后**，对话会跟激活对象的对话」（疑为「**录音之后**」）；「小麦为 NPC 的一种，**首以上**点击行为断掉和重新激活」（疑为「**适用以上**」） | **澄清后回写需求范围第 3、5 条** |
| **D2** | **小麦「变为问号」的低龄体验**：小麦是孩子的情感锚，**问号态可能引发困惑**；且**待机视觉不该像「故障」** | **改为小麦退至画面角落旁观（点头 / 欢呼小动效），点击即召回；避免问号符号** |
| **D3** | **NPC 定义重复建设风险**：若在故事配置里内联人设，**将与 NPC 资产登记表（统一真源）漂移** | **bbox 只绑 `npcId`；人设 prompt / 形象 / 音色运行时读登记表**；prompt 遵循**对话课 NPC 标准结构（Driver / Follower）** |
| **D4** | **上下文切换规则未定义**：**切换 NPC 时对话历史如何处理？切回小麦是否恢复此前话题？** | **共享场景事实 + 各 NPC 独立人设上下文；切回小麦恢复待机前话题** |
| **D5** | **依赖与成本口径**：NPC 对话必然多轮，**依赖《用户和小麦的对话升级》**；**是否计电量未定**（现状电量仅覆盖 `main_chat`） | **排期挂依赖；电量口径与对话升级、贴纸岛两需求一并决策** |
| **D6** | **教学一致性**：**纯英文自由对话易漂移出页面教学目标** | **NPC 台词按页面教学脚本服务教学目标**，句子难度遵循课程统一原则；**自由聊天设轻引导回正** |

### ⚠️ 待确认（写用例前需拉齐）
> 原文自己已经列了 D1–D6 且写明「进入开发前需补齐」五项 —— **这篇在当前状态下还不具备写完整用例的条件**，下列是在此基础上补充的测试视角问题。
1. **激活 / 切换的状态流转图缺失**（原文点名要补）：`进入页面自动激活` 与 `点击激活` 同页共存时谁优先、**翻页时上一页激活的 NPC 如何收尾**、连续快速点击多个 NPC 的表现，全未定义。
2. **D1 的两处笔误未澄清前，第 3、5 条规则实际不可执行**（语音输入发给谁、小麦召回的点击行为适用范围）。
3. **上下文规则（D4）只是建议**：「共享场景事实 + 各 NPC 独立人设上下文」若落地，**切换后 NPC 是否知道孩子刚跟别人说过什么**、**离开页面再回来是否续上**，都要定义，否则无法判定对话正确性。
4. **电量口径（D5）未定**，且与本批另两篇冲突：《消息列表》写「列表中的对话消耗电量」、《小麦接入课程路径》写「不消耗电量、不显示电量组件」—— **三篇必须一起定**。
5. **NPC 资产登记表本身不在本篇**：登记表的字段、维护入口、**NPC 下线或改人设时对已发布故事的影响**，都没有说明。
6. **纯英文 vs 周边 UI 多语言**：孩子界面语言是印尼语时，**NPC 全英文对话的可理解性与兜底**（是否允许母语提示、听不懂时怎么办）没写，而 D6 只给了「轻引导回正」的方向。
7. **埋点仅两个建议事件且待评审**：没有**激活失败 / 切换 / 翻页导致的对话中断**等事件，`round_count` 的计数口径（含 NPC 首句？）也未定义。
8. **存量故事兼容**只写了「未绑定 NPC 按现状运行」，**部分页绑了、部分页没绑**的混合故事如何表现（是否影响翻页连续对话）没写。
9. **与 V1.36《M Town Talk 支持 bbox 点击》的关系**：那篇把「乱点 bbox 当意图输入喂给 AI」，本篇 bbox 改成绑 `npcId` —— **同一 bbox 两种语义是否共存、优先级如何**，需要与那篇一起回归。
