## 摘要
和《社交广场新增舞会》同版本、同背景的另一个广场玩法：广场新增**冰淇淋推车入口** → 店铺首页 `Ice Cream Time` 两个按钮。**「当店长赚钱」（打工，产出 Giggles）**：限时 60 秒，顾客（随机取广场用户形象）用英文点单（如 `One scoop of strawberry and one scoop of mint in a cone, please.`），选对口味 / 容器后点「制作好了」交付，**服务正确 N 位 = 单价 × N Giggles**，**每日上限 2 次**，额度用完店铺首页的打工按钮置灰并用中英 TTS 告诉孩子明天再来；首次进入播放新手引导。**「买冰淇淋」（消耗 Giggles）**：八爪鱼店长出货，**一次性 action、不进永久道具库存**，买完在广场播吃冰淇淋动画（他人可见），也可以 `Send it` 送给广场好友（对方看到 `Tom brought you an ice cream.` 并播动画）。前端和广场动画都是 H5，金币和赠送成功由后端负责；新增 5 个埋点事件 `plaza_icecream_work / purchase / trade / gift / effect`。⚠️ **价格（10 vs 示意稿 5 / 20）、动画时长（10–20 秒 vs 30 秒）、每日额度口径、买完落点 / 同时持有 / 连续购买都未定**。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 基本信息
- 背景与舞会篇一字不差：广场 V1.39 上线后「看到真人在场」的感受成立，但可玩性与互动性不足；本期要给广场一个**常驻的、不用等人的、带轻教学属性**的集体活动。
- 产品目标：**拓展广场玩法的同时，在场景中学英语，寓教于乐**。
- 目标层级（内嵌表 EiF8kp）：功能层（主）= **广场单次停留时长与回访率提升**；全局（次级）= APP 留存。
- 实现：埋点章节写明「**前端及广场动画均为 H5；金币与赠送成功由后端负责**」。
- 文中未写 AB key / 灰度开关。
- 附件 `plaza-icecream-demo.zip`（飞书文件块，fetch 不下载附件，**未入库**）。

### 1. 入口
- 社交广场新增**冰淇淋车入口**（图 1：广场右侧绿白条纹顶棚的推车 + 八爪鱼店长）。
- 点推车 → **店铺首页 `Ice Cream Time`**（左上返回、右上 `?`），底部两个按钮：**「买冰淇淋」**（粉色）/ **「当店长赚钱」**（白色）。
- 埋点控件名（内嵌表 bdDU2l）：冰淇淋车入口 `icecream_entry`；`Buy` → `icecream_buy`；`Be shopkeeper` → `icecream_work`；`Take it` → `icecream_take`；`Send it` → `icecream_send`。⚠️ 设计稿按钮是中文「买冰淇淋 / 当店长赚钱」，埋点按英文文案 `Buy / Be shopkeeper` 命名，多语言文案表未给。

### 2. 打工（当店长赚钱，产出 Giggles）
**规则（正文）**
- **限时 1 分钟**（设计稿右上闹钟倒计时 `60`），顾客依次点单（正文示例 `Can I have one mint in cup?`；设计稿示例 `One scoop of strawberry and one scoop of mint in a cone, please.`）。
- **选对配料 / 容器 → 顾客开心获得冰淇淋 → 金币入账 → 下一位**。
- 奖励：**服务正确 N 位 = 单价 × N Giggles**（单价未给）。
- **每日上限：2 次 / 天**。
- 点单需求**随机生成**；**点单顾客形象随机取广场里的用户形象**模拟顾客。
- **冰淇淋口味有多种，但每次进入游戏只随机出 4 种**；点单时顾客要的口味必须和本局已有的 4 种匹配（**不能点本局没出的口味**）。
- **新手引导**：首次进入游戏（店长模式）播放新手引导流程（流程内容未给）。

**顾客表情反馈（正文）**
| 情况 | 表情 |
|---|---|
| 10 秒内顺利拿到正确的冰淇淋 | 开心 |
| 10 秒内没拿到冰淇淋 | 轻微着急 |
| 拿到错误口味的冰淇淋 | 沮丧 |

**设计稿中的 Avatar 表情分镜**（图 2）：S02 点单 · 开口表达 / S03 制作中 · 期待 / S04 久等 · 轻微焦急 / S05 递交 · 惊喜接收 / S06 品尝 · 咀嚼过渡 / S07 好吃 · 开心爱心 / S08 不符 · 轻微沮丧 / S09 完成 · 感谢告别（第一格编号被标题遮住）。

**操作细节（设计稿）**
- 柜台 4 桶口味（示例：草莓 / 香草 / 巧克力 / 薄荷）+ 勺子；容器：蛋筒、粉色杯，另有一个蓝色图标（图上无文字标注）；右下「制作好了」按钮（未选时置灰）。
- **点击道具：会播放单词英文发音**。
- **最多支持三个球**。
- 选错 / 超时反馈：设计稿 2.6 标题写「**待确认**」。

**每日额度用完（正文）**
- 原文：「当天上线两次后，继续玩，要告诉孩子明天再来，并且**首页打工按钮置灰**，**第三局的时候，隐藏再来一次按钮**。在首页点击打工，」播放：
  - 中文 TTS：`今天的 Giggles 赚满啦，你真棒！明天再来赚更多吧！`
  - 英文 TTS：`You earned lots of Giggles today. Great job! Come back tomorrow for more!`
- ⚠️ 原文句子不完整，「上线两次」应为「玩两次」；「第三局的时候隐藏再来一次」与「首页打工按钮置灰」的先后关系不清（第 2 局结算页是否就该隐藏「再来一次」？）。埋点口径：**每日额度不足不产生打工局**（不报 started）。

### 3. 买冰淇淋（消耗 Giggles）
**规则（正文）**
- **定价 10 Giggles**。
- **性质：一次性 action，不是永久道具**。
- **效果：在广场播放 10–20 秒吃冰淇淋动画**。

**购买流程（设计稿核心流程 4）**
- 4.1 我当顾客：八爪鱼店长 TTS「**告诉我你喜欢吃的冰淇淋口味，我会立马开始制作**」；面板 `Pick your ice cream`：容器 `Cone` / `Cup` 二选一，4 个口味（Strawberry / Vanilla / Chocolate / Mint）各带 `− 数量 +` 步进器，按钮 `🪙 价格 Get it!`；右上 Giggles 余额（示例 1,712）。
- 4.2 购买成功：余额处飘 `-20`，示意「**一次性 action，不进入永久道具库存**」；出货弹层 `Ice cream` 放大发光展示。
- 4.3 广场吃冰淇淋 · **他人可见**：Avatar 拿着冰淇淋 → 吃（开心爱心）→ 恢复；图注「**播放 30 秒；具体时长及中断行为待确认**」。

**出货规格（UX Spec 8-2 出货 · Take it，由 7-2 扣款成功进入）**
| 操作 | 响应 |
|---|---|
| 出货 | 冰淇淋放大发光展示 |
| 店长台词（建议） | 出货时店长 TTS：EN `Here you go` ／ 中「给你」；按钮 EN `Take it`（稿中原文）／ 中「拿好啦」 |
| 点击 Take it | 回到广场，进入 7-3 吃冰淇淋动作；**一次性 action，不进永久道具库存** |
- **待确认 · 买完落点**：推荐点 `Take it` 直接回广场播放动作（购买的价值在于被其他玩家看见）。
- **待确认 · 同时持有**：推荐**同一时间只持有 1 个**，动作结束前「买冰淇淋」置灰（一次性道具，不做库存）。
- **待确认 · 连续购买**：推荐**不限购买次数**，但须当前动作结束后才能再买。
- 设计稿另有产品批注：「购买成功之后，是要引导他去广场、离开购买界面，还是留在当前界面继续购买？另外，我们支持用户手上拿着多个冰淇淋道具吗？还是说冰淇淋道具会被存在某一个地方，然后拿出来使用（作为一次性道具）？可以一直购买吗？」

### 4. 赠送给好友
- **购买成功后新增【赠送给好友】按钮**（设计稿出货弹层两个按钮：`Send it` / `Take it`），点击后**回到广场，引导用户选择广场中的好友**赠送冰淇淋。
- 玩家本人视角：**点击赠送对象后，被赠送的对象播放 Avatar 动画（可以点击自己的 Avatar）**（S05 递交 · 惊喜接收 → S07 好吃 · 开心爱心）。
- **好友接受流程**：好友在社交广场里能看到冰淇淋动画；被赠送者视角顶部提示 `Tom brought you an ice cream.`。
- 埋点口径：**当前需求没有「接受 / 拒绝」按钮**；`Send it` 点击**只表示赠送意图**，赠送成功以后端「一次性权益已归属目标好友且事务提交」为准。
- ⚠️ 未定义：取消选人、好友离线 / 已离开广场、权益失效如何处理；可否送给自己（「可以点击自己的 Avatar」与「赠送」关系不清）；同一冰淇淋能否既送人又自己吃（埋点写「自用与赠送互斥」）。

### 5. 数据埋点（2026-10-14 研发测试执行表 · 精简版）
- 正文说明：埋点按 1.41.0 规范的处理方式见另一篇文档《冰淇淋店埋点处理方式（1.41.0）》（`https://wsgh3q8mwfpp.sg.larksuite.com/docx/ExXwd5a7zob6LnxiOwMl0YkIgGh`），**以该文为准**；该文**未入库**。
- 本表为待实施定义，**未创建或发布到生产**。**复用 2 类 H5 预置事件，新增 5 个业务事件**，共 16 项事件属性配置（12 个不同属性名）。
- 删掉的细项：逐顾客订单事件、配方 / 口味 / 容器 / 球数、教学步骤、动画结束状态与中断原因。保留正确完成订单数作为玩法产出，**不据此宣称英语学习效果**。
- 复用既有属性类型：`session_id`、`play_duration_ms`、`correct_count`、`fail_reason`、`reward_giggles`、`giggles_cost`；**不修改全局字典显示名或类型**。**条件必填字段只在指定阶段传，其他阶段省略，不传 null 或空字符串**。

**预置事件复用（内嵌表 bdDU2l）**
| 事件 | 触发与属性 |
|---|---|
| `$pageview` | 首屏真实可见时报一次，H5 路由返回再进可报；重渲染、刷新数据不重复报。`$title`：冰淇淋店首页 / 冰淇淋店打工 / 冰淇淋店购买 |
| `$WebClick` | 真实点击报一次；`$element_name` 只要求 5 个关键控件（见「入口」），口味选择、垃圾桶、返回等不新增。Canvas 控件无法自动采集时由 H5 统一出口补报，**自动与手动二选一** |

**新增 5 个业务事件**
| 事件 | 来源 | 触发 | 属性 |
|---|---|---|---|
| `plaza_icecream_work` 冰淇淋打工 | H5 | 打工页**正式计时开始**、计时结束结算或主动离开本局时；**教学和额度拦截不报**，异常关进程不伪造退出 | `session_id`（每局唯一，再来一局换新）；`work_stage` = `started` / `completed` / `exited`；`play_duration_ms`、`correct_count`（**仅 completed / exited 必填**，started 不传） |
| `plaza_icecream_purchase` 冰淇淋购买 | H5 | 购买页**有效提交**先报 `attempted`；明确拒绝报 `failed`；超时未确认报 `pending`；**成功以金币流水为准，不在此事件报** | `purchase_id`（H5 有效提交时生成、**早于余额校验**，贯穿购买 / 扣款 / 赠送 / 动画，传输重试复用）；`purchase_stage`；`fail_reason`（仅 failed：`insufficient_balance` / `other`） |
| `plaza_icecream_trade` 冰淇淋金币结算 | **后端** | 金币账本**奖励入账或购买扣款事务成功提交后**；失败、待处理、重复回调不报 | `trade_id`（流水唯一）；`trade_type` = `work_reward` / `purchase`；`session_id`（仅 work_reward）；`purchase_id`（仅 purchase）；`reward_giggles`（仅 work_reward，>0 的入账增量）；`giggles_cost`（仅 purchase，实际扣款 >0，**不写死示意价**）。分类：激励 / Giggles奖励 |
| `plaza_icecream_gift` 冰淇淋赠送成功 | **后端** | 一次性权益已归属目标好友且事务成功提交时；取消选人、失败、重试回调不报 | `purchase_id`（同一购买只能成功赠送一次；上报主体 = 赠送者）。**不采目标好友 ID / gift_id / 赠送失败原因** |
| `plaza_icecream_effect` 冰淇淋实际使用 | H5 | 自己吃或收到赠送的冰淇淋动画**首次实际起播**时；点击、发播放指令、通知、旁观、重播不报 | `purchase_id`；`effect_source` = `self_purchase` / `gift`（上报主体 = 实际使用者，旁观者不报） |
- 打工：每局 started 一次，`completed` 与 `exited` **二选一**；断进程缺结束事件单列「无结束记录」，不算主动退出；**额度不足不产生打工局**，不新增 blocked / guide 枚举。
- 购买：同一 `purchase_id` 的 attempted 最多一次；failed / pending 各最多一次；pending 后查明失败可补 failed，最终成功以后端扣款流水确认；**余额不足也保留 attempted → failed**（保证尝试人数分母完整）。
- 金币结算：逐单发放或局末汇总都按真实账本流水报增量；若研发确认已有语义完整的统一金币流水，**优先复用并替代本事件，不双报**（已核对的表情购买事件和泛奖励事件不足以替代）。
- 实际使用：同一 `purchase_id` 只计一次，**自用与赠送互斥**，消息重复送达不重复报。

**测试验收表（内嵌表 wuY6rP）**
| 操作场景 | 应看到的事件与属性 |
|---|---|
| 进入店铺并点 Buy | 首页 `$pageview` 1 次；`$WebClick` 的 `icecream_buy` 1 次；购买页可见再报页面浏览；**没有购买业务事件** |
| 完整玩一局 / 提前离开 | work：started 1 次 + completed 或 exited 1 次，同一 `session_id`；仅结束事件带 Number 型时长与正确数；**教学、额度拦截不创建打工局** |
| 有效购买但余额不足 | 同一 `purchase_id` attempted 1 次、failed 1 次（`insufficient_balance`）；不得有扣款、赠送或动画事件 |
| 购买成功并自己吃 | purchase attempted；后端 `trade_type=purchase` 流水 1 次带真实 `giggles_cost`；起播报 `effect_source=self_purchase` 1 次；不报 gift |
| 购买成功并赠送 | 扣款后后端赠送事务提交报 gift 1 次；好友端真正起播报 `effect_source=gift` 1 次；两事件 `purchase_id` 一致；取消选人或仅收到通知不报 |
| 超时、重试、重复回调 | 超时未确认报 pending（不算失败或成功）；重试沿用购买 ID；扣款按 `trade_id` 去重，赠送与实际使用按 `purchase_id` 去重 |
| 打工奖励 | 每笔成功入账的 `work_reward` 流水带 `session_id` 与 `reward_giggles`；奖励字段与消费字段按类型互斥，数值与账本一致 |

**指标口径**：人数按公共孩子身份去重；参与 = 店首页 UV、打工 started UV、购买 attempted UV；打工完成率 = completed 局数 ÷ started 局数；购买成功按 `trade_type=purchase` 的 `purchase_id` 去重；余额不足人数按 failed + `insufficient_balance` 去重；赠送数按 gift 的 `purchase_id` 去重；好友实际触达以相同 `purchase_id` 的 gift 来源动画为准，未起播标「尚未观测到」不算失败。广场停留与回访复用 `plaza_enter` / `plaza_exit`，按是否用过冰淇淋店分组观察，不能据此推断因果。
