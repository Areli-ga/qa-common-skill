## 摘要

V1.35.0 在 V1.34「路径无奖励」实验组基础上**叠加第二层 AB**(key `homepage_learning_order`):实验组把**按天解锁**改为**按完成单元解锁(一次解两个单元)**,把**任意跳学**改为**单元内必须顺序学、单元间可跳**,并调整新手 Hello 课流程,测解锁规则与学习顺序对**完课深度和留存**的影响。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 0. 实验设计(两层 AB 叠加,回归前提)

- **基线**:基于「路径中没有奖励」的形态 —— **V1.34 key `homepage_reward_giggles` 的实验组**。
- **本期 key**:**`homepage_learning_order`**(V1.35)。
- 即:本实验的两组**都跑在 V1.34 实验组(无扭蛋/宝箱)之上**,再对比解锁方式与学习顺序。
- 测试目标:解锁规则和学习顺序对**完课深度**及**留存**的影响。

### 1. 对照组 vs 实验组总表

| 维度 | 对照组 | 实验组 |
|---|---|---|
| **奖励相关(V1.34,两组共同基线)** | | |
| 路径奖励(核心) | 扭蛋、宝箱 | 去掉扭蛋和宝箱(无单元宝箱,Nexthook 去掉) |
| 普通课程 | 三颗星 + Giggles 发放动画 | 三颗星 + Giggles 发放动画 **+ 奖励中心图标状态变化(Giggles 数额状态)** |
| 单元完成 | 开宝箱服装动画 | 单元结算:保留学习中心面板进度呈现 **+ 勋章结算** |
| **规则(V1.35,本期变量)** | | |
| 解锁规则 | 前一天有学习行为 → **按天解锁**;完成 part 全部内容后可继续解锁 | **一次解锁两个单元**;按完课行为解锁,**完成一个单元解锁后面的单元** |
| 学习顺序 | 可以跳着学习 | **单元内按顺序学**;**已解锁的单元间可以跳着学** |

- **后续计划**(本期不做):等奖励和解锁规则确定后,再测 UI 元素——背景图片、音乐、动画细节(三颗星 vs 一颗星 + 路径勋章动画)、Avatar 引入。

### 2. 新手流程(Hello 课)

**对照组(线上逻辑不变)**
- Hello 完课 → 获得三颗星 → **自动进入第 2 节课**。
- Hello 中途退出未完课 → **可以玩别的课程**。
- Hello 课程**不强制学习完成**(评审后修改的口径)。

**实验组(修改)**
- 首次进入地图:**解锁 Hello 课程 + 前两个单元的内容**。
- Hello 完课 → 获得三颗星 → 自动进入第 2 节课(同对照组)。
- Hello **中途退出未完课** → 可继续选择学习:**第一个单元的第一节课** 或 **第二个单元的第一节课**;
  - 若点击第一个单元内**非第一节课** → **引导定位到该单元内第一节课**。
- **Hello 课当成单独单元处理**,同时算作**第一单元内的课程**:完课获得星星,**必须完成才能获得第一个单元的勋章**。
- ⚠️ 「Hello 当独立单元」与「算第一单元内课程」两种表述并存,勋章归属需实测确认。

### 3. 解锁机制

**对照组(不变)**
- 只要**前一天有学习行为**(完成任意一节课),**次日**解锁新 part 内容。
- 若用户把**前一 part 内容全部完成**,可继续解锁新 part 内容(不必等次日)。

**实验组(修改)**
- **去掉按天解锁**,改为**按完成单元的行为解锁**。
- 首次进入地图:解锁 **Hello + 前两个单元**。
- 完成**已解锁的最后一个单元(第 2 个单元)** → **再解锁两个单元**。
- 解锁动画:**复用线上已有解锁动画资源**(@ray)。
- ⚠️ 原文只写"完成最后一个已解锁单元"触发,**未说明只完成第 1 个单元时是否解锁**;按字面 = 不解锁,需实测。

### 4. 学习顺序

**对照组(不变)**:已解锁的课程可以跳着学。

**实验组(修改)**
- **单元内必须按顺序学,不能跳**:
  - 点击单元内**已解锁未完成的第一节课** → 正常进入学习;
  - 点击单元内**已解锁未完成的非第一节课** → 播放「**课程无法进入反馈动画 + 推荐课程动画**」(不进课)。
- **单元间可以跳着学**:可选第一单元或第二单元的**首节课**开始;**每个已解锁单元的"未完成的第一节课"都有课程引导动画**。
- 点击**未解锁的单元** → 通过动画**引导定位到最新解锁单元的第一节未完成课程**。

### 5. 数据埋点

- 目标数据:**地图定位和解锁顺序**、**完课深度和留存**。
- **触发解锁的埋点分两段**:「完成(触发解锁)」与「真正解锁」分别上报。
- **`status` 属性新增枚举值**:
  - `unlocked` — 已解锁;
  - `locked` — 未解锁;
  - **`isOrderLocked`** — 单元已解锁,但点击的是单元内**不按顺序**、暂不可学的课程。

| 时机 | 事件 | 属性 |
|---|---|---|
| 单元内点非首节课时的**拦截动画曝光** | `unit_lesson_blocked_show` | `unit_index`、`lesson_id`(点击的课程)、`lesson_name`(点击的课程)、`Part_Number` |
| 完成 2 个单元后的**解锁动画开始** | `unlock_2units_animation_start` | `unit_index` |
| 完成 2 个单元后的**解锁动画结束** | `unlock_2units_animation_end` | `unit_index` |
| **单元完成**上报 | `app_unit_complete` | `unit_index`、`pathway` |

- ⚠️ **`app_unit_complete` 是新增事件**:原来"单元完成"是**和开宝箱动作绑定**上报的,实验组路径移除宝箱后原上报失效,故新增独立事件——**测试重点:对照组(有宝箱)与实验组(无宝箱)都要能正确上报单元完成**。
