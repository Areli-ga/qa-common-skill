## 摘要

V1.38.0 围绕「进入奖励中心后的首日购买率从 50% 提到 60%+」做四件事：新人低价套装专属标签 + 全量上新 New 标签、商城两层排序（后台权重 + 用户性别购买偏好）、家具面板自动召回并从右侧改到下侧、新增第二个空间场景（浴室）用 Giggles 解锁。

## 功能信息（逻辑/状态/边界/字段）

### 背景数据与目标

- 首日：单元完成 946 人 → 880 人进奖励中心（弹窗引导效率 93%）→ 437 人消费（购买转化率 50%）；首日有消耗行为的人占比 35%。
- 价格改动前：进入 880 → 购买成功 500（56.81%），5 日内 60%；价格改动后：进入 938 → 购买成功 577（61.51%），5 日内 64%。
- 消费人数后续下降快，第 4 天和第 6 天尤其明显（缺持续复购内容）。
- 首日家具面板曝光人数只有服装购买的一半 → 家具购买功能曝光不足。
- 老用户 Giggles 缺消耗场景 → 新增解锁空间。
- Giggles 余额分布（总人数 10,286，人均 496.87，见 img-11）：<100 占 54.84%（5,641 人）、100~500 占 27.1%（2,787）、500~1000 占 7.98%（821）、1000~2000 占 5.44%（560）、2000~5000 占 3.6%（370）、5000~10000 占 0.72%（74）、≥10000 占 0.32%（33）。**即弱提示档（500~1000）约 8%、强提示档（≥1000）约 10%**。
- 目标：① 首日购买率 50% → 60%+；② 按性别偏好提升有效展示率；③ 提升家具面板曝光；④ 新增空间场景解锁。

### 1. 新用户限时优惠引导（Unity 弹窗）

- 首次引导购买弹窗的插画改为展示**宇航服 + 粉色公主裙**（商城中卖得最好的两款）。
- 任务体系实验组因引导冲突已在 **V1.37 去掉该弹窗**，本篇仅描述现状（对照组有弹窗、实验组没有）。
- ⚠️ 评审提到该弹窗可能是 **Unity 弹窗而非 H5**，任务已从 Unity 的 Joey 转给杰克。

### 2. 新用户低价引流套装曝光

- Admin 后台在**现有枚举中新增「新人套装」标签类型**（后端加枚举，按文字匹配「新人套装」识别），配置入口在「编辑商城套装」弹窗的**标签**字段（img-04）。
- 曝光对象：**未购买任何商品**的用户。
- 位置：排在套装列表**最前方**；若多个套装都带新人标签，标签组内部仍走下方的排序规则。
- 样式：新人套装有**专属标签样式** —— 设计稿为套装卡片右上角的**绿色「%」折扣角标**（img-05），新人套装单品价 20 Giggles，普通套装单品 299/499/599/799 Giggles。
- 消失条件：**购买任意一件商品后该标签消失**。
- ⚠️ 思维导图（img-03）里「重新进也会有这个标签么？什么时候这个标签会去掉？」被高亮为待答问题，旁注结论是「购买后消失」。

### 3. 全量用户「New」上新标签

- 对**全量用户**展示；触发点为套装**首次给用户曝光**时开始计时。
- Admin 配置标签展示时长，**默认值 = 套装上线之后 7 天**，不限制最大配置时长。
- 套装**下架后重新上线，时间重新计算**。
- 样式：套装卡片顶部红色 `New!` 文案（img-06）。
- ⚠️ 口径冲突：正文/任务写「默认 7 天」；会议纪要写「首次浏览后展示**三天**，若按用户曝光实现复杂，可通过后台配置展示七天，默认值为七天」。

### 4. 排序优化（分性别优先曝光）

两层排序：

1. **第一层**：后台排序权重（Admin 手动配置的排序值）。
2. **第二层**：用户购买的性别属性偏好 —— 针对**购买超过两次及以上**的用户，取**过去一周**其购买商品的性别标签占比；女性属性买得多则优先展示女性套装。

- 数据字段：**套装维度新增性别字段 男/女/中性**（img-07 红框标注新增「性别」在编辑套装弹窗内）；产品在上线时补齐存量套装的性别数据。
- **不做服装与套装性别不一致的拦截**（评审明确）。
- 套装色系展示规则：取套装图片中**颜色最多的**颜色。
- 后台排序交互改造：套装列表**新增预览图**、支持**直接拖拽上下调整排序**（替代原先的复杂计算），拖拽结果同步到 App 家园端展示顺序，并作为性别权重筛选的基础依据。
- 后台位置：`admin-ga.toolsapple.net/reward-center/wardrobe-shop`「服装商城套装」列表，现有列 编码 / 名称 / 获取方式 / 标签 / 物品数 / 排序 / 状态 / 操作（编辑·下架·删除），共 12 条；获取方式枚举含「购买」「同桌配对」（img-08）。
- 编辑弹窗约束（img-07）：每个类目至多一件；「购买」套装上线时要求所选物品**均已上线且已配置售价**；类目含 上衣 / 单元勋章隐藏类目 / 下装 / 鞋子 / 眼镜 / 帽子。

### 5. 家具面板引导与改版

- 引导时机：用户**已购买过服装**后，**再次进入奖励中心**时**自动打开**家具面板。
- 入口动效（img-09）：家具入口图标 200ms → 1500ms → 闪光高亮 → 家居面板自动打开。
- 布局改版：家具面板**从右侧改到下侧**；场景缩放 **0.9x（原右侧面板）→ 0.7x（下侧面板）**（img-09 / img-10）。
- 面板内容：左侧竖向 tab（衣柜 / 奖杯），第二格为贴纸与家具缩略分类，家具带价格（20/50/100 Giggles）。
- 贴纸处理：**老用户的贴纸资产保留**，与主题一起下拉展示；主题增多时采用**两排下滑**展示，同步调整区域高度。
- ⚠️ 仅见于会议纪要、正文未写：家居面板**装饰编辑模式下顶部按钮隐藏**；**垃圾桶从左下角挪到右上角**（img-09 中垃圾桶仍在左下角）。

### 6. 新增空间场景拓展（浴室）

解锁门槛与提示分档：

| 用户 Giggles | 提示形态 | 行为 |
|---|---|---|
| >500 | 弱提示：右下角小标签 | 点击标签唤起弹窗 |
| >1000 | 强提示：直接弹窗 | 引导解锁新空间 |

- 关闭解锁弹窗后**保留右下角小标签**，点击可重新唤起解锁。
- 解锁弹窗（img-12）：标题 `New Space Unlocked!`，卖点两条 `Unlock 12 exclusive furniture items & floors`、`Keep permanently & switch back anytime`；主按钮 `Unlock Now ⓖ1000`，次按钮 `Not Now`。
- 解锁成功后：**标签消失** → 播放新空间解锁动画 → 新空间自带**默认几件家具**。
- 解锁后自动平移动画（img-12，仅首次播放）：弹窗 0.2s 淡出，HUD 固定；场景向左平移至右侧新空间，落位轻微回弹；首次到达时半透明手势左右滑动示范一次。时长：平移 0.9s + 引导 0.8s ≈ 1.9s，**不循环**。音效：平移柔「呼」声，落位清脆「叮」。TTS：`Your new space is ready! Swipe to explore.`
- 关闭弹窗后画面右下角显示入口按钮 `Unlock New Space!`（带光线滑动动画）。
- 首次进入新空间的左右滑动引导（img-14）：触发条件为**首次解锁并进入新空间后，仅引导一次**；半透明手指向左滑动、画面小幅跟随并露出相邻空间边缘，回原位后再向右示范一次；**循环播放，用户触摸或滑动后立即停止**；约 3s/次；首次播放轻柔滑动声、后续循环静音；TTS（可选）「左右滑动，看看你的不同空间吧！」
- Giggles 不足（img-13）：触发条件为**余额不足时点击「立即解锁」**；解锁按钮轻晃一次、原弹窗淡出、不足提示弹窗从中心轻弹出现，Giggles 图标小幅下落，学习按钮轻微放大回弹；时长约 0.8s；音效为轻短提示音（避免失败警报感）；TTS（可选）「Giggles还不够，完成学习就能获得更多哦！」。设计稿弹窗为：标题「Giggles 不足」、副文案「先去学习课程赚取 Giggles 吧」、按钮「稍后再说」「现在就去」。
- ⚠️ 形态冲突：正文写的是 **toast**，文案「Giggels不足，去学习」；设计稿是**双按钮弹窗**，文案不同。
- 探索项（效果达标才上线，否则移除）：点击空位置，人物移动到目标位置。

数据结构（img-15）：

- Admin「家具配置」新增 **空间场景** 维度，层级为 **空间场景 → 家具主题 → 家具物品**；新建主题时必须选择空间场景。
- 后台位置：奖励中心 → 家具配置，tab 为 家具物品 / 家具主题 / **空间场景**（新增）；家具主题列表列为 编码 / **空间场景**（新增列）/ 名称 / 摆放区（FLOOR）/ 排序 / 状态 / 操作，现有主题 001 基础、002 粉色公主、003 未来科技。
- 老数据处理：上线后由产品在后台把现有主题配置为「起居室」。
- 当前空间场景：**起居室**（存量）+ **浴室**（新增）。

C 端行为：

- 滑动定位**只能停在特定空间场景中，不能停留在两个场景中间**（正文注明「评审讲的有改动」）。
- 切换空间场景后，只展示**该场景下的主题与家具物品**。
- 浴室也可更换墙纸地板，该家具物品**与浴室场景下的主题绑定**。
- 滑动与拖动家具易冲突，**新增引导箭头**。
- **从某个空间退出，下次进入回到对应空间**；**串门进入的依然是起居室**。
- 切到浴室时 Avatar 出现在浴室：前端识别**空白区域最大的中心位置**；用户移动过后**记住位置**，下次进入停留在该位置。
- 家具在空间之间**互通**（评审）；新空间图片写死。
- 背景可类似家园换背景，但实现方式待后续讨论。

### ⚠️ 待确认（写用例前需拉齐）

1. **New 标签展示时长口径冲突**：正文/任务「默认 7 天」vs 会议纪要「首次浏览后 3 天，实现复杂则改后台配置 7 天」。
2. **Giggles 不足提示形态与文案冲突**：正文是 toast「Giggels不足，去学习」，设计稿是双按钮弹窗「Giggles 不足 / 先去学习课程赚取 Giggles 吧 / 稍后再说 / 现在就去」。

4. **解锁扣费口径**：设计稿按钮写 `ⓖ1000`，正文只写「Giggles 数量大于 1000 弹窗提示解锁」，未写明扣费金额与扣费后余额校验；埋点有 `giggles_cost` 说明会扣费。
5. **两段引导动画是否串联**：img-12 的解锁后自动平移「不循环、约 1.9s」与 img-14 的首次进入左右滑动引导「循环、约 3s/次、触摸即停」是先后播放还是二选一，正文未写。
6. **滑动定位是否吸附到整屏**：正文写「不能停留在两个场景中间」并注明「评审讲的有改动」；会议纪要说主题/场景两个筛选维度还需取舍、确定后群里同步 —— 结论未定。

10. **家具主题老数据兜底**：若产品上线后未把现有主题配成「起居室」，C 端展示如何兜底。
11. **购买成功事件名待研发确认**（埋点表原文标注）。
12. **奖杯已获取/未获取是否分区展示**：正文只给了两组各自的排序，未写两组之间的展示关系。
13. **垃圾桶移到右上角、编辑模式隐藏顶部按钮是否本期做**：仅见于会议纪要，正文与设计稿（img-09 垃圾桶仍在左下角）未同步。
