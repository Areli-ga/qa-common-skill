## 摘要

V1.37.0 优化 V1.35 上线的小麦唤醒仪式 —— 实测 **start→woke 通过率两天都卡在 ~65%**，本期把原本的两步合并成「进场即打鼾 + 点击触发打哈欠动画 + 循环递进语音提示 + Combo 连击」的游戏化流程，并新增 **ASR 解析「Hi」累计 3 次的小音量兜底唤醒**，目标把通过率从 **65% 提到 85%**。

### 1. 需求背景（V1.35 上线后的实测数据）

依据《07/25 V1.35.0 新功能上线两日数据总结（07/25–26）》：

| 观察 | 数据 |
|---|---|
| 破冰仪式**见效但不明显** | `main_chat` **0 轮率**两天压在同期基线下方 —— 07/25 **23.6%（-2.5pp）**、07/26 **24.8%（-1.2pp）** |
| **唤醒仪式卡在「唤醒」这一步** | 两天 **start→woke 都是 ~65%** |

其他已知问题：
- **iOS 上小麦会被自己吵醒**：声音调到最大的情况下，**会被吹口哨的声音吵醒**。
- **iOS BUG（已验证）**：偶现**麦克风输入指示灯亮、有声音输入，但音量输入进度条无反应**。

分析结论：
- 唤醒仪式存在卡点，需要提供**更有趣的、可执行的**交互方式。
- 现在破冰仪式的规则**过于简单，不能兼容广泛的用户场景**。

### 2. 产品目标

- 原则：以**降低 0 轮率**和**游戏化破冰**为总目标；**好玩、简单可执行**。
- 量化：**总通过率从 65% 提高到 85%**。

### 3. 功能描述

**① 合并前两步：进入唤醒仪式后**
- **小麦直接开始打鼾**；
- 同步播放语音提示：**「小麦睡得好香呢，我们大声的喊小麦起床吧！」**

**② 用户点击小麦后**
- 触发**打哈欠动画 + 哈欠 🥱 音效**（**降低分贝，避免自己把自己吵醒**）。
- 动画播放完毕后，触发语音文本 + 语音提示，原则：**确保音文一致**。
- 文案序列：

| 阶段 | 文案 |
|---|---|
| 初始化 | 小麦睡得好香呢，我们一起喊小麦起床吧！ |
| 连续点击循环 1 | 跟我一起喊：「起床啦！」（原文注：**需要调研是不是可以模仿出「起床啦」的效果**） |
| 连续点击循环 2 | 声音不够大哦，再用力大声点！ |
| 连续点击循环 3 | 再来一次！马上就醒了！ |
| 连续点击循环 4 | 叫你的爸爸妈妈一起来喊醒小麦吧！ |

- **播放以上文本时闭麦。**
- **可连续触发**打哈欠的动画和音效。
- 语音提示播放过程中，**打哈欠的音效降低分贝**。
- **不支持连续触发语音提示** —— 上一条语音提示播放完之后，才开启下一个语音提示的播放窗口。
- 点击出现 **Combo 连击**。

**③ 唤起规则修改**
- 仍旧**防止点击的瞬间高脉冲误唤醒小麦**；标准：**不允许达到阈值**。
- 需要被排除（不得触发唤醒）的行为：
  - 用户**点击屏幕**；
  - **小麦自己的声音**（打鼾的音频，**删除吹口哨**）。
- 判断用户语音输入：**输入高脉冲（达到阈值，但没有达到 0.1S）**之后，给出循环的语音提示：
  - 声音不够大哦，再用力大声点！
  - 再来一次！马上就醒了！
  - 叫你的爸爸妈妈一起来喊醒小麦吧！
- **兜底策略（目的是让小音量也可以唤醒小麦）**：
  - 系统执行 **ASR**，解析用户每次输入的音频；
  - **当解析结果为「Hi」累计达 3 次的时候，唤醒小麦。**

**④ 入口优化**
- 结合**小麦的每日打卡仪式**，**右下角的入口显示优化，变为动态的睡觉方案**。
- 🔗 「每日打卡仪式 / 作息」详见同版本《小麦的作息陪伴 + 话术承接 + 冻结解救》。

### 4. 待确认项

1. **全篇无数据埋点**：唯一量化目标是「通过率 65% → 85%」，但没有新增任何事件 —— start→woke 只能沿用 V1.35 的 `ritual_start` / `ritual_woke`（而那篇的**埋点是否统一加 `mai_` 前缀至今未定**）；本期新增的 **Combo 连击、循环文案播到第几条、ASR「Hi」兜底触发、点击次数分布**全部无法量化。
2. **「模仿出『起床啦』的效果」原文写的是「需要调研」** —— 本期是否交付这条文案 / 用什么方式实现（TTS 还是录音）未定。
3. **阈值口径不清**：「达到阈值，**没有达到 0.1S**」是**新增了时长门槛**还是沿用旧阈值？与 V1.35《新用户破冰仪式》的 **RMS 0.15–0.18**、《语音识别-音量阈值设定》的 **Speech 15 / Very Loud 70** 是什么关系需对齐（三篇同一阈值三种量纲的老问题）。
4. **ASR 兜底「Hi 累计 3 次」细节全缺**：累计范围（本次会话内 / 跨会话 / 是否超时清零）、**大小写与近似音**（hai / hey / 嗨 / 你好）是否算、用哪个引擎（V1.36 已把 ASR 打分切自研）、**ASR 调用是否计入电量**（V1.36 电量系统里学习环节不计费，破冰是否属于学习环节）均未说明。
5. **两个 iOS 问题只解决了一个**：「小麦被自己吵醒」对应「删除吹口哨」；**「麦克风指示灯亮但音量进度条无反应」（已验证的 BUG）本期是否修**没写。
6. **狂点时的动画/音效队列策略未定义**：「可连续触发打哈欠动画和音效」与「不支持连续触发语音提示」并存，用户快速连点时动画是叠加、排队还是丢弃？Combo 连击的计数与断连规则也无定义。
7. **闭麦与「大声喊」的体验冲突**：播放提示文本期间闭麦，用户此时喊话会被丢弃；是否有提前收音 / 提示结束的视觉信号未说明。
8. **「右下角入口变为动态的睡觉方案」只有一句**，无界面描述、无状态定义（本篇**无图**），需配合作息篇确认。
9. **通过率 85% 的验收方式未写**（观察窗口、对照口径），且本篇**无验收标准章节**。
