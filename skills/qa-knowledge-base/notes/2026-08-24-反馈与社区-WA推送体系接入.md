## 摘要

V1.37.0 把 WhatsApp 从「只导流进群」推进到**双向推送体系**：游客模式新增【联系我们】入口（带家长验证）、APP 与 WA 用户 ID 按 KIDID 绑定、用户回「我是家长」后进入**按首次互动 +18h 累计的 4 轮推送节奏**（按当天有无完课走两套钩子文案），并**实测了 13 个 App Scheme 外链唤起结果**（走 `unity/customsendmessage` 的入口仍只能落主路径、练习册 QA 白屏）。

> ⚠️ **原料补抓说明**：本篇有 **6 个内嵌 Sheet（`block_type=30`）**，fetch.py 抓不到，其中装着**打标签字段表、10 层数据统计漏斗、10 个新增埋点定义、3 张埋点字段表**。已用 `sheets/v2` API 补抓（code=0）落 `raw/WA推送体系接入/sheets.json`，`meta.json` 补 `embedded_sheets` 字段。`tables: 3` 只算正文表格。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 1. 游客模式新增【联系我们】入口

- 位置：游客的**菜单页**（登录 / 注册页）新增入口（图 1/3 红框，在「Complete Our Survey」banner 右侧）。
- **点击按钮要加一个家长验证**。
- Admin 新增枚举值：可配置一个**特有的链接 `whatsappbusiness`**，走 **WA 商业账号链接** `https://whatsappbusiness`（原文即此占位写法）。
- 埋点：

| 事件 | 触发 | 属性 |
|---|---|---|
| `guest_contact_us_show` | 游客状态下，联系我们按钮曝光 | — |
| `guest_contact_us_click` | 游客状态下，联系我们按钮点击 | — |

| `parent_contact_click` | 页面中点击不同的子渠道 | `contact_channel`：`wechat` / `whatsapp` / `feedback` / `business_email`；`source` 同上 |

### 2. WA 消息推送

**绑定与入口**
- 用户在 **APP 和 WA 的用户 ID 绑定**，根据 **KIDID** 发送互动消息。
- 两个钩子入口话术（从 APP 入口跳转到 WA 自带的固定话术）：**「我是家长」**、**「我想加入家长社群接受孩子报告」**。
- 实际链接授权话术（图 7）：`I authorize Giggle to link my WhatsApp account and send me messages via WhatsApp. Account: <邮箱>. Verification code: GIGGLE-XXXXXXXXXX`。

**WA 首轮自动回复（4 条，印尼语为准，「英语基于印尼语」）**

| # | 内容 |
|---|---|
| 1 | `Halo 👋 Selamat datang di komunitas Giggle Academy! 🎉` / `Di sini ada beberapa cara untuk tetap terhubung dengan kami:` / `Silakan pilih yang paling sesuai untuk Anda 😊` |
| 2 | **【群链接】** + `📢 Ikuti Channel kami untuk mendapatkan update, tips parenting, dan informasi terbaru dari Giggle Academy.` |
| 3 | **【channel链接】** + `👨‍👩‍👧‍👦 Gabung ke grup WhatsApp untuk berinteraksi dan berbagi pengalaman dengan orang tua lainnya.` |
| 4 | 想要通过学习报告了解到孩子的学习情况吗？**回复 1，接受孩子学习报告** |
| 尾 | `Reply STOP anytime to stop receiving these messages.` / `Balas STOP kapan saja untuk berhenti menerima pesan ini.` |

- ⚠️ 第 2 条挂【群链接】却配 **Channel** 文案、第 3 条挂【channel链接】却配 **群** 文案，**疑似串位**。
- 用户回复后，WA 回「孩子每天的学习情况，我们将通知你」→ 推送**【孩子当天的报告链接】**，点击跳转到 APP 中报告 H5 页面。

**推送节奏（按首次互动后 18h 累计，非自然日）**

| 轮次 | 分支 | 文案 / 选项 |
|---|---|---|
| 首次互动 **18h** 后 | **有完课** | 单个孩子：「【宝贝昵称】在 Giggle Academy 完成了【3】节课，开口了【5】次。想要听一听孩子英文说的怎么样吗？」；**多个孩子取聚合数据**：「孩子们在 Giggle Academy 完成了【3】节课，开口了【5】次。」+「回复 1，查看详细的学习报告」 |
| 首次互动 **18h** 后 | **无完课** | 「今天计划学习的【单元名称】孩子不喜欢吗？还没有开始学习。没关系，让我给你介绍更多功能？」+ 回复 1 **自然拼读** / 回复 2 **AI 对话课** / 回复 3 **把今天的学习计划推送给你** |
| **day2 互动后再 18h** | 有完课 | 同「有完课」报告钩子 |
| **day2 互动后再 18h** | 无完课 | 同话术，选项换成 回复 1 **绘本故事** / 回复 2 **歌曲** / 回复 3 学习计划 |
| **day3 互动后再 18h** | 有完课 | 同「有完课」报告钩子 |
| **day4 互动后再 18h** | 无完课 | 同话术，选项换成 回复 1 **闪卡** / 回复 2 **绘画** / 回复 3 学习计划 |

- ⚠️ **轮次表不对称**：day3 只写了「有完课」分支，day4 只写了「无完课」分支（原文顺序为 day2 有 / day2 无 / day3 有 / day4 无），疑漏 day3 无完课与 day4 有完课两格。
- 用户按要求回复后：
  - 报告分支 → 推**【报告链接】**，点击跳转到 APP 并打开报告页面，**不需要家长验证即可查看**。
  - 功能分支 → 按用户回复的选项**推送不同的 APP 功能页面链接**，点击可跳转到 APP 并打开对应功能页面。

**WA 用户打标签（手动筛选用户标签）**
- 用户在 APP 和 WA 的用户 ID 绑定，根据 KIDID 发送互动消息，把以下标签同步到 WA（内嵌 Sheet `PLOb5w`）：

| 字段 | 说明 |
|---|---|
| User ID | 唯一 ID |
| Country | 国家 |
| Language | 语言 |

### 3. 数据统计（10 层漏斗，内嵌 Sheet `KY8uPO`）

| 层级 | 关键动作 | 统计维度 / 注意点 |
|---|---|---|
| ① 入口曝光/点击 | 游客/家长看到联系我们入口 | `guest_contact_us_show|click`、`parent_contact_show|click` 已有埋点，按 `source` 拆 |
| ② 渠道选择 | 点击 WA 子渠道 | `parent_contact_click` 的 `contact_channel=whatsapp` 占比（vs wechat/email） |
| ③ 加好友转化 | 跳转 WA 后是否真的发起对话 | 需新增 WA 对话发起率；**这一步流失只有 Meta/WA Business API 能看到，APP 侧埋点看不到** |
| ④ 绑定成功 | 回复「我是家长」→ KIDID 绑定 | 绑定率 = `wa_kid_binding_success` / `wa_kid_binding_start` |
| ⑤ 24 小时窗口内送达 | WA 平台层 message status | sent → delivered → read，**必须从 WA Business API webhook 拿，不是 APP 埋点能覆盖的** |
| ⑥ 首条钩子回复 | 「回复 1 接受报告」 | 回复率 = 回复数 / 送达数，**最核心的触达效率指标** |
| ⑦ 分支选择分布 | 完课分支 vs 未完课分支 | 未完课分支里回复 1/2/3 的选择分布，看哪个钩子最吸引人 |
| ⑧ 深链跳转 | 点击报告链接 / 功能链接 | 跳转成功率（**H5 / Unity / Flutter 三种技术栈可能分别失败**）、跳转 → 到达目标页曝光 |
| ⑨ 轮次留存 | Day1→2→3→4 | 每轮还愿意互动的用户占比（**疲劳曲线**，「三天测试」最该看的曲线） |
| ⑩ 退出 | 回复 STOP | 每轮退订率，**既是效率指标也是合规红线** |

### 4. 数据埋点（新增 10 个，内嵌 Sheet `jKRoyC`，编号 5–14）

| # | 事件名 | 模块 | 触发时机 | 触发端 |
|---|---|---|---|---|
| 5 | `wa_kid_binding_start` | 绑定 | WA 收到「我是家长」话术，开始绑定 | 服务端 |
| 6 | `wa_kid_binding_success` | 绑定 | user_id / kid_id 与 WA 号码绑定成功 | 服务端 |
| 7 | `wa_kid_binding_fail` | 绑定 | 绑定失败 | 服务端 |
| 8 | `wa_push_send` | 推送与回复 | 推送服务向 BSP 发起单条消息发送请求（代表「我们尝试发了」，**不代表送达**） | 服务端 |
| 9 | `wa_reply_option_select` | 推送与回复 | 解析到用户回复并匹配到预期枚举选项 | 服务端 |
| 10 | `wa_unsubscribe` | 推送与回复 | 用户回复 STOP 退订 | 服务端 |
| 11 | `deeplink_redirect_page_view` | 深链跳转 | 从外部链接打开 APP | 客户端（H5），属性 `channel` |
| 12 | `deeplink_scheme_launch_attempt` | 深链跳转 | 中间页执行 scheme 跳转尝试 | 客户端（H5） |
| 13 | `deeplink_open_result` | 深链跳转 | 跳转尝试后**启发式判定**成功 / 超时 | 客户端（H5） |
| 14 | `deeplink_landing_page_view` | 深链跳转 | APP 内目标落地页曝光（**三端统一**） | Unity / H5 / Flutter |

**字段定义**

- `wa_push_send`（Sheet `aVSPn6`）：
  - `push_message_id` string 必填 —— 取 **BSP 同步返回的消息 ID，用于跟 BSP Webhook 表 join**
  - `push_round` string 必填 —— `first_18h` / `day2_18h` / `day3_18h` / `day4_18h`（**按首次互动后 18h 累计，非自然日**）
  - `branch_type` string 必填 —— `completed` / `not_completed`
  - `send_result` string 必填 —— `success` / `fail`（**BSP 同步返回的发送请求结果，非送达结果**）
- `wa_reply_option_select`（Sheet `sgnX5m`）：`push_message_id` / `push_round` / `branch_type` / `reply_option`（选项 1/2/3）
- `wa_unsubscribe`（Sheet `TcSFbL`）：`push_round` **可选** —— 退订发生在第几轮之后；**若未进入推送节奏前就退订可为空**

### 5. 支持跳转的链接（本期实测，@shengling @stephen @Dong）

- 链接格式：`https://<域名>/open-app?giggleScheme=giggleacademy://<路径>`；QA 域 `qakjukl.net`，正式域 `giggleacademy.com`（**正式链接上带 channel**）。
- **每次跳转都有中间页**（图 10：落地页含视频 + 「点击下载」+ **「在 APP 上玩」**按钮 + 「下载 Android 安装包」）。
- 下面的页面**有不同的技术栈实现**（Unity / H5 / Flutter），因此逐个实测：

| 入口 | Scheme（路径部分） | 实测结果 | 备注 |
|---|---|---|---|
| 主页面 | `unity/game_home` | 通 | **和冷启动一样，支持定位到具体的地图推荐课程** |
| 小 Mai | `h5/honor-wall?url=<域>/ai-tutor#mai-chat?sceneId=815522012588933&mainLandSceneId=800694733102341` | 通 | — |
| 绘本故事 | `unity/storybook_home` | 通 | — |
| 闪卡 | QA：`h5/flashcard?url=<域>/ai-tutor/#/flashcard?type=new`；正式：`unity/customsendmessage?...paramValue=Flashcard` | **QA 打开就到闪卡内了（返回到主路径）；正式打开的是主路径** | 两环境用了不同 scheme |
| 专题课 | `unity/customsendmessage?objName=TopBar_New(Clone)&methonName=OnToolboxItemAction&paramValue=MiniPlan` | **打开是主路径** | 原文「尽量支持，如果不行放下个迭代也要支持」 |
| 自然拼读 | 同上 `paramValue=Phonics` | **打开是主路径** | 同上「尽量支持」 |
| 磨耳朵 | `flutter/giggleCastList?unityLevel=3` | 通 | — |
| 同桌 | `h5/ai-tutor?url=<域>/ai-tutor/#/deskmate` | 通 | — |
| 绘画 | 同上 `paramValue=Art` | **打开的主路径** | — |
| 歌曲 | 同上 `paramValue=Songs` | **打开的主路径** | 原文「尽量支持」 |
| 练习册 | `h5/honor-wall?url=<域>/ai-tutor/#/worksheets&backType=back` | **QA 白屏** | — |
| 口语 | 同上 `paramValue=Speaking` | **打开的主路径** | 原文「**可以暂时不处理**」 |
| 排行榜 | `h5/honor-wall?url=<域>/ai-tutor/#/leaderboard?type=board&closeCallbackLink=giggleacademy://unity/leaderBoardClose&bgColor=%23FFECB2&backType=back` | 通 | — |
| 家长中心-学习报告 | QA：`h5/parent-center?url=<域>/ai-tutor/#/learned-lessons`；正式：`.../#/weekly-learning-report` | 通 | ⚠️ **QA 与正式目标页不同**（与 V1.35 WA 篇同一遗留问题） |

- **结论**：走 `unity/customsendmessage` 的入口（专题课 / 自然拼读 / 绘画 / 歌曲 / 口语 + 正式环境的闪卡）**全部只能落到主路径**；练习册 QA 白屏。这与 V1.35《whatsapp 加好友发送消息链路》的实测结论一致，**本期仍未修复**。

### 6. 待确认项

1. **首轮第 2/3 条消息链接与文案串位**：【群链接】配 Channel 文案、【channel链接】配群文案。
2. **推送轮次表不对称**：day3 只有「有完课」分支、day4 只有「无完课」分支，疑漏两格；且 day4 之后是否停止推送未写。
3. **多语言范围**：只给了印尼语原文 + 「英语基于印尼语」，中文及其他市场文案是否要做未说明。
4. **WA 24 小时客服窗口**：18h 推送节奏与 WA Business API 的 24h 会话窗口如何配合（超窗必须用模板消息、且需审核）文档完全没提，这是能否发出去的硬约束。
5. **BSP Webhook 本期是否接**：`wa_push_send` 的 `send_result` 只记同步返回结果，送达 / 已读（漏斗第 ⑤ 层）必须靠 Webhook，本期范围未定。
6. **深链缺口的处置**：`customsendmessage` 系 6 个入口只落主路径、练习册白屏 —— 哪些本期必修、哪些放下个迭代需产品拍板（原文对专题课/自然拼读/歌曲写「尽量支持」，对口语写「可以暂时不处理」）。
7. **家长中心学习报告 QA 与正式目标页不同**（`learned-lessons` vs `weekly-learning-report`），哪个是目标页。
8. **家长验证口径冲突**：游客联系我们入口要「加一个家长验证」，但 WA 报告链接跳转 APP「**不需要家长验证即可查看**」，需确认是否有隐私/安全风险。
9. **打标签只有 4 个字段 + 「手动筛选」**：标签体系、同步时机、同步失败与更新机制均无定义。
10. **Admin 新增枚举 `whatsappbusiness` 的链接写成 `https://whatsappbusiness`**，是占位符，真实商业账号链接待补。
11. **闪卡两环境用了不同 scheme**（QA 走 `h5/flashcard`、正式走 `customsendmessage`），是否统一为 h5 方案未定 —— 这直接决定「能不能直达闪卡」。
