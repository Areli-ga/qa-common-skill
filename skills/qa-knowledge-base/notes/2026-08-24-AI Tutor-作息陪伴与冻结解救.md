## 摘要

V1.37.0 给小麦装上**跟随用户宗教/自然作息的生命节律**：按 `rhythm_mode`（`sun_based` / `prayer_based`）决定小麦何时睡醒、首页透出睡醒动画、主对话背景跟当地日升日落走；用户进入时走**七级承接矩阵（P1 冻结解救 → P7 常规进入，命中即停）**；用户不来则**逐日渐冻（Day1–6）→ 冰雕（Day7+）**，回来要用**锤子敲击 combo × 不活跃天数**解救；承接完成后**≤2 轮内必须导向 word play**。

### 1. 需求背景

- 小麦主推印尼市场：**印尼语言用户占小麦总用户 80%–90%**；印尼穆斯林人口占比约 **86%–87%**（全球穆斯林人口最多的国家）。
- 宗教用户有每天固定的生活节拍（**五次礼拜**）；用户调研发现**深度用户会主动跟小麦聊仪式中、聊和宗教相关的事情**。
- **小孩子礼拜很容易开小差。**
- 期望：小麦融入不同民族、不同宗教信仰用户的生活，跟随其习惯与节奏，快速找到最合适的话题，建立更深情感连接，以此提升留存。

### 2. 目标、原则

- **目标（主指标 = `prayer_based` 组）**：prayer_based 用户获得跟随宗教时间的仪式感，其**次日 / 7 日留存与日均会话数**较上线前基线显著提升：**+10 个 / 3 个百分点**。
- 原则：
  1. **目标群体优先**：本模块服务全平台约 80% 的印尼穆斯林用户；体验、资源或规则冲突时**优先满足目标群体**。
  2. **包容性强**：包容全球不同地区、不同宗教信仰的用户。
  3. **绝对不挑战、不违背用户的宗教理念**，符合各自宗教文化价值观。
  4. **小麦从来不会拒绝用户**：睡觉状态**不构成使用门槛**，任何时刻进来都被好好承接。
  5. **学习优先**：任何话题完成后，快速引导至 word play / game play。

### 4. 环节⓪ 作息模式 `rhythm_mode` 与首页透出（8.1）

**状态判定**

| 逻辑状态 | 判定 | 小麦作息 |
|---|---|---|
| **默认初始状态** | 新用户，未探测出 rhythm_mode | **`sun_based`**：日出醒来；**20:00 入睡** |
| **穆斯林** | 宗教生活信号命中（见打标 ③） | **`prayer_based`**：**Fajr 开始醒来；Isha 结束后入睡** |
| **非穆斯林** | 用户明确拒绝 / 表达自己不属于穆斯林群体 | **`sun_based`**：日出醒来；20:00 入睡 |

- **礼拜时刻表来源**：**Kemenag 官方口径**（计算法可选 Kemenag / Muhammadiyah，可用 **Aladhan** 等成熟服务）、**城市级 IP 定位（不请求 GPS）**、**每日拉取 + 7 天缓存**；取不到 → 用缓存；**缓存过期 → 退化 `sun_based`**。
- ⚠️ **礼拜时间零容忍：报错一次 = 瞬间失信，视为不敬。**

**落库实现（合规设计）**
- `rhythm_mode ∈ {sun_based, prayer_based}` + `probe_status ∈ {active, done}`
  - 「非穆斯林」= **`sun_based` + `done`**
  - 「穆斯林」= **`prayer_based` + `done`**
  - 「待确认」= **`sun_based` + `active`**
- **字段不含宗教词，满足「不存宗教标签」合规线。**

**打标机制（4 步）**

| 步骤 | 机制 | 说明 |
|---|---|---|
| **① 默认** | `sun_based` + `probe_status = active`（待确认），按日出作息表现 | **无需任何采集**，新用户即刻可用 |
| **② 系统引导探测** | **手机系统语言 = 印尼语** → 小麦在话题切入中**主动、直接**询问宗教相关关键词，引导孩子说出判定词汇。探测问题**时机感知**（AI 已知当地日期与时间，按上下文措辞），如「今天你祷告了吗？」「今天和家人一起去清真寺了吗？」。**此项为系统引导，仅适用于印尼语言** | 探测句**嵌入正常话题、保持自然**；**持续探测直到出终态** —— 信号命中 → 穆斯林；**用户明确拒绝 / 表达不属于穆斯林群体 → 标记非穆斯林（`sun_based` + `done`），探测永久停止** |
| **③ 用户主动告知 → 直接打标** | 对话中（含探测回答）出现**宗教生活信号（冻结词表：安拉 / Allah、礼拜 / sholat / 祈祷、清真寺 / masjid、斋月 / puasa、开斋节…）**。打标条件：**第一人称提及自己 / 家人的宗教生活 ≥1 次、跨 ≥1 个自然日（转述他人不计）** → 直接写入 `prayer_based`。**适用所有语言**（如「我是中国人，我信奉安拉」）；**支持用户主动切换**（如「我不再信仰伊斯兰教了！」） | **静默打标**；小麦作息随即切换，后续以 `prayer_based` 节奏沟通 |
| **④ Push 订阅邀请（与打标解耦）** | 已打标 prayer_based 后，在话题自然收尾处邀请：「今晚念完经，要不要小麦提醒你来练 5 分钟英语呀？」→ 同意则拉起系统通知权限弹窗 → 开通**傍晚学习提醒（Maghrib + 60–90 分钟发送，延迟可配置）** | ⚠️ **和 Push 需求一起上线，不在本期范围内** |

- Push 数据依据：**Fajr 时段（4–5 点）30 日仅 1,174 次打开 → 不做 Fajr 推送**；**傍晚 18–20 为全天流量峰 + 双祷告窗（礼拜 + mengaji 后的家庭练习槽），是推送主战场**。邀请只管 Push、不影响标签；同意后写入推送白名单；**拒绝 / 沉默 = 不开推送，7 天冷却后可再邀 1 次**。

### 5. 环节① 醒来 / 环节⑥ 入睡（8.2）

- **前置：新用户需要先完成 onboarding（破冰唤醒 + 姓名采集）**，才进入本状态机。
- 状态：`awake` / `asleep`，按 `rhythm_mode` 与**当地时刻表**切换。
- 首页入口透出：**醒 = 常态动画 + 支持眼球跟随（跟随用户在首页的点击事件）**；**睡 = 动态睡觉动画 + zzz 动画**。
- 入口动态配置：**睡着 / 醒来状态均可叠加冻结皮肤**。
- **入睡时刻到点若用户在会话中，不打断当前会话，退出后再入睡态。**
- **主对话背景严格跟随当地日升日落做主题变换**（Living Sky）。
- 状态机**预留 `calendar_overlay` 接口（斋月 / 节日），v1 不实现**。
- 过渡动画：loading 页面小麦的**睡觉动画升级为「小麦的蠕动」动画**，应用于 **H5 框架加载时** 与 **打开子场景时的加载动画**。

### 6. 环节② 用户进入：承接矩阵 + 轻唤醒（8.3）

**承接矩阵**（按优先级自上而下，**命中即停**；**判级由代码状态机执行，台词由 prompt 生成，示例语仅为语气锚点**）

| 优先级 | 触发条件 | 承接策略与示例语 | 命中比例（当前数据推演） |
|---|---|---|---|
| **P1 冻结解救** | 次日起不活跃（**`freeze_days >= 1`**，小麦为逐渐的冰雕状态） | 进入解救流程（锤子 combo × 不活跃天数）→ 解救台词随天数动态变化（7 日锚点「好久不见，我们的关系都跌到了冰点。谢谢你救了我！」）→ **随后走常规承接（P6–P7）** | freeze 1 天 **9.8%**；2–3 天 **4.0%**；4–6 天 **2.2%**；7 天+ **2.1%** |
| **P2 约定命中** | 存在**未过期的回访约定（revisit）且在时间窗内** | 「哈哈，你真的来啦！你真是一个遵守约定的人！…」→ **直接接约定内容** | / |
| **P3 匆忙折返** | **当日、间隔 < 30 分钟 且 `last_exit = silent`** | 「哼，刚刚不辞而别，干嘛去了呀～」俏皮嗔怪 → 接上次话题 | **共 41.8%**（5 分钟内 23.2%、5–30 分钟 18.6%） |
| **P4 快速回访** | 当日、间隔 < 30 分钟 且 **`last_exit = farewell / button`** | 「咦，这么快又见面啦！」→ **无缝接上次话题** | （并入 P3 区间） |
| **P5 当日重访** | 当日、**间隔 ≥ 30 分钟** | 「你回来啦！」→ 接未完成学习或开新话题 | **14.0%** |
| **P6 日历节点** | **跨天首访**且落在**醒来后首窗 / 入睡前窗** | 晨间问候 / 哄睡向（进入时段矩阵对应行） | / |
| **P7 常规进入** | 以上均未命中 | 按当前时段走时段矩阵 | **26.1%** |

**轻唤醒**
- 用户在小麦睡着的作息时候进入 → 进入唤醒流程。
- **用户点击 combo 十下，或者声音达到阈值时候，唤醒小麦。**
- **区别于新用户的破冰流程**：唤醒流程里对应的文本跟语音提示**恒定为「小麦睡得好香呢!」**。
- **唤醒转场语与承接语融合为一句**（如 P3 + 睡态 → 「啊，被你吵醒了…刚刚不辞而别，现在又来叫醒我呀～」）。
- 转场语锚点：**凌晨被吵醒**「你今天起得好早呀！」；**晚上被吵醒**「啊，你把我吵醒了，你怎么还没睡呀？」。
- **约定过期未命中：静默作废，不提及、不指责。**

### 7. 冻结与解救（8.4，负反馈 combo）

- 做什么：用户不来，小麦被**逐日冻住**（负反馈，表达「关系变冷」）；用户进入时**先处理冻结状态，再进入承接与话题**。**暂时不做正向打卡连击。**

| 阶段 | 触发 | 表现 | 进入时的处理 |
|---|---|---|---|
| **渐冻期 Day 1–6** | 连续不活跃第 1–6 天 | 入口与主对话中的小麦呈**逐日加深的结冰视觉**（睡 / 醒态均可叠加） | 触发解救流程 → 对应 P1 → 随后常规承接（P6–P7） |
| **冰雕 Day 7+** | 连续 7 天不活跃 | **完全冻成冰雕** | 同上 |

**解救流程**
1. 点击冰冻小麦 → **全屏状态**下呈现冻结的小麦（**按 `freeze_days` 程度渲染渐冻 / 冰雕**）+ **锤子工具**。
2. 用户**连续敲击 combo × 不活跃天数**（**渐冻期取不活跃天数，冰雕状态恒定为 7**）敲碎冰层，小麦解冻。
3. **连续的敲击数字并未因为用户常驻而清零；用户退出解救流程的时候清零。**
4. 解救台词随不活跃天数动态变化：
   - **1–3 天**：走当前逻辑。
   - **4–6 天**：「还好你来的早，不然我就冻成冰雕了。」
   - **7 日**：「好久不见，我们的关系都跌到了冰点。谢谢你救了我！」
5. 进入常规承接（接话题 / 学习），**`freeze_days` 清零**。

### 8. 话题切入 → 学习（8.5）

**执行顺序（开发按此实现）**
1. 输出承接语（已由 8.3 判定）。
2. **话题切入**：按时段矩阵选 1 问（**P2 / P3 / P4 命中时跳过此步，直接续接原话题**）。
3. **≤2 轮内引导至 word play（第一优先级），其后 game play。**

**表 A · `prayer_based`**（礼拜时刻锚定；括号内为 WIB 参考时刻，实际按当地礼拜表动态计算）
> **礼拜话题可以在贴近礼拜的时间前后 30 分钟之内进行主动抛出。**

| 时段（礼拜锚点） | 小麦状态 | 话题切入示例 |

| 0:00–Fajr | 熟睡 | 「你这么早起床，在准备做礼拜吗？」/「天还没亮呢，你怎么起这么早呀」 |
| Fajr–日出 | 刚醒 | 「哇，你今天起得好早呀！和家人一起做礼拜了吗？」/「天还没全亮呢，我们小声一点说话～」 |
| 日出–9:00 晨间 | 醒 | 「今天谁叫你起床的呀？」/「早饭吃了什么好吃的？」 |
| 9:00–Dhuhr（~11:30） | 醒 | 「今天上午都做了什么呀？」/「和谁在一起玩？」/「有没有学到什么新东西？」 |
| Dhuhr 后–Asr（~12:00–15:00）**全天流量峰** | 醒 | 「今天有没有发生什么有趣的事情？」/「你吃午饭了吗？」 |
| Asr 后–Maghrib（~15:30–18:00） | 醒 | 「下午过得怎么样呀？」/「和小伙伴玩了什么好玩的？」/「有没有帮家里做什么事呀？」 |
| **Maghrib+60′–Isha（~19:00–19:15）主战场** | 醒 | 「念完经啦？来和小麦练 5 分钟英语吧！」/「今天跟着家人做了什么呀？我们边玩边说～」 |
| Isha 后–00:00 | **已入睡** | 「啊，你把我吵醒了，你怎么还没睡呀？」 |

**表 B · `sun_based`**（固定时钟）

| 时段 | 小麦状态 | 话题切入示例 |
|---|---|---|
| 0:00–日出 | 熟睡 | 「天还没亮呢，你怎么起这么早呀？」 |
| 日出–9:00 | 刚醒 / 醒 | 「昨天晚上做了什么梦？」/「今天谁叫你起床的呀？」/「早饭吃了什么？」 |
| 9:00–12:00 | 醒 | 「今天上午做了什么好玩的？」/「和谁在一起呀？」/「有没有学到什么新东西？」 |

### 9. 约定系统（8.6，最简版：只有「下次见面」一种）

- 做什么：把每一次离开变成下次见面的期待。约定只有一种 —— **道别时和孩子说好「下次什么时候见」**。
- 引入三步（全部发生在道别语境）：① 孩子表达要走（或到点该睡了）→ ② **小麦从对话推断去向**，顺势把重逢时间**说成约定** → ③ **道别的最后一句，从静态变为动态的复述约定（钩子句）**。

| 场景 | 立约对话 | 动态结束语 | 下次进入 · 兑现 |
|---|---|---|---|
| 去上课 | 孩子「我要去上课啦。」→ 小麦「你快去上课吧，等你放学，我们再一起玩！」→ 孩子「好！」 | 「不要忘记我们的约定哦，放学后我们再一起玩！」 | 当天 16:30 进入 → 「你放学啦！我们说好的！快来，我们继续一起玩！」 |
| 临时要走 | 孩子「我先走啦。」→ 小麦「你先去忙，我们等会儿再见！」 | 「说好了哦，等会儿回来找我！」 | 2 小时后进入 → 「哈哈，你真的回来啦！说好的等会儿见～」 |
| 晚安（哄睡段） | 孩子「我要睡觉啦。」→ 小麦「晚安好梦，明天起床后再见！」 | 「我们拉钩啦，明天见！」 | 次日早上进入 → 「早上好呀！说好早上见的，你真的来啦！」 |

- **过期 = 无事发生**：约了「放学见」但第二天才来 → **只字不提这件事**，按其余优先级正常承接（**静默作废，绝不指责**）。
- 规则 4 条：
  1. **单槽**：同一时刻最多 1 个约定；**新约定直接覆盖旧约定**。
  2. **只在道别时立约**：对话式道别**必带**；**按钮退出可带一句轻约定**。
  3. **道别最后一句 = 约定钩子句**。
  4. 兑现只有两种结局：**时间窗内回来 → P2 惊喜承接 + 情感夸奖**；**过期 → 静默作废，此后不再提及**。
