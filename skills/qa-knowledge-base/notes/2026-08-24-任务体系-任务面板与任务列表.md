## 摘要

V1.37.0 新建**任务体系**：首页加任务面板入口，用「任务 → 奖励」引导用户去体验没碰过的核心功能（完成第 1 单元 / 唤醒小麦 / 开消息通知 / 跟读故事书 / 邀请好友），新老用户各跑一层 AB（`homepage_tasks_list` / `homepage_tasks_list_old`，按**游客 id 是否 8 月 21 日前生成**划分），验证「任务体系能否提升核心功能体验率进而提升留存」。

> ⚠️ **原料补抓说明**：本篇正文只有 3880 字符，**核心埋点表与三语文案表全在 3 个内嵌 Sheet（`block_type=30`）里，fetch.py 不抓**。已用 `sheets/v2/spreadsheets/{token}/values/{sheetId}!A1:Z300` 补抓（机器人有权限，code=0），结果落 `raw/任务体系/sheets.json`。`meta.json` 的 `tables: 5` 只统计正文表格，不含这 3 张 Sheet。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 0. 背景与实验设计

- 背景：APP 功能多，老用户学了很久都没体验到；新用户需要「每天来发现不同的功能惊喜和奖励」延迟对单一内容的疲劳、减少流失。
- 假设：**任务体系是否能提升核心功能的体验率，从而提升留存**。
- 设计稿：Figma `1.37.0` node-id=49102-58002。

| 人群 | 划分依据 | AB key | 实验组 | 对照组 |
|---|---|---|---|---|
| 新用户 | 游客 id 生成时间 **8 月 21 日之后** | `homepage_tasks_list` | 有任务面板，**5 个任务** | 没有任务面板 |
| 老用户 | 游客 id 生成时间 **8 月 21 日之前**注册的（后台配置 8 月 21 日之前的游客和注册用户） | `homepage_tasks_list_old` | 有任务面板，**2 任务（小麦、跟读故事书）+ 邀请任务兜底** | 没有任务面板 |

- 老用户差异说明：**不管用户过去是否完成过**小麦和跟读故事书，**都可以引导用户完成**。
- 核心指标：
  - **留存**
  - **任务转化率** = 点击去完成任务 / 任务曝光
  - **任务完成率** = 达到任务领取奖励 / 任务曝光

### 2. 任务面板引入方式（新老用户不同）

**新用户（AB）**
- 入口**固定展示**，用户点击进入任务面板。
- **完成第一个单元 → 触发任务面板入口**，引导用户点击 → 进入奖励中心 → 领取奖品。
- 实验组：**删除原本的 Giggles 购买弹窗引导**，改由「完成单元任务」触发引导。

**老用户（AB）**
- 任务面板是**动态**的，按 AB 展示。
- 对**升级到 V1.37 版本、非首日启动 APP** 的老用户：上线后**固定展示入口**；主动弹面板的时机 = **完成一个单元之后、单元勋章发放流程后**，判断用户是否点击查看过任务面板，**若没有则主动弹出面板**。

### 3. 各任务的引导与领奖路径

**任务一：完成第 1 单元**
- 未完成时点击该任务 → 回到路径，**语音提示「完成第一个单元领取奖励」**。
- 完成后：完成第 1 个单元 → 单元勋章结算 → 引导用户**手动点击功能入口** → 引入任务面板 → 任务状态变**已完成盖章仪式感** → 用户点击任务面板后，**服装奖励飞入奖励中心**（点击奖励中心可定位到该服装奖励）。
- 下次点击进入任务面板：看到【动画】任务收纳到**【已完成任务】列表**，并按任务优先级**更新下一个任务**。
- 结算动效节奏（图 10 注）：① 进度条更新（Lv1 进度条向前推进一段，小兔滑块跟着前移）约 **500ms**；② 奖章点亮（刚完成的卡片下方由灰色轻微抖动 → 抽出星光粒子 → 变为点亮的金色奖章）约 **500ms**；③ **停留 800ms**，奖章星星动画；搭配音效 @Anzai。
- 领奖三步（图 13）：引导用户领取奖励（卡片打勾）→ 用户**主动点击礼物盒子**，出现奖励 mask（`New Award` + `Take it`）→ 点击收下，奖励飞入奖励中心，mask 消失。**Giggles 奖励同样走 New Award + Take it**。
- 首个任务完成后（图 11 注）：获得一套服装 → **点击给 Avatar 穿上** → 进入奖励中心；**奖励中心关闭后回到首页，任务面板依然打开**，点击可以去完成下一个任务。

**任务二：唤醒小麦**
- 未完成时点击小麦任务 → **通过自动引导方式打开小麦**。
- 完成后：toast 弹窗提示任务完成 → **退出小麦功能后**引导用户点击任务面板 → 任务状态变已完成盖章仪式感 → 点击后服装奖励飞入奖励中心（可定位）→ 回到路径中。
- 后续用户主动打开任务面板：小麦任务已完成，**解锁下一个任务**。
- 引导有两个方向（图 12 设计注，本期择一/并存未明）：
  1. **引导用户主动点击**（系统出遮罩 + 手指点击引导动画，需用户自己点「小麦」进入）—— 好处：用户能学到后面去访问这个功能的入口。
  2. **自动入口引导**（系统主动出遮罩，然后手指点击、伴随点击特效直接进入对应模块）—— 好处：压缩交互链路长度、减少过程中流失。
- 任务开启组件提醒（图 12）：小麦睡着态 + 提示「睡的有点死，唤醒它试着，大声说 "Hi!"」。

**任务三：跟读故事书**
- **自主探索路径**：用户自己体验到跟读故事书 → **被动完成任务**，结算页面 toast 提示。
- **任务引导路径**：从任务看板点击 → 引导用户打开故事书 → **待用户选择一本故事书后，播放跟读引导动画**。
- 完成后：故事书结算页面 toast 弹窗提示任务完成 → **退出故事书功能后**服装奖励飞入奖励中心（可定位）→ 回到路径 → 任务面板打开、跟读故事书任务完成、解锁下一个任务。
- **评审后补充**：故事书的跟读模式引导，**根据用户点击是否有前向的跟读任务引导** —— 若用户还没完成跟读任务，则打开一本故事书后引导故事书跟读模式。
- 结算页停留：**结算完成之后停留在页面 3s**（图 15）。

**任务四：消息通知**
- **自主路径**：用户自己打开消息通知 → 同意后弹窗 → toast「开启消息通知任务完成 ✅」→ Giggles 飞入奖励中心动画。
- **任务引导路径**：任务面板点击 → 跳转引导打开消息通知。
  - 点击**允许** → toast「消息通知已开启，点击领取奖励」→ 点击后 Giggles 飞入奖励中心 → **首页中自动打开任务面板页面**，进度变化。
  - 点击**不允许** → 页面提示「在设置中主动打开消息」。
- **后续补偿**：用户后来在系统设置里打开了消息通知，需要**监控任务完成并反馈 APP** → toast「开启消息通知任务完成 ✅」→ Giggles 飞入奖励中心动画。
- 弹窗层级（图 5 / 图 16）：先自定义前置页（`Max can help you remember to learn every day!` / `Turn on reminders to build a good learning habit.`，按钮 `Remind me to learn` / `Not now`；中文版「让 Giggle 提醒你上课吗？」允许 / 不允许），**同意后才拉系统权限弹窗**。

**任务五：邀请好友**
- 通知文案：
  - title：`Wow! A new friend has joined!`
  - 内容：`Thanks to your invitation, ${inviteeName} is here! Your reward has been added. Invite one more friend to unlock the next reward!`
- 好友接受邀请后：**主路径** toast「XX 好友已接受邀请」→ 随后播放 Giggles 领取动画 → 奖励中心入口 Giggles 数字刷新动画。
- **状态特殊**：toast 展示后**直接**走 Giggles 发放动画；**邀请好友卡片没有「已完成待领取」状态，也没有「收起完成」状态**。

### 4. 任务全局规则

- 任务之间**没有前后依赖关系**，用户可以不按顺序完成。
- 用户是否有任务，**取决于当前用户任务列表展示了几个任务**。
- 任务完成后**收纳到任务列表**中，点击可查看历史已完成的任务。
- 用户可以**自己探索被动完成任务**，依然会有奖励提示。

### 8. 待确认项

1. **任务优先级缺 P5**：表内 P1–P4 之后直接跳 P6，是否漏配一个任务。
2. **老用户任务数量口径**：指标表写「2 任务（小麦、跟读故事书）+ 邀请兜底」，需求详情写「老用户有**三个任务**，小麦和跟读故事书，兜底任务为邀请好友」，究竟是 2 张卡 + 兜底还是 3 张卡需对齐。
3. **小麦命名两套并存**：埋点主表用 `task_wheat` / `wheat_feature_start|end`（wheat），引导埋点用 `task_mai_intro1`（mai），文案表写「唤醒小麦AI / Wake Up Xiaomai AI」，设计稿卡片写「叫小麦起床 / Go wake up Mai」，四套叫法需统一（否则埋点分析对不上）。
4. **任务卡片文案与三语表不一致**：三语表 P4 写「跟读一本故事书 / 练出好听发音」，设计稿卡片写「**读一本书给妈妈听**」；P2 三语表「唤醒小麦AI」vs 设计稿「叫小麦起床」。以哪套上线未定。
5. **P2 奖励未定**：「一套服装（或者特殊的头饰）」；且全部奖励商品仍待 Alice 设计。
6. **`task_status` 的 `gifted` 语义**：中文写「领取礼物」，与 `task_reward_claim` 的关系（gifted = 已完成待领取，还是已领取）未定义。
