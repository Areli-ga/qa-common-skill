## 摘要

V1.37.0 把 M Town Talk 里的小麦从「单向解释」改成**多轮次交互式指导**：小麦激活提到最高优先级（连续两轮开麦无进展 / 点画面内容 / 主动点小麦三种触发）、Prompt 改为**反问引导 + 用母语沟通**、胶囊组件可关闭拒读、点击 object 可播**动画 + 音效**，并用**动态 prompt 把用户英语水平反馈给 NPC 以改变 NPC 说话习惯**；另做**多镜头切换的技术预研（本迭代不开发）**。目标：M Town 使用时长**增长 100%**。

### 1. 需求背景（当前 4 个问题）

1. **小麦的激活有问题**：用户很难主动去发掘小麦；**即使小麦给出了语音引导，用户的执行准确率仍旧偏低**。
2. **小麦承担的是单向解释作用**，丧失了跟用户**答疑的交互式**方式。
3. **对话没有分级策略**：对于基础不好的用户、害羞的用户，**不知道怎么开口，课程太难**。
4. **场景仍是单镜头**，需要支持**单角色多镜头** —— 例如老师 NPC 带用户从校门口转场到教室；购物环节从货架区域 → 结账 → 给钱的特写镜头。

### 2. 产品目标

- **提高 M Town 的使用时长，目标增长 100%。**
- **提前做技术预研，面向未来的设计。**

### 3. 小麦多轮次指导教学（5.1）

| 项 | 内容 |
|---|---|
| **需求范围** | **涵盖英文课和中文课** |
| **小麦退出的视觉** | **把当前的「睡眠状态」修改为「监听状态」**（原文注：考虑到未来的小麦的睡着需要严谨） |

**激活小麦流程**
- **小麦内容激活处于最高优先级**，以下任何一种行为都可以触发小麦的 Tutor：
  1. **用户和 NPC 连续两轮开麦，但没有推进剧情**；
  2. **用户点击画面里面的内容**；
  3. **用户主动点击小麦**（当前已有）。

**小麦和用户的交互对话（Prompt 修改）**
- 小麦**不再直接给出建议，而是给出反问，引导用户思考**。
- **用母语和小麦进行沟通**。
- **胶囊组件提供关闭按钮（仅限于中英文的 M Town Talk 游戏）** —— 用户可以**拒绝朗读当前的推荐内容**。
- 小麦可以**承接用户朗读组件的行为**，并在合适的时候**继续给出推荐朗读内容**。
- **用户完成朗读后，继续推荐和 NPC 的流程**。

**支持动画和音效（08/06 新增）**
- 点击一个 **object 对象**的情况下，可以**播放动画以及音效**。
- 动画和音效**协同播放**：
  - **动画会在音频的播放时间周期之内进行循环播放**；
  - **一个音频重复点击，从头开始播放**；
  - **支持同时触发多个 object 的动画和音频播放**；
  - 为避免音效打扰后续音频对话（小麦讲话、录音功能等），**暂定音效播放完毕以后，才会进入到后续的一轮对话**（比如小麦的对话开启，或者 NPC 的对话开启）。

**动态 prompt（对话分级）**
- 小麦应能通过**和用户的母语沟通捕捉用户的英语水平**，并把**当前用户与 NPC 沟通遇见的困难以及解决方案给到 NPC，以此改变 NPC 的说话习惯**：
  - 判定**太难** → 让 NPC 说**简单的、重复的、慢速的**话；
  - 判定**太无聊 / 太简单** → 让 NPC 说**更有趣、相对复杂的**话。

### 4. 支持镜头切换（5.2，技术预研）

- 目的：提高场景沉浸式，**在一个对话游戏里切换不同的场景镜头，一个镜头代表一个图片**。
- 分工：**内容运营侧**准备课件、制作 demo，根据课件脚本做功能配置；**UI/UX 侧**做场景之间的转场设计。
- ⚠️ **本迭代暂不开发**，可以去探索 **AI 自动根据语义 / 剧情推进 / 用户点击事件切换场景**的可行性：

| 触发方式 | 示例 |
|---|---|
| **语义** | 「我们到小房间看看吧！」 |
| **剧情推进** | 当用户确定已经在购物车放置了所有的商品之后，**镜头自动推进到收银台** |
| **用户点击** | 用户点击广角镜头中的 NPC，可以**切换到该 NPC 的特写镜头**并与之对话 |

- **风险：游戏上下文太长导致 AI 响应变慢。**

### 5. 待确认项

1. **全篇无数据埋点**：唯一量化目标是「使用时长增长 100%」，但没有任何事件定义 —— 小麦三种激活方式各自的触发量、反问轮次、胶囊关闭率（拒读率）、object 点击/动画播放、动态 prompt 的分级判定结果全部无法观测。**同一模块 V1.36《MtownTalk 支持 bbox 点击》也是「全篇无埋点」，已连续两版缺失。**
2. **「连续两轮开麦但没有推进剧情」判定标准未定义**：什么算「推进剧情」？ASR 无识别结果 / 静音超时 / 说了但语义不相关，各算不算一轮。
3. **小麦激活「最高优先级」的抢占规则未定义**：触发时 NPC 正在说话、用户正在录音、object 音效正在播放，分别如何处理（打断 / 排队 / 丢弃）。
4. **胶囊关闭按钮「仅限中英文」**：印尼语是主力市场（小麦 80–90% 用户），印尼语用户拿不到关闭按钮，是否有意需确认。
5. **电量消耗与频控仍未定义**：V1.36 bbox 篇已把「每次点击触发一轮 AI 回复即消耗电量」列为待确认，本期又新增「**支持同时触发多个 object**」+ 小麦多轮反问，电量口径（是否计费、连点频控、余额不足时的表现）仍是空白 —— 与 V1.36《Mai 电量系统》的「子游戏准入 ≥0.01 美金、余额不可为负」直接相关。
6. **「音效播放完毕才进入后续一轮对话」是暂定**；且**同时触发多个 object** 时，是等最后一个音效结束、还是第一个结束就放行，未说明；长音效会不会把对话卡死也无超时兜底。
7. **动态 prompt 的分级依据与落库全缺**：用什么信号判定「太难 / 太简单」（ASR 打分？母语求助次数？无应答次数？）、判定结果是否持久化、**跨场景 / 跨课是否继承**、是否作为用户属性上报、是否走 AB，全部未定义 —— 这是本篇最不可测的部分。
8. **「小麦睡着」的状态定义三篇不一致**：本篇把「睡眠状态改为监听状态」（原文自承「未来的小麦的睡着需要严谨」）；同版本《作息陪伴与冻结解救》定义了 `awake` / `asleep` 状态机 + 冻结皮肤；《新用户唤醒仪式优化》又有破冰的睡着态。三者是否同一状态字段、M Town Talk 内的小麦是否受作息影响，必须统一。
9. **5.2 的交付边界**：明确「本迭代暂不开发」，但「内容运营准备课件 / 制作 demo」「UI/UX 转场设计」是否属于本期交付物未说明。
10. **无验收标准、无异常兜底**：动画资源缺失、音效加载失败、object 无配置时的表现均未定义。
