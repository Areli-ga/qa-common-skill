## 摘要
V1.39.0 把 IP 打电话从 V1.38 的**固定脚本 + 三语预生成音频**改造成 **AI 生成 + 四层架构的场景库**：内容单元从「完整台词」降为**一句话事件条目**，音频改**实时 TTS 零预生成**，多语言改 **AI 本地化**，并首次支持**孩子的回复被实时接住**；来电分成**被动来电（系统发起，1–3 轮、话题由事件池预置）**与**主动来电（孩子在家园拨打，前期不限轮次、不限话题）**；频控降频为 **D1/D2 每日 1 通 → D3 起改事件触发（成就 / 节日 / 生日 / 活动）+ 距上通 ≥N 天（N 初始 3）兜底**，**「取消订阅」状态与语音信箱一并取消**，主动拨打与系统来电**不再互斥**；场景由「**触发器（服务端）+ 事件池（人工审核）+ goal_prompt（含占位符的自然语言指令）+ runtime 配置**」三件套组成，**触发判定与指令渲染在服务端、agent 对话在客户端**（客户端拿到的是已渲染好、无占位符的指令）。另有一条待评估的小需求：**新手引导与拨号盘的数字改读英文单词**（1 → one，Max61 → six one）。

### 1. 内容设计原则：一期固定脚本 → V2.0 场景库
| 维度 | 一期固定脚本 | **V2.0 场景库** |
|---|---|---|
| 内容单元 | 完整台词（覆盖所有轮次） | **一句话事件条目** |
| 音频 | 每条预生成 × 3 语言 | **实时 TTS，零预生成** |
| 多语言 | 每条人工翻译 | **AI 本地化表达** |
| 上下文 | 无 | **占位符注入**（姓名 / 记忆 / 学习进度 / 时间） |
| 孩子回复 | **无法响应** | **实时接住并引导** |
| 组合数 | N 条脚本 = N 通电话 | **M 模板 × K 事件 × 上下文变量** |

四要素分工：**触发器（程序化）**决定「什么时候打、为什么打」；**事件池（人工审核）**决定「这通聊哪件具体的事」；**目标指令（自然语言）**决定「怎么聊、怎么引导、怎么收尾」；**上下文（程序注入）**决定「这通对这个孩子有什么不同」。

**来电触发场景依赖（长期会接入的上下文源）**：C1 时间（日期 / 节日 / 季节 / 开学季 / 生日 / 注册天数 / 活跃间隔）；C2 会话记忆（上通摘要、`open_loop`、孩子说过的事实）；C3 学习（最近学的词或单元、最近完课、卡住的关卡）；C4 行为（成就、活动）。

### 2. 四层架构与端到端链路
| 层 | 内容 | 变更频率 |
|---|---|---|
| **L0 常量层** | Max 人设、世界观、语言策略、儿童安全红线、主动引导原则 | 几乎不变 |
| **L1 触发层** | 触发器定义、主动/被动分层、频控、优先级仲裁 | 按实验调 |
| **L2 场景库** | 事件池 + 目标指令模板 | 定期上新，**可能每周上一批事件** |
| **L3 上下文层** | 时间 / 记忆 / 学习 / 行为，填充占位符 | 实时 |

**端到端链路**：服务端触发器判定命中 → 服务端选中场景、**从事件池随机取一条事件** → 拉取上下文 → **渲染目标指令（替换全部占位符）** → 下发客户端 `{scene_id, event_id, 已渲染的目标指令, 运行时配置}` → 客户端唤起来电 UI → 孩子接听 → agent 按目标指令引导对话 → 通话结束**生成结构化摘要写回记忆层 + 上报埋点**。
**【关键】触发判定与指令渲染在服务端，agent 对话在客户端；客户端拿到的是一段已渲染好、无占位符的自然语言指令，不需要理解任何业务规则。**

**L0 不可变约束（任何场景不得覆盖）**
- 角色设定：**Max 是孩子的朋友，不是老师、不是助手、不是客服**；Max 始终是话题的带动者。
- 世界观一致性：引用的地点 / 角色 / 事件必须在既定世界观框架内。
- **语言策略：待定（决策项 D1）**。
- **儿童安全红线**：不索取住址 / 学校名 / 家长联系方式；不涉及暴力、恐怖、宗教、政治、身体隐私；不做医疗或心理诊断式表述；**不承诺现实世界的物品或见面**。
- **不得提及**：未解锁功能、付费引导、其他用户的个人信息。

### 3. 主动来电 vs 被动来电（L1）
| 维度 | **被动来电（系统发起）** | **主动来电（孩子在家园拨打）** |
|---|---|---|
| 定位 | 打扰用户，**必须轻量、有明确对话目标** | 类似豆包的场景，安全合规话题下可随意聊 |
| **轮次上限** | **1–3 轮** | **前期不限制**，后续看使用情况加限制 |
| 话题控制 | 由场景的**事件池预置** | 不限，仅用 IP 人设 + goal 框住 |
| IP | **Max 来电** | **全部 IP 可选** |
| 频控 | 前 2 天连打建立认知，之后事件触发 + N 天运营事件触发 | 前期不限制 |
| 上下文 | **与主动来电互通，共用同一记忆层** | 同左 |
| 主指标 | **次通接听率** | **主动拨打人数 / 人均次数** |

### 4. 频控改造（本期核心改动）
- **D1、D2**：每日 1 通系统来电（建立「Max 会打给我」的认知）。
- **D3 起**：不再每日推送，改为 ① **事件触发**（成就达成 / 活动上线 / 生日 / 节日）；② **兜底：距上一通 ≥ N 天（N 初始 3，实验调优）**则从常规轮换池推一通。
- **取消订阅逻辑全部删除**：**电话没有「取消订阅」状态**；**不需要发送取消订阅来电和语音信箱**；**线上已取消订阅的用户，二期上线后会恢复来电状态，但不会再收前两通电话，只收后续特殊节点内容**。
- **主动来电与系统来电不再冲突**：即使当日用户已主动拨打，满足条件依然会来电。
- 时机表：D1/D2 系统来电；D3 及后续走特殊节假日来电（由触发器判断，**当日触发多个则按优先级仲裁**）；孩子主动打电话随时可打。
- **场景触发优先级**（同一时刻多触发器命中）：**成就 > 时间节假日 > 常规轮换池**。

> ⚠️ 与 V1.38 的断裂点：一期有「连续拒接 / 信箱积压 → 取消订阅话术 + 停推」和**语音信箱**（未接来电按时序补播），二期把这两块**整体取消**。老用户的取消订阅状态、已积压的语音信箱内容如何清理与迁移，原文只写了「会回复来电状态」，没写数据处理方式。

### 5. 场景三件套结构（Scene）
一个来电场景 = **触发器（服务端配置，程序化）+ 事件池（人工审核，程序随机取一条）+ goal_prompt（自然语言，含占位符）+ runtime（客户端运行时配置）**；`类别` 仅供内容运营管理，**不进入 prompt**。

结构样例（`school_start`）：
- `trigger`: `trigger_id: trg_school_season`；条件 `month in [1, 9]`；**实现难度 T1**；**冷却 7 天**；`适用age_band: [6-8, 9-12]`。
- `event_pool`：`{ev_sch_01, "把午饭洒在自己身上了"}`、`{ev_sch_02, "第一天找不到自己的教室"}`、`{ev_sch_03, "认识了一个新同桌，但忘了问他叫什么"}`…… **每个场景 8–15 条**。
- `goal_prompt`：300 字以内连贯文本，含占位符。
- `runtime`：`max_turns: 3`；`sfx_whitelist: [school_bell, kids_chatter, backpack_zip]`；`fallback_audio: fallback_school_01`。
- 备注：**不同国家地区开学时间不同，需要定义【国家】+ 开学时间节奏**。

**样例一 `ask_word_help`（求助类，被动接电话）**
- trigger `trg_recent_lesson`：条件 **`recent_learned_words` 非空 AND `days_since_last_lesson <= 3`**；**难度 T2（需学习服务提供最近学习词表）**；**冷却 5 天**；age_band `[6-8, 9-12]`。
- event_pool 6 条（Max 遇到的困境）：餐厅点喝的卡住 / 商店问价说不出口 / 跟新邻居打招呼忘了怎么说 / 动物园问动物叫什么 / 想要一份没有洋葱的东西 / 去朋友家想说谢谢却卡住。
- goal_prompt 行为分支（**这是 QA 验收 AI 表现的判据**）：Max 卡在 `{target_word}` 上**装作想不起来**、用求助语气**不能用考他的口吻**；**答对 → 表现惊喜并马上把词用进情境说给他听**；**答错或说不会 → 不指出错误，自己「忽然想起来」自然带过**；**沉默超过几秒 → 自己想起来并把功劳给他**；**任何情况都不追问第二个词**；收尾真诚道谢并约定下次告诉他办成没有。
- 占位符：`child_name`（用户昵称）、`max_event`（事件池随机一条）、`target_word`（取自 `recent_learned_words`）、`age_hint`（按 age_band）、`memory_hint`（记忆层生成）。

**样例二 `open_freetalk`（开放，主动来电）**
- trigger `trg_active_dial`：条件 **`call_type == active`**；难度 T1；age_band `[全]`；**`event_pool: []`（主动来电无预置事件，话题由孩子决定）**。
- goal_prompt 要点：开场表现「没想到你会打来」；**把主动权交给孩子**；顺着他的话题走；**每次回应里至少有一处具体复述他刚说的内容**；**孩子不知道说什么时主动抛一件自己今天遇到的小事，不许冷场**；**聊到第 `{max_turns}` 轮用自然理由收尾（如妈妈叫吃饭），不能突然切断**；**不问住址 / 学校名 / 家长联系方式**。
- 占位符：`child_name`、`memory_hint`、`age_hint`、`max_turns`（样例值 **5**）。

### 6. 触发器实现难度分级
| 级 | 说明 | 举例 |
|---|---|---|
| **T1** | 纯日期 / 本地状态可算，易实现 | 月份、节日、生日、活跃间隔、季节 |
| **T2** | 需内部业务数据 | 学习记录、完课、关卡失败、成就、活动 |

### 8. 数据埋点（内嵌表 ndDfoe / cIGPeH / or1mnk）
本期是**在一期事件上加参数**，不是新增事件。目标：**系统来电看接听完成率；主动来电看来电频率与对话轮次**。

| 事件 | 触发时机 | 端 | 参数（**加粗为本期新增**） |
|---|---|---|---|
| `calls_incoming_show` | 电话机页停留 20s 未拨 / 首页停留 5s 或完成单元后 / 家园停留 5s / push 触发来电时 | **H5、Unity** | `scene` = calls_page / home_idle / home_finish_unit / house / push；`ip_role`；**`type` = weekend_plan / comeback_greeting / leaderboard / streak_congrats / first_day / second_day（首日、次日及运营场景）** |

| `calls_decline_click` | 来电时点拒接，或**通话中途退出（未播放完 90%）** | H5 | `stage` = decline_before_answer / hangup_during_call；`ip_role`；**`source` = dial / answer（主动拨打 / 系统来电）** |

### ⚠️ 待确认（写用例前需拉齐）
1. **L0「语言策略」明确标着「待定，见决策项 D1」** —— 实时 TTS 用什么语言、跟端内语言设置怎么联动、新增需求里「引导语音本地语言 + 数字英文」是不是同一个决策，全悬着。这条不定，多语言用例无法写。
2. **取消订阅 / 语音信箱下线的数据迁移未定**：线上已取消订阅用户「会恢复来电状态」，但**积压的语音信箱内容怎么处理、一期的 `calls_*` 退订相关统计是否还保留**没写；而埋点表里 `calls_decline_click` 还挂着退订监控口径。
3. **N 天兜底的 N 是否可配**（初始 3，「实验调优」）：配置入口、是否按 AB 分组、改动后对已在冷却中的用户是否即时生效，均未写。
4. **冷却与优先级的交互**：场景各自有冷却（school_start 7 天 / ask_word_help 5 天），同一天多个触发器命中时先比优先级还是先比冷却；被优先级挤掉的场景是否消耗它的冷却，未定义。
5. **轮次上限两套值**：被动来电表写 **1–3 轮**，`school_start` 的 runtime 写 `max_turns: 3`，而 `open_freetalk` 的占位符样例写 `max_turns: 5`（主动来电又说「前期不限制」）。到底以 runtime 下发为准还是以文案里的数字为准，要统一。
6. **AI 对话失败的兜底**：`runtime.fallback_audio` 只在 `school_start` 样例里出现一次，**TTS 失败 / agent 超时 / 网络中断 / 弱网**时是否回落到一期固定脚本，原文没写（一期有「固定脚本兜底」的说法，二期是否保留待确认）。
7. **儿童安全红线怎么验**：L0 列了红线（不索取住址学校、不承诺见面、不谈医疗），但**没有拦截机制描述**（是 prompt 约束还是有后置审核 / 敏感词过滤），QA 无法定义「违规」的判定与处置路径。
8. **对话留档是 P2**：「Max 说的 + 孩子回的转写 + 主/被动标识 + 脚本 ID」若本期不做，则**线上出现不当内容时无从复现**，与红线验证直接冲突 —— 建议优先级复议。
9. **`leaderboard` 场景强依赖 Top Learners 段位改造**（V1.38《Top Learners 段位系统》），两边上线时间是否对齐要确认；段位变化的触发口径（升段 / 降段 / 同段内变化）也没写。
10. **首批场景清单里的孤立数字（100–103）**含义不明；且清单里 `ask_choice_help` 等 7 个冷启动场景**没有标优先级**，只有 4 个运营场景标了 P0–P3。
11. **文档里贴了真实 admin JWT**（`/admin/kid-phone/scene/pin` 接口），属于凭证外泄，建议推动删除或轮换；QA 用该接口 pin 场景时用自己的 token。
12. **新增需求（数字读英文）本期是否交付未定**（原文就是「评估能否这一期做」），涉及**新手引导音频、拨号盘按键音、通讯录号码朗读**三处，要么一起做要么一起不做，否则会出现同一页面数字一半英文一半本地语言。
13. **埋点 `type` 枚举里 `second_day` 在一张表里写成 `secord_day`**（内嵌表 ndDfoe 原文），上线前需核对拼写，否则首日/次日分布统计直接错。
14. **主动来电不限轮次 vs 成本**：`open_freetalk` 前期不限制轮次也不限次数，**实时 TTS + agent 的成本与超长通话的截断策略**没写（对照 V1.36《Mai 电量系统》是另一套成本控制机制，本期是否复用未提）。
