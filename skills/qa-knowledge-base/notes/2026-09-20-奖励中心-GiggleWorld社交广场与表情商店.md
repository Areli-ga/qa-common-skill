## 摘要
V1.39.0 把**家园、游戏大厅、广场**三个分散入口收进一张新地图 **【Giggle World】**（AB：新用户 `reward_function_plaza` / 老用户 `reward_funciton_plazaold`，并加后端开关），新增**社交广场 Square**：进入 Giggle World 及其子功能（家园 / 游戏大厅 / 广场）且**非游戏中**的用户，Avatar 就会出现在广场同屏（按房间分流，Admin 可配单房人数上限，默认 20、范围 2–50），可点好友 Avatar 看名片并**访问家园**或**发起 PK（本期限免、不扣 Giggles）**；同时新增 **「表情商店 Moves shop」——按动作独立计次的次数包**（如「机械舞 x10」），在广场 / 家园用一次扣一次，作为 Giggles 的新消耗出口；配套：Admin 新增「运营 / 功能广场配置」（背景图 / BGM / 默认动画库 / 基础参数，支持节假日定时生效）与「奖励中心 / 表情动作」商品管理、昵称对他人**匿名化展示**、**家长端屏幕时间开关**可关闭社交广场入口。

### 2. 广场入口与房间
**谁出现在广场**（内嵌表 G85Pj6）
- **进入 Giggle World 以及子功能的用户 —— 包括在家园中、在游戏大厅、在广场的人，只要不在游戏中，都出现在广场**；⚠️ 与正文「当用户进入【Giggle 家园】中，非游戏状态，形象就会出现在广场中」表述不同，但两处都指向「**人不在广场页面也会被渲染进广场**」这一反直觉规则。
- **一旦进入游戏或者 PK 中，从广场中移除**；退出后可继续进入广场。
- 他人 Avatar：复用现有 Avatar 渲染，**含当前穿戴服装与配饰，不展示家园内容**；昵称在 Avatar 下方、单行、超长省略、只展示昵称；**自己的 Avatar 有标识区分**（图 4 标注「玩家本人 / 其他玩家 / 进场特效」）。

**房间分配规则**
- 按优先级：① **随机未满房**；② 全部房间已满 → **新建房间**。
- 约束：**房间内站位由服务端从预设的 N（10）个坐标点中分配，进房后不变**；用户退出后释放站位；用户被分配到**唯一 `room_id` 与唯一 `slot_id`**；进入广场在线池后对同房其他用户可见。
- **软碰撞**：角色间设最小间距，互相推开，**禁止圆心重合**（图 4）。
- Admin 可配**单房人数上限**：默认 **20 人/房，范围 2–50**（同一房间内可同时在线的 Avatar 数量上限，**含自己**）。
- ⚠️ **坐标点 N=10 与单房上限 20（可配到 50）直接冲突**；且图 4 图注写的是「**每次好友进出，随机分配一个没有被占的位置**」「自己站在核心位置」，与「**进房后不变**」也不一致。

**Admin「运营 / 功能广场配置」**（图 6 / 图 7，面包屑写明 `运营 / 功能广场 · ABkey reward_function_plaza`，四个 Tab：基础参数 / 背景图 / 背景音乐 / 默认动画库）
- **背景图**：支持**常驻默认 + 定时生效**，列表字段 `预览 / 名称 / 生效方式 / 生效时间 / 绑定 BGM / 优先级 / 状态 / 操作`；**生效规则：同一时刻命中多条时取优先级大的一条；无任何定时配置命中则回落到常驻默认**；节假日皮肤提前配好时间段自动切换，无需当天手动上下架。示例时间轴：日常广场（常驻，优先级 0，BGM_01）、万圣节 10/25–11/02（优先级 10，BGM_02）、圣诞 12/18–12/31（BGM_03）、春节（印尼/全球）02/10–02/22。
- **背景音乐**：**广场 BGM 总开关**（关闭后广场静音，不影响 APP 内其他 BGM；**用户端设置里的音乐开关优先级更高**）；**默认音量 60（0–100），动作音效音量不受此项影响**；播放方式 **单曲循环 / 列表随机**（选列表随机时，命中同一时段的多条 BGM 依次随机播放）；BGM 列表同样支持常驻默认 / 定时生效 + 独立音量。
- **默认动画库**：在广场**停留 5 秒**随机播一个默认动画（从默认动画库随机抽）。
- 基础参数：新增**房间最大人数（占位数）**。

### 4. 动作使用与消耗
- 前置条件：**场景为家园或广场**；**该动作剩余次数 > 0 或为免费动作**。
- 后置：**本地播放动画 + 实时广播给同房用户**；**剩余次数 −1，写入使用流水**。
- 动作栏（内嵌表 qW9ZJQ）：广场底部**横向可滑动**，每项 = 动作图标 + 剩余次数角标；**单击即用，无二次确认**；**次数为 0 时展示动作价格标签，点击原地弹购买浮层（不跳商店）**；**家园内同样有动作栏（收起态，点击展开）**。
- 图 12 补充（与上表有出入）：**设置 6 个槽位，默认赠送用户 4 个基础动作，用完则需要购买**；后续拓展 8.5 个槽位、支持横向滑动；**点击面板以外区域收起 popover**；点有价格标签的表情进入购买流程；**点已有的表情，减 1 动画，收起面板并直接播放表情**；设计稿自问「进入广场，动作槽位默认展开？」未定。设计稿动作栏实际 8 项：挥手 / 鼓掌 / 欢呼(7x) / 转圈(7x) / 比心(7x) / 空翻(7x) / 机械舞(300) / 撒花特效(300)。

### 5. PK 发起与等待
- **玩法复用现有游戏竞技场玩法**；**PK 不消耗 Giggles，UI 上加「限免」标志**；**结算奖励在 PK 结算页即时到账，不需要回任何面板领取**。
- 入口（内嵌表 6hAGoO）：**好友卡片「PK」按钮 / 排行榜个人卡片「PK」按钮**。
- 发起方：等待中浮层 = 对方 Avatar + **5s 倒计时环** + 「取消」；成功 → 直接进入 PK 场景；失败 → 图形化「现在不方便」+ 建议，**可一键系统匹配一个假用户开始对战**（图 13：`{name} is busy right now`，按钮 `Not now / Find else`；**点 Find else 走机器人随机 PK 流程**）。
- 接收方（内嵌表 fQvyZX）：邀请弹窗 = 对方 Avatar + 昵称 + 「接受 / 拒绝」+ **5s 倒计时**，**有音效**；**弹窗出现场景 = 【Giggle World】各功能页面，排除游戏中**。
- **业务规则（内嵌表 yl0RYh）**

| 规则 | 值 |
|---|---|
| **邀请有效期** | **7 秒** |
| 同一发起方对同一对象的邀请冷却 | **60s**（防骚扰） |
| 单用户当日被邀请上限 | **5 次，包括成功与失败** |
| 单用户同时进行中的邀请 | **1 个** |
| 多人同时发起给同一人 | 只推送第一个；后续发起者收到「对方正在被邀请」 |
| 多人同时被 waiting_pk 用户接受 | **先到先得**，第一个 accept 成立，其余收到「来晚了」 |
| 学习中 | **不可被发起，不弹窗** |

- ⚠️ **邀请有效期 7s 与两处 UI 的 5s 倒计时冲突**（发起方等待环 5s、接收方弹窗 5s），需定一个口径。

- **异常 / 分支（内嵌表 5YasVD）**

| 分支 | 处理 |
|---|---|
| 对方在邀请到达前离线 | 邀请失效，发起方收到「对方离开了」 |
| 双方同时向对方发起 | 服务端按接收时间取先者，**后者自动转为 accept** |
| PK 场景加载失败 | 双方回退到广场，邀请标记 `failed`，**不消耗被邀次数** |
| 接受后对方掉线 | 按**现有竞技场断线规则**处理 |
| 邀请弹窗出现时用户正在使用动作 | **动作照常播放，弹窗叠加在上层** |

### 7. 昵称匿名化（对他人展示）
- **2–3 个字符**：展示第 1 个字符，其余用 `*` 遮盖 —— `Al → A*`；`Bob → B`（原文如此，**3 字符示例被截断，应为 `B**` 还是 `B*b` 未写清**）。
- **≥4 个字符**：展示**前 1 个 + 后 2 个**，中间用 `*` —— `Sunny → S**ny`；`Michael → M****el`。

### ⚠️ 待确认（写用例前需拉齐）
1. **老用户 AB key 疑似拼错**：`reward_funciton_plazaold`（`funciton`）。若客户端按 PRD 写死，实验直接不分流。
2. **「谁出现在广场」口径**：正文说进家园就出现在广场，内嵌表说家园 / 游戏大厅 / 广场的人都出现。**在家园里的人被渲染进广场**意味着广场人数 ≠ 广场在线人数，房间计数、可见性、退出释放 slot 的时机都要按这个口径重测。
3. **站位坐标点 N=10 vs 单房上限 20（可配 50）**：坐标不够时怎么排；以及「**进房后不变**」与图注「**每次好友进出随机分配未占位置**」哪个为准。
4. **表情动作清单两套数据**（PRD 内嵌表 vs Admin 截图）：免费项、价格、使用场景、获取方式全不一致；且 PRD 没有 Admin 里的「**任务奖励**」获取方式和 `ACTION_HELLO`。上线配哪套要定。
5. **动作栏槽位数**：设计稿「6 个槽位、默认赠送 4 个基础动作」 vs 内嵌表「免费动作只有挥手 + 鼓掌 2 个」；以及「进入广场动作槽位是否默认展开」设计稿自己还打着问号。
6. **表情商店第二入口「动作栏末位 +」在设计稿里不存在**（末位是待购动作），入口到底有几个。
7. **PK 邀请有效期 7s vs UI 倒计时 5s**（发起方环 / 接收方弹窗），必须统一，否则「超时」判定客户端和服务端会打架。
8. **PK 限免与游戏大厅扣费的关系**：V1.37 定的是所有游戏 20 Giggles/次，本期 PK 走好友卡片发起**不扣费**；那么从广场发起 PK 和从游戏大厅进 PK 是否同一套计费入口、限免是否有时间窗 / 次数上限，全未写。
9. **昵称匿名化 3 字符规则被截断**（`Bob → B`），且好友名片设计稿里昵称 `Edd` 未打码；匿名化是否同时作用于排行榜、PK 对局页、家园访客列表也未说。
10. **本期做不做 P2 项**：3.3 Avatar 广场内移动、3.8 家长开关都是 P2，但家长开关在正文有完整描述（含置灰与提示文案）—— 到底交付不交付要拍板，直接决定用例范围。
11. **广场无埋点**：本篇业务目标全部依赖数据验证（模块留存、Giggles 消耗率、游戏大厅曝光），但没有埋点方案。
12. **Avatar 实时同步的边界全空**：进出房的广播延迟、断网重连后是否回到原 slot、同房用户上限打满时的排队或提示、动作广播失败的兜底、**他人正在播放动作时自己进房是否能看到**，均未定义。
13. **表情次数包的账本规则**：跨端同步、退款 / 回滚（播放中断、动作播放失败是否退次数）、次数为 0 的动作是否还占槽位、**免费动作是否也写使用流水**，未写。
14. **Giggle World 与旧入口的关系**：旧的家园入口、游戏大厅入口（V1.37 已替换掉家庭游戏入口）在实验组是否收起或保留双入口；**老用户引入视频要更新成新地图**，旧视频资源的下线时机也要跟。
