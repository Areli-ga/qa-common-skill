## 摘要
游戏大厅小游戏原本**每局消耗 20 Giggles**（V1.37 定），覆盖用户有限；本期用 AB **`abt_arcade_free_play`**（**仅新用户实验组**，游戏大厅和聚合入口两处入口都要分流）验证**去掉 Giggles 消耗**能把覆盖量级和留存拉到哪里。实验组改动：游戏介绍页**去掉「每局 20 Giggles」一行**；大厅首页改成**左侧 3 个推荐位轮播 + 右侧游戏卡网格**（没玩过 → 随机 3 个打 Hot，按 UTC+8 每天刷新；玩过 → 上次在玩 / 排名最高 / 即将掉出前 100，不足随机补齐 3 个），上榜前 100 的卡片角标 `No.排名`；推荐卡的**游玩数是假数据**（`N = base + rate × D`，D 从 2026-08-22 起按 UTC+8 自然日算，只涨不跌、同一天同一值）；结算**胜利 / 平局发 Giggle x 20、失败不发**，新增开宝箱过渡动效。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 基本信息
- 背景：游戏大厅小游戏需要消耗金币（V1.37《游戏大厅 2.0》每局统一扣 20 Giggles），**覆盖到的用户有限**，所以测试**不要金币**，看扩大量级对留存的影响。
- 目的：**AB 验证去掉消耗 Giggles 后覆盖量级和留存拉到哪里**。
- **实验 key：`abt_arcade_free_play`**
  - 对照组：目前线上；
  - 实验组：本需求部分，**仅针对新用户开放**，通过 AB 配置实现；
  - **游戏大厅和聚合入口进入都需要进行 AB 分流**。
- 核心指标：**功能留存、覆盖率（游戏大厅人数 / 同期 DAU）、大厅内游戏点击率、人均游戏次数**。
- UI：Figma 1.41.0 文件；正文另有一个飞书画板（「游戏大厅布局」下方，fetch 不抓画板，**未入库**）。
- 文中**没有埋点章节**。
- ⚠️ 「新用户」的判定口径（注册时间 / 安装版本 / 游客 ID 生成时间）未写。

### 1. 游戏大厅首页（原型说明表第 1 行 + 图 1）
- 进入大厅首页：**左侧推荐位轮播，右侧游戏卡位网格**。
- **推荐规则**
  - **没玩过游戏**：随机 3 个游戏，打上**热门（Hot）tag**；随机范围单人、双人游戏都可以；**随机的 3 个一天不变，以 UTC+8 时区刷新**。
  - **玩过游戏**：三个推荐位分别是
    - **上次在玩**：玩过的最后一个游戏；
    - **排名最高**：自己玩过的游戏中排名最高的那个；
    - **即将掉出前 100**：自己玩过的游戏中排名在**全国榜 90～100 名**的。
  - **补足 3 个**：如果只玩过 1 个游戏，就只放「上次在玩」，其余随机补足，保持 3 个。
- 推荐位轮播**自动播放**，底部轮播指示点，**点指示点切到对应一屏**。
- 点推荐位 → 进该游戏介绍页；点右侧任一游戏卡 → 进该游戏介绍页；**点左上返回 → 回岛屿地图**。
- **顶部展示当前 Giggles 余额，实验组与对照组一致**（实时读取孩子当前余额）。
- **右侧游戏列表**：单人游戏和多人游戏**分别随机展示**（原文「右侧游戏卡槽展示规则：单人游戏和双人游戏随机展」）；**用户上榜全国榜前 100 的游戏卡，左上角标注 `No.排名`**。
- 图 1 示意：推荐卡 `Name Matching`（Hot、游玩数 `13,9k`、`Go` 按钮、三点指示器）；右侧卡片 `Word Battle`、`Word Fishing`（`Last Played` 标签）、`Memory Master`（`No.1`）、`Listen & Run`、`Word Space`、另一张 `Word Batt…`；卡片右上的人形图标应为单人 / 多人标识。
- ⚠️ 边界未定义：「排名最高」与「即将掉出前 100」指向同一个游戏、或与「上次在玩」重复时怎么去重；玩过 2 个游戏但都没上榜时怎么补；「全国榜」按哪个国家；双人（本地多人）游戏有没有排名。

### 3. 结算流程（原型说明表第 3 行 + 图 3）
- 题目全部作答完毕 → **播放开宝箱动效** → 进入胜利页。
- **胜利页展示 `YOU WIN` 与平局发 `Giggle x 20`**，点 `Next` 进入结算详情页。
- **失败不发奖励**。
- **无胜负游戏的胜利定义：完成游戏算胜利，中途失败结束不发**。
- **结算页不变**。
- 过渡动画（图 3 文字）：
  - 场景压暗：对战场景整体降亮 / 虚化，聚焦中央；宝箱从顶部进度位放大移入画面中心；
  - 蓄势 Hold：宝箱轻微抖动 / 呼吸约 600ms，配上锁扣微微跳动，营造「即将开启」张力；
  - 爆发：宝箱开锁瞬间，背景由暗转亮（暖黄光幕铺满），四射彩色光线 + 星星粒子从宝箱中心向外爆炸扩散，蓝色能量环扩大淡出，伴屏幕轻震 + 开箱音效；
  - 进入结算 2：光效峰值后收束，转入奖励结算内容（Giggles 数量翻动增长、顶栏余额补间上涨）。
- 结果页动效：光效收束后转入结果页；横幅「YOU WIN」弹入；金币奖励爆闪并飞向右上余额（补间上涨）；数据条依次淡入；Back / Play Again 上滑出现。
- 按钮：**Back → 返回 Arena Hub**；**Play Again → 直接重新匹配开新一局（主 CTA）**。设计稿另有一个 `Play Again` 状态，注「**点击 TTS「明天再来」提示，不进入对战**」。
- ⚠️ 冲突 / 未定义：
  - 原文「胜利页展示 YOU WIN 与平局发 Giggle x 20」——胜利和平局都发 20？平局也显示 `YOU WIN`？
  - **取消消耗后每局还能赢 20 Giggles，等于玩游戏净产出 Giggles**，是否有每日上限未写；而 `Play Again`「明天再来」状态暗示存在每日次数上限，但正文没有任何次数规则。
  - 奖励 20 是本期新增还是原有（「结算页不变」），对照组是否也发，未写。

### 4. 游戏大厅游玩数（假数据）
- 游戏大厅**所有推荐位卡片（含 Hot 卡）**的游玩数都按这套规则展示：**按日期算出来的配置值，不读真实埋点**。
- 公式：**`N = base[game] + rate[game] × D`**
  - **D：自 2026-08-22 起的天数，按 UTC+8 自然日计，08-22 当天 D=0**；
  - **每天 00:00 重算一次，日内不变**；
  - **base 和 rate 写死在配置里，不随机**。
- 各游戏数字故意收窄在同一量级：推荐位并排展示且 Hot 随机轮换，哪个游戏都要看起来像热门；**新上线游戏按同档位补一组 base / rate**。
- **三条底线**：① **数字只能涨**（今天 13.9k、明天 12.1k 就穿帮）；② **同一天同一个值**（纯日期函数，不用客户端随机数，不依赖本地存储）；③ **增速每天一百多，不做日内跳动**。

**配置值（内嵌表 RkuARp）**
| 游戏 | base | rate（/天） | 10/22 展示值（D=61） |
|---|---|---|---|
| Word Battle | 5,200 | 185 | 16.5k |
| Name Matching | 5,100 | 180 | 16.1k |
| 抢答游戏（英文名待补） | 5,000 | 178 | 15.9k |
| Word Fishing | 4,900 | 172 | 15.4k |
| Memory Master | 4,800 | 170 | 15.2k |
| Listen & Run | 4,700 | 166 | 14.8k |
| Word Space | 4,600 | 163 | 14.5k |
| 单词PK无尽模式（英文名待补） | 4,500 | 160 | 14.3k |
- 校验：Word Battle `5200 + 185 × 61 = 16,485` → `16.5k`，与表一致。

**数字格式化（内嵌表 9ailWh）**
| 区间 | 显示规则 | 举例 |
|---|---|---|
| < 1,000 | 整数 | 842 |
| 1,000 – 99,999 | 一位小数 + k | 3.2k / 13.9k |
| ≥ 100,000 | 整数 + k | 128k |
| ≥ 999,000 | 封顶 | 999k |
- 按当前 rate，三年后约 25 万，显示 `254k`，不会碰到封顶。
- ⚠️ 图 1 推荐卡显示 `13,9k`（逗号作小数点），与格式表 `13.9k` 不一致，需确认印尼语等 locale 的小数分隔符是否随系统。
- ⚠️ 配置表 8 个游戏里**没有 V1.39 上线的「泡泡单词」**；「抢答游戏」「单词PK无尽模式」英文名待补。
- 测试点：D 的计算跨 UTC+8 零点要变化、设备时区非 UTC+8 时也要按 UTC+8；只在推荐位卡片展示，右侧网格卡片不展示游玩数。

### ⚠️ 待确认 / 测试关注点
1. **净产出 Giggles 风险**：实验组免费玩 + 胜利 / 平局发 20 Giggles，每日上限未写；设计稿 `Play Again` 灰态「明天再来」与正文无次数限制矛盾。
2. 「胜利页展示 YOU WIN 与平局发 Giggle x 20」句意不清（平局是否也是 YOU WIN 页）。
3. 「新用户」判定口径未写；老用户进实验后看到什么（是否仍扣费）需确认，两处入口（游戏大厅 / 聚合入口）分流结果必须一致。
4. 推荐位三种类型的去重、多人游戏是否参与排名推荐、「全国榜」国家口径未定义。
5. 游玩数配置缺泡泡单词；`13,9k` 与 `13.9k` 格式不一致。
6. 无埋点章节，核心指标（覆盖率、游戏点击率、人均次数）靠哪些既有事件统计未写。
