## 摘要

竞技场 PK 的**机器人对手生成规则**:匹配成功时服务端一次性生成机器人对象(昵称/头像/饰品 + **6 题逐题行为**),客户端本地回放;机器人分 **L1 陪练 / L2 普通 / L3 较强 / L4 劲敌** 四档,每档只有「答对概率 P + 答对用时区间 T」两组参数;**每局开局按连胜/连败/近 20 局胜率定档**,除 L1 防碾压兜底外**全程不看用户实时表现**。

> 原文开头声明:内容由产品描述需求后 **AI 生成**,如有错误请开发指正。范围**只覆盖机器人(对手生成)**,计分/题型/结果页见《随机 PK PRD》(= [竞技场（Arena）1.0](2026-08-11-竞技场-竞技场Arena1.0随机PK.md))。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 0. 引用的计分规则(与主 PRD 一致)

单题得分 = **20 ×(10 − 用时)**;前 2s 内答对计 **160**;最后 4s 内答对计 **80**;**末题 ×2**;答错 **0 分**;每局 **6 题**。

### 1. 机器人对象结构

匹配成功时**服务端**为本局生成:

```
Robot {
  nickname      // 从昵称资源池随机
  avatar        // 从头像资源池随机
  outfit        // 从饰品池随机 3 件(≤300 Giggles 的饰品)
  behaviors[6]  // 6 道题的逐题行为,开局一次性生成
}
behaviors[i] = { isCorrect: bool, answerTimeMs: int }
```

- **客户端拿到 `behaviors[6]` 后本地回放**:第 i 题开始计时后,到 `answerTimeMs` 时刻展示机器人作答动画;`isCorrect=true` 按计分规则加分并推进其进度条,`false` 不加分。
- **本局中机器人行为不再变化,不读用户实时表现**(唯一例外见 3.4 陪练档兜底)。
- 📌 这是**异步对战**的实现基础:整局对手数据开局就定死,弱网下也不需要实时同步。

### 2. 难度档位(4 档,服务端常量)

| 档位 | ID | P(每题答对概率) | T(答对用时,ms) | 答错时用时(ms) |
|---|---|---|---|---|
| 陪练 | **L1** | **45%** | 5500–8500 | 6000–9000(超时不答) |
| 普通 | **L2** | **60%** | 4000–7000 | 5000–9000 |
| 较强 | **L3** | **75%** | 3000–5500 | 4000–8000 |
| 劲敌 | **L4** | **88%** | 2200–4500 | 3000–7000 |

- 所有参数为**服务端常量,调整随服务端发布**(不发客户端版本)。
- **答错行为**:机器人在「答错用时」时刻做一次**错误作答动画**(选错项 / 未答),不得分。
- 用时区间均**均匀随机**取值。

### 3. 选档规则(每局开始时定档)

**3.1 输入**
- `streakWin`:用户当前 PK **连胜**场数;
- `streakLose`:用户当前 PK **连败**场数;
- `wr20`:用户**近 20 局 PK 胜率**(不足 20 局按实际局数;**一局没打过按 0.5**)。

**3.2 规则(自上而下命中即停)**

| # | 条件 | 本局档位 |
|---|---|---|
| 1 | `streakLose ≥ 2` | **L1 陪练** |
| 2 | `streakLose == 1` | L1 陪练(50%)/ L2 普通(50%) |
| 3 | `streakWin ≥ 3` **且上一局对手不是 L4** | **L4 劲敌** |
| 4 | `wr20 > 0.75` | L3 较强(70%)/ L4 劲敌(30%) |
| 5 | `wr20 < 0.45` | L1 陪练(30%)/ L2 普通(70%) |
| 6 | 其余 | L2 普通(70%)/ L3 较强(30%) |

- 规则 3 的附加约束:**L4 不允许连续出现两局**。
- **新用户**:第 **1 局固定 L1 陪练**;第 **2–3 局固定 L2 普通**;之后走上表。

**3.3 行为生成(开局一次)**

```
for i in 0..5:
  isCorrect    = rand() < P
  answerTimeMs = isCorrect ? uniform(T.min, T.max) : uniform(E.min, E.max)
```

**3.4 唯一的实时规则(防碾压兜底)**

- **仅 L1 陪练档生效**:回放到**第 4 题开始时**,若**机器人总分 − 用户总分 ≥ 300**,则**第 4/5/6 题的 `isCorrect` 强制改为 false**。
- **其他档位无任何实时调整**。

### 4. 硬性约束(违反即 bug)

1. **`answerTimeMs ≥ 1800ms`**,任何档位、任何题。
2. 除 3.4 外,**禁止根据用户本局表现修改机器人行为**(**禁止末题反超、禁止跟随放水**)。
3. **同一局内 6 题用时不得全部相等**(生成后校验,**全等则对第 2 题重新采样**)。
4. 昵称/头像资源池**不得直接使用真实用户资料**;使用预置资源池——**昵称池 ≥ 500 条(已过敏感词审核)**,**头像池 = 官方 Avatar 组合**。
5. **机器人身份对用户不暴露**(无"机器人"标识);**埋点中必须带真实档位**(对应主 PRD 的 `robot_level` = l1/l2/l3/l4)。

### 5. 结果与状态更新

- 本局结束按**总分正常判胜负**(无特殊逻辑)。
- 更新 `streakWin` / `streakLose` / `wr20`;**平局:两个 streak 都清零,计入 wr20 分母,胜场不变**。

### 6. 边界情况

| 场景 | 处理 |
|---|---|
| **用户中途退出** | 本局作废:**不计胜负、不更新 streak / wr20**;**计一次当日 PK 次数**(防反复退出刷对手) |
| **用户某题超时未答** | 该题用户 0 分,**机器人行为照常回放** |
| **本局题数因词库不足 < 6** | 行为数组**按实际题数生成**,**末题 double 作用于最后一题** |
| **断网 / 杀进程** | 本局作废:**不计次数、不计胜负、不更新 streak** |

- ⚠️ **与主 PRD 冲突(已入待确认)**:主 PRD 写「进入后台或强制杀 App 按中途退出处理,**扣除 PK 次数**」;本篇写「断网/杀进程 **不计次数**」。两处对**杀进程是否扣次数**的口径相反,必须确认后再定用例预期。
- 📌 主 PRD 的埋点 `pk_battle.status=exit` 带 `exit_question_index`,与本篇「中途退出计一次当日次数」配套;而断网/杀进程按本篇不计次数、也未定义上报路径,**是埋点缺口**。

### 关联依赖(回归注意)

- **主 PRD = [竞技场（Arena）1.0 随机PK](2026-08-11-竞技场-竞技场Arena1.0随机PK.md)(V1.35.0)**:计分、题型、结果页、每日 10 次上限、扭蛋进度均在那篇;本篇只管对手生成。
- **1.36 换真人后本篇失效范围**:主 PRD 的「本期记录数据」表(`is_complete` / `is_abnormal` / `rule_version`)是真人回放的地基,**`rule_version` 改版后旧局不再回放**——机器人档位参数若调整,需同步考虑是否影响 `rule_version`。
- **昵称池敏感词审核**与同版本 [排行榜细节优化](2026-08-11-排行榜-排行榜细节优化.md) 的**昵称审核机制**(中英印三语词库)应共用同一套词库,避免机器人昵称命中真人昵称的禁用词。
- 机器人 `outfit` 从 **≤300 Giggles 的饰品池**随机 3 件,与 [奖励中心 / 商城购买](2026-07-13-奖励中心-新增购买服装和家具.md) 的服装价格体系耦合:**商城调价会改变机器人可穿戴范围**。
- 机器人 Avatar 组合依赖 [奖励中心2.0虚拟形象装扮](2026-06-30-奖励中心-奖励中心2.0虚拟形象装扮.md) 的官方形象资源。
