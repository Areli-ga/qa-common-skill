## 摘要

V1.31.0 对现有「App Feature AB Testing」后台系统(承载 Feature Flag / 灰度 / AB 分流)做 4 项优化:**① 从"事件级 AB 标签"改为"用户级公共属性"分流**(解决漏埋断链 + 看板配置繁琐)、**② 加 Layer 实验层管理实验关系 + 支持多分支(多 variant)**、**③ 多分支运行中改规则标准化**、**④ 区分 `not_in_experiment` 未命中用户**(避免 control 组污染)。产品 Owner: Leah。⚠️ 这是 **AB 平台本身的改造**(区别于 taxonomy 中「终身学员计划/AB实验分流」的业务用法)。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 需求 1 · 事件分流 → 用户属性分流
- **核心机制**:自研 AB 系统返回分组结果那一刻,立即调神策 `registerSuperProperties`(**h5 用 `registerPage`**)把分组写入**用户公共属性**;之后该用户所有事件**自动携带**,无需逐事件传。`启动有游客 uid → 启动神策公共属性(传 id+分组)→ 后续事件带 AB`。
- **神策双 ID**:`distinct_id`(App 首次启动 SDK 自动生成) / `login_id`(注册时 `sa.login()` 传入);接口入参 `guest_id / user_id / device_id` 都传过去,ID 优先级与实现由开发定。
- **核心要求(测试重点)· 身份变化分组不变**:
  - 游客→注册新用户、已注册新设备登录、卸载重装后登录、跨设备使用 → **实验分组均保持不变**。
  - 一台设备多账号登录 → 神策按 `login_id` 区分,实验分组**按各自 `user_id` 判定**。

### 需求 2 · Layer(实验层)字段
- **Layer = 一组业务相关 Feature 集合**,仅做业务归属标签,**本期不做强校验**。
- 示例 5 个 Layer:`onboarding`(新用户引导)、`course`(课程内容)、`homepage`(首页)、`reward`(奖励体系)、`default`(未分类)。
- **Layer 规则(测试重点)**:同 Layer 内 Feature **默认互斥**(同时生效会互相干扰,建议同层同时只存一个);不同 Layer **正交**,可同时命中、独立分流、可交叉对比(如新用户流程 × 奖励中心)。
- 列表页:新增 **Layer 列 + 按 Layer 筛选**。New/Edit Feature 弹窗:新增 **Layer 必选下拉**,选中后实时显示同层 Feature(Key+Description);**仅提示风险不阻止创建**;新增 Layer 走 admin 发版。

### 需求 3 · 多分支规则(Rules 弹窗)
| 操作 | 后端处理 |
|---|---|
| **调整流量比例** | 已分组用户保留原身份;新进入按新比例分配 |
| **增加新分支**(填 variant 标识如 `treatment_v3`,总和=100%) | 已分组用户保留原标签(不被切走);新进入按新比例分到所有分支;⚠️ **首次未命中用户调整后可能再次分组**;新分支从加入时间起累积数据 |
| **关闭某分支(比例调 0%)** | 已命中该 variant 用户保持原分组、功能继续;新进入不再分到;其他 variants 按相对比例分配;用户数停增、历史保留 |
| **关闭整个实验(Delete)** | 已命中 `treatment_*` 用户功能回退=对照组;control 不变;Feature 停止生效;神策 `abt_xxx` **保留最后写入值**(历史不删) |

### 需求 4 · 区分未命中实验用户(两层命中判定)
- **第一层 · 实验范围 Scope**:过滤规则 `country / internalStaff / channel / registerTimeAfter` → 决定哪些用户被实验影响。
- **第二层 · 分组规则 Variant**:百分比规则 `percent_guest / percent_normal / time_range` → 范围内用户分到哪组。
- **variant 三态(测试重点)**:
  - `treatment` = 实验范围内 + 命中百分比;
  - `control` = 实验范围内 + 未命中百分比;
  - `not_in_experiment` = **不满足过滤规则、被排除在实验外**。
- **判定顺序**(同现有规则引擎):白名单 → 实验范围 → 百分比(`whitelist / out_of_scope / rule`)。
- 返回:所有当前生效 Feature(含 `not_in_experiment` 用户)。**性能:P95 < 100ms,用户级缓存 5–10 分钟**。

### 字段与神策影响(测试重点)
- 字段:`abtestnewuser128`(旧,写死)→ **`abt_{layer}_{标识}`**(新),值形如 `treatment:layer:rule`(例 `abt_onboarding_first_screen = "treatment:onboarding:rule"`)。
- **新老看板分离**:老 Feature 看板字段不变继续用;新 Feature 按新规范建;**跨改造时间点同一实验不可直接对比**(分两段)。
- **历史数据断层**:改造前用户档案无 `abt_xxx`,改造后第一次启动 App 才写入。
- **PM 查数必加过滤(关键)**:神策分析分组属性选 `abt_{feature_key}`,**必须加「不包含 `not_in_experiment`」**,否则 control 组被污染;排除内部员工加「不包含 `:whitelist`」(两者可叠加)。
- **数据迁移**:双轨制 + 时间分界,**零迁移成本**——老实验用老字段看板,新实验全走新方案,不跨期对比。

### 上线范围
- 1.31 的需求都按此 AB 方案测:**首页路径、商店购买、故事书、新课程分支**。
