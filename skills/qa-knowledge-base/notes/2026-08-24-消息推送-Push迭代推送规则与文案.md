## 摘要

V1.37.0 重做 Push 触达：**现有推送全部改为游客也推**（此前排除游客导致触达不到大量用户）、推送时间统一为**用户本地 19:00 或用户自定义提醒时间**；每日正学提醒改为**五级优先级取一条**（P1 连胜特殊节点 > P2 小麦 > P3 故事书 > P4 Giggle TV > P5 课程类）；**印尼地区当地 14:00 单独推儿童兴趣内容**；挽留召回改为**缺席 day2 起（14:00 + 19:00）、day3–day7 每晚 19:00**；并下掉连胜保护卡相关 push。

### 1. 需求背景

- 目前线上的 push **触达率低**，技术做了对应优化，**1.36 会先上**。
- **游客不下发 push，导致触达不到大量用户。**

### 2. 推送规则调整（本期最大变更）

- **现有的推送全部修改为「游客也推送」。**
- 推送时间：**用户本地 19:00 或自定义提醒时间**。
- 原有「正学提醒」规则（作为对照记录）：用户本地 19:00 或自定义提醒时间、**排除游客**、今天没学、昨天学过；**七选一取最高优先级，每人每天 1 条**；每档有 3 到 4 个文案随机选（**P1、P5 会跳过数值为 0 的文案**）。
- **游客模式下，用户选择关闭授权弹窗，下次在其他规则遇到时依然弹出，让用户授权。**
- 原文注：**本期会增加任务、小麦**（进正学提醒的候选池）。

### 5. 待确认项

1. **游客推送的落地问题**：改成「游客也推」但推送时间是「用户本地 19:00 **或自定义提醒时间**」—— **游客没有登录、没有设置中心里的提醒时间**，自定义时间对游客如何取值？另外游客的「昨天学过 / 昨日推送类型 / 连胜天数」等状态靠什么标识（游客 id？设备？）均未说明。
2. **反复弹授权弹窗无频控**：「游客关闭授权弹窗后，下次在其他规则遇到时依然弹出」—— 每天最多弹几次、总上限、冷却期全无。且这与 V1.37《任务体系》P3「打开消息通知」任务的授权弹窗、既有 `app_popup_push_show`／`app_popup_push_request` 的 `scene` 枚举（`locklesson` / `afterregister` / `tasks`）如何协同、会不会连弹，需一并定。
3. **两套优先级编号冲突（必须先定）**：2.2 开头写旧口径「**P1 新关卡解锁 > P2 连胜里程碑 > P3 关卡进度 > P4 单元进度 > P5–P7 单元解锁节奏**」，而「每日正学提醒」又定义「**P1 连胜 > P2 小麦 > P3 故事书 > P4 Giggle TV > P5 课程类**」。同一节里两套 P1–P5 含义完全不同，本期以哪套为准。
4. **新人引导与 19:00 全员推的互斥关系未说明**：原则第 3 条把「新人引导」列入「命中后当天不推课程学习 push」，但新人引导本身是独立 AB、时点是 14:00 / 18:00 / 19:30（不是 19:00），两条链路如何判定「已命中」。
5. **「昨日推送不是 X」的判定在无推送日如何取值**：P1–P4 全都依赖「昨日推送类型」，若昨天用户未授权 / 未命中任何规则 / 推送失败，该条件算 true 还是 false，未定义。
6. **连胜倍数重叠未定义**：21 天同时是 3 和 7 的倍数、30 天同时是 3 和 10 的倍数 —— 走「带奖励」档还是「纯里程碑」档？（两档奖励表述不同，会直接影响用户是否真能领到 Giggles。）
7. **P5 课程类只有文案表、没有档位判定规则**：44 条文案分 8 个档位（新关卡解锁首日 / 单元主题预告 / unlocked / practice / review / unit_progress / 奖励即将领取 / 明确行动），但**什么条件命中哪个档位完全没写**；「30 天内不要重复」是按**文案条目**去重还是按**档位**去重也未定。另「单元主题跟进-practice」**只有 1 条文案**，与其他档位 3–10 条不对称，疑似漏写。
8. **旧规则里的「跳过数值为 0 的文案」在新表中失效风险**：原规则写「P1、P5 会跳过数值为 0 的文案」，新表里带数值的变量有 `${streak_days}` / `${progress}` / `${lessons_left}` —— 新的 P1/P5 是否仍执行这条兜底、`${lessons_left}=0` 时怎么办，未说明。
