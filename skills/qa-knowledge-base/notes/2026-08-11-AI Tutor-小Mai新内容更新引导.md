## 摘要

V1.35.0 给小Mai 的新内容做主动引导:对**历史访问过小Mai、且上次登录后有内容更新**的用户,在**主对话页岛屿**和 **Scene list 卡片**上加**闪闪发光动画** + **完成每日猜词游戏后的语音提示**,并配一套 **Admin 手动推送**(按 user ID + 模板发送、点击直达并跳过每日单词复习)。目标:新内容流量 100% 覆盖。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 0. 背景与目标

- 现状:**无任何提示时老用户会自发探索新内容**(见 07/06 King's Ring 上线数据对比),但**新内容覆盖率不足**,更新发挥不了最大价值。
- 内容更新频率:**1 周 1 节新内容**。
- **目标:新内容流量 100%**。
- 产品 Owner:**Libin**;优先级:**中**;Figma `1.35.0` node `44116-130940`(与破冰仪式同一 node)。

### 1. 目标用户(触发条件)

**同时满足**:
1. **历史上访问过小Mai 的用户**;
2. **距离上次登录小Mai,有内容的更新**。

### 2. 需求清单

| 序号 | 需求 | 状态 |
|---|---|---|
| 1 | **应用内提醒**:小Mai 主动引导(语音)+ 视觉引导(闪光) | 本期 |
| 2 | **应用外通知** | **待定** |

### 3. 应用内引导(4 处 + 1 项布局)

**3.1 岛屿下场景的布局紧凑一些**
- 确保在 **mobile 上第四个卡片也露边**(暗示可横向滚动),**范围为所有岛屿的场景列表**。

**3.2 主对话页面 · 语音提示**
- 时机:**在完成每日猜词游戏之后**,当有内容更新时给出语音提示。
- 文案:「**最近有内容更新哦,点击闪闪发光的岛屿试一下吧!**」
- **内容更新的优先级高于普通的语音提示**。
- ⚠️ **待讨论(原文标注)**:若按场景化设计,应具象到某一个岛屿,如「我听说 {island.name} 最近完成了一个新的建设,快去看一下吧。」——**那就需要定义不同岛屿的优先级**,本期未定。

**3.3 主对话页面 · 视觉提示**
- 有内容更新的**岛屿出现闪闪发光的动画提示**。
- **点击完之后,再次访问主对话页面,该岛屿的动画提示消失**。
- **支持多个岛屿同时亮,逐个灭**。

**3.4 Scene list 页面 · 语音提示**
- 时机同上(完成每日猜词游戏之后)。
- 文案:「**最近有新的游戏加入,找找闪闪发光的试试看吧!**」

**3.5 Scene list 页面 · 视觉提示**
- 有内容更新的**卡片出现闪闪发光的动画提示**。
- **点击完之后,再次访问场景列表,已被点击的卡片动画提示消失**。
- **支持多个卡片同时亮,逐个灭**。

📌 **"灭"的判定统一为「点击过 + 再次进入该页面」**,即**当次页面内点击后不会立刻消失**,要等下次进入才消失 —— 测试要按这条验,不能按"点完即灭"。

### 4. 消息通知(推送)

- 面向**曾经使用过小Mai 的用户(子账号)**,在**内容更新发布之后定时发送**。
- **文案**:「{island.name} 新增了一个有趣的地方,快去看看会发生什么吧!」
- **Icon**:**主 icon 为小Mai 头像**,**次 icon 为 giggle academy icon**。
- **链接行为**:点击**打开主对话页面**,**跳过每日的单词复习环节**,**直接播放对应的文案语音提示**。
- **Admin 配置**:输入 **user ID(子账号 id)**、选择模板、执行发送;支持:
  - **多语言**;
  - **推送时间:立即 / 用户本地时间**;
  - **数据回收**。
- ⚠️ 本期是**按 user ID 手动发送**,非自动圈选人群 —— 与需求清单里「应用外通知:待定」并存,**本期到底发不发需确认**。

### 5. 数据埋点

原文以 JSON 给出,为**扩展已有事件属性**(`_action: extend_properties`),不是新增事件:

| 事件 | 新增属性 | 类型 | 必填 | 显示名 |
|---|---|---|---|---|
| `StartTalkScene` | `is_new_content` | Bool | **是** | 本场景对该用户是否为新内容 |
| `EndTalkScene` | `is_new_content` | Bool | **是** | 本场景对该用户是否为新内容 |

- 更新历史:**2026-07-22 埋点修改,Start/End 各加 `is_new_content`(Bool)**。
- 📌 `is_new_content` 是**按用户维度判定**("对该用户是否为新内容"),不是内容的绝对新旧 —— 同一场景对不同用户取值可能不同,测试要覆盖"老用户已看过 vs 未看过"两种。

### 关联依赖(回归注意)

- **同版本 [小Mai的新用户入场破冰仪式](2026-08-11-AI%20Tutor-小Mai新用户入场破冰仪式.md)** 与本篇共用同一 Figma node,且都改**主对话页的首次语音**:破冰仪式面向**新用户**、本篇面向**老用户**,**两者互斥条件要验**(新用户不应收到"内容更新"提示)。

- **Scene list / 岛屿场景**见 [Mai场景内口语对话课](2026-07-13-AI%20Tutor-Mai场景内口语对话课.md);本次改了**场景列表布局(第四张卡露边)**,影响所有岛屿的列表页。
