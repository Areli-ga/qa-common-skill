## 摘要

V1.35.0 给 M Town Talk 场景对话课补上**关卡选择页**替代原来简陋的完成页,并开放**重玩自选角色**:**首轮严格走四步流程**(甲方旁观 → 甲方练习 → 乙方旁观 → 乙方练习)不变,**完成首轮后**由关卡选择页驱动「玩完 → 选择甲方/乙方 → 再玩」的循环;**二次访问已完成首轮的用户直接进选择页**,未完成的仍从中断处继续严格流程。

⚠️ **版本**:文档「版本号」字段写「**待填,来源于产品规划迭代 Roadmap**」,Figma 为 `1.35.0`;按主人给的 **V1.35.0** 入库。产品 Owner:**Libin**;优先级:**中**。

## 功能信息(逻辑 / 状态 / 边界 / 字段)

### 0. 背景与目标

- **问题**:一局结束后**只有一个简陋的完成页,没有承接**;用户**没有切换角色的权利**,只能按 AI 预设顺序推进(甲方旁观 → 甲方练习 → 乙方旁观 → 乙方练习),**重复游玩时缺乏自主性**。
- **数据**:07/13《M Town Talk 上线 2 日内数据复盘(07/11–12)》—— 用户在 **tutorial 阶段流失率 50%–60%**。
- **目标**:**首次严格、重玩自由**;**承接完整**——用关卡选择页形成「玩完 → 选择 → 再玩」循环,提升重玩率。

### 1. 范围

**范围内**:定义关卡选择页(可选扮演甲方/乙方)、定义其**触发场景(何时出现、何时不出现)**、重玩流程编排、进入方式与选择行为的埋点。

**范围外(本期不做)**:
- **首次流程本身的改动**(仍按《Mai 场景内对话》四步编排严格执行);
- 新增场景 / 新对话内容(本期只做**流程与选择能力**);
- **旁观 / 练习视角的自由选择** —— 本期只开放甲方/乙方角色选择;**「重玩默认进练习视角」原文标注待确认**。

**依赖与前置**:依赖《Mai 场景内对话》的**角色定义**(甲方/乙方**随场景换皮**,如超市售卖 = 顾客 / 店长);**系统已记录用户在该场景的完成状态**(首轮四步是否完成、各角色是否玩过)。

### 2. 核心流程

**首轮游玩(严格流程,不变)**
```
进入场景 → ① 甲方旁观 → ② 甲方练习 → ③ 乙方旁观 → ④ 乙方练习
   ↓ 完成
[关卡选择页](替代原完成页):展示 甲方 / 乙方 两张角色卡 + 完成状态
   ↓ 用户选择一方
直接进入该方练习(重玩)→ 结束后回到关卡选择页,形成循环
```

**二次访问(已完成首轮)**
```
进入场景 → 直接进入 [关卡选择页] → 选择甲方/乙方 → 开局 / 塞回记忆 → 完成后回到 [关卡选择页]
```

**二次访问(未完成首轮演示环节)**
```
进入场景 → 从上次中断处继续严格流程(不出现关卡选择页)
```

### 3. 流程文案(三语)

**首轮完成 → 关卡选择页**(AI 给出鼓励 + 邀请再玩):
```json
{"completionGuide": {
  "zh": "你做得真棒!还想再玩一关吗?",
  "en": "You did a great job! Want to play another round?",
  "id": "Kamu hebat sekali! Mau bermain satu ronde lagi?"
}}
```

**二次访问(已完成首轮)进入选择页**:
```json
{"zh": "我们来玩过家家吧!今天你想扮演谁?",
 "en": "Let's play pretend! Who do you want to be today?",
 "id": "Ayo bermain pura pura! Hari ini kamu mau menjadi siapa?"}
```

### 4. 关卡选择页元素

| 元素 | 规则 / 逻辑 |
|---|---|
| **角色卡 · 甲方** | 展示 **NPC 的角色头像**、角色形象与名称(**随场景换皮**,如超市 = 顾客);**点击进入扮演甲方的练习对话** |
| **角色卡 · 乙方** | 同上(如超市 = 店长);点击进入扮演乙方的练习对话 |
| **AI 引导** | Mai 用一句话引导选择(如「这次你想当顾客还是店长呀?」),**遵循母语引导与非功能性表述铁律** |
| **返回 / 退出** | 可退出场景返回上级页面 |

### 5. 触发矩阵(测试直接按此表覆盖)

| 触发场景 | 是否出现选择页 | 说明 |
|---|---|---|
| 首次游玩全程 | **不出现** | 严格四步流程期间**不可切换角色** |
| 玩完一局游戏后 | **出现** | 替代原完成页,承接"再玩一次" |
| 二次访问(**已完成**首轮) | **出现** | 进入场景**直达选择页** |
| 二次访问(**未完成**首轮) | **不出现** | 从**中断处**继续严格流程 |

### 6. 规则

- **角色选择只影响用户扮演哪一方**;对话内容、组件与铁律沿用《Mai 场景内对话》定义。
- **重玩默认进入实战,不再提供「再看一遍演示」入口**。
- **系统记住用户最近一次选择,下次进入选择页时默认高亮**。

### 7. 数据埋点

| 事件名称 | 触发时机 | 参数 | 说明 |
|---|---|---|---|
| `MaiRoleSelectEnter` | 进入关卡选择页 | `scene_id`、`entry`(`game_end` / `revisit`) | 进入方式:玩完游戏进入 / 二次访问进入 |
| **`mai_role_start_chat`** | 关卡选择页开始玩 | `scene_id`、`role`(`party_a` / `party_b`) | 选择分布,观察两方受欢迎程度 |
| `RoleSelectExit` | **未选择直接关闭 / 退出** | `scene_id` | 选择页流失 |

- 修订记录 **2026-07-22:修改角色选择埋点为 `mai_role_start_chat`**。
- ⚠️ **三个事件三种命名风格**:`MaiRoleSelectEnter`(大驼峰带 Mai)、`mai_role_start_chat`(下划线带 mai_)、`RoleSelectExit`(大驼峰**不带 Mai**)。同版本 [破冰仪式](2026-08-11-AI%20Tutor-小Mai新用户入场破冰仪式.md) 的修订记录也要求「埋点重命名,增加 `mai_` 前缀」——**本篇是否也要统一改名需确认**。
- 数据观测:选择页**进入→开局转化率**、**重玩率**、**甲乙两方选择分布**、**选择页流失率**。
