## 摘要

V1.37.0 给「邀请同桌」加社交深度：发起页改为**每 3s 切换的四条奖励轮播**、分享从「只有海报」改为**WhatsApp / 微信 / 复制链接三渠道分享 H5 邀请链接**；组队成功页把中间的 **VS 换成宝箱**（双方都完成同一 Level 后可点开、**一人获得 50 Giggles**）、进度条改为当前 Level 进度，底部新增**「我 / 同桌最近在玩的 3 个游戏」并可挑战对方最高分**（复用 PK 动画与挑战课结局动画）。

> 本篇即 V1.37《游戏大厅 2.0 小游戏》里提到的「Study Buddy 单开需求」本体。
>
> ⚠️ **原料补抓说明**：本篇有 **1 个内嵌 Sheet（`block_type=30`）**，装着**全部 6 个埋点定义**（正文「数据埋点」标题下是空的）。已用 `sheets/v2` API 补抓（code=0）落 `raw/邀请同桌-1.2-支持游戏挑战/sheets.json`。

## 功能信息（逻辑 / 状态 / 边界 / 字段）

### 1. 需求背景与现状漏斗

- 「目前上线了邀请同桌效果还可以，**虽然组队链路长，但是组队成功后留存和学习数据有明显提升**。」
- 现状漏斗（图 1）：

| 环节 | 数据 |
|---|---|
| 发起页 | **日均访问 2600**，占活跃用户 **1/10**；**50% 的人点击发起** |
| **卡点** | **登录 —— 90% 的用户流失** |
| Share 页 | **发起成功占比 4%** |
| 组队成功 | **107 人**；**次留 / 7 留 = 70.1% / 36.8%**；**日均完课深度 12 节** |

### 2. 发起页面改造

**① 奖励轮播图（替换原静态图）**
- **每 3s 切换一次**，共 4 条：

| 主题 | 文案 |
|---|---|
| 组队能看到对方的打卡数据 | `Team up and never learn alone!` |
| 套装奖励 | `Once teamed up, you both unlock an outfit!` |
| 开宝箱 | `Finish a level together, crack the chest!` |
| 挑战好友的游戏分数 | `Challenge your studybuddy and top the score!` |

- 设计稿（图 3）：轮播卡带**分类标签 + 计数**（`Level Reward 3/4`、`Word Battle 4/4`）；页面标题 `Invite a studybuddy to study together!`，副标 `Cheer each other on and see who learns more!`，按钮 **`Invite my friend` / `Join a friend`**。

**② 分享渠道改造**
- **支持分享到 WhatsApp 和微信以及复制链接。**
- 点击 WhatsApp 或微信 → **唤起选择好友发消息页面，选择好友后分享一个 H5 链接**给对方。
- 点击复制链接 → 复制成功后 **toast「已复制」**，用户可以粘贴 H5 链接发送给好友。
- ⚠️ **需要原生修改分享组件，目前全是海报的方案。**
- 分享弹窗（图 6）：标题 `How your friend joins ?` + 三步说明（① `Opens your link & copies the code` ② `Download Giggle Academy & sign up` ③ **`Enters it in Deskmate — on the Home page`**）+ **`Pairing code` 六位邀请码（可一键复制）** + `Share link to:` **WhatsApp / Wechat / Copy link**。

**③ 分享链接落地页**
- 点击分享的链接，**直接进入复制邀请码和下载界面**。
- ⚠️ 原文只写了一句「**微信分享卡片和 WhatsApp 的文案！**」，**没有给具体文案**。
- 落地页（图 7）：`{昵称} wants you as a study buddy, learn English together!` + `Copy the code for faster pairing` + 六位邀请码（点击后 toast **`Copied to clipboard`**）+ `Team up with {昵称} in 3 steps`（Copy the pairing code / Download Giggle Academy & sign up / Open Deskmate on the home page, enter the code）+ **`Team up to pick a limited-edition outfit`**（两套限定服装预览）+ 底部固定 **`Download App` / `About us`**。

**④ 受邀者链路：本期不做修改。**

### 3. 组队成功页改造

| 位置 | before | after |
|---|---|---|
| 中间 | **VS** | **宝箱** —— 双方都完成**同一个 Level** 后变成**晃动可点击**状态；开宝箱后**一人获得 50 Giggles** |
| 进度条 | 当日是否完成 | **当前 Level 的进度条**，计算规则同学习中心：**已学习课程数 / 总的课程数** |
| 底部 | — | **【我】和【同桌】最近在玩的 3 个游戏**，展示对方的分数，点击后可以对对方发起挑战（挑战对方最高分） |

- ⚠️ 原文自带两个待定：**「不一样的 level 如何处理」**、**「开出来的动画是否可以直接用扭蛋的动画」**。
- **支持挑战的小游戏（5 个）**：单词 PK 无尽模式 / 点名连连看 / 托盘打包台 / 钓鱼钩卡 / 听音跑酷。
- **游戏展示规则**：游戏名、游戏图标、最近玩耍的时间 —— **6 小时内用具体的 `x hours ago`，超过 6h 展示 `recently`**。
- 设计稿补充（图 10，正文未写）：
  - 左右分屏（`You` 绿 / `{同桌昵称}` 蓝），各自 **`Lv 1` + 百分比进度条**；
  - 中间宝箱带文案 **`Complete Lv1 unlock reward`**；
  - 下方 `My week` / `{同桌}'s week` 卡片，右上角 **`14 days together`**，一行 Su–Sa 打卡圆点（完成绿勾 / 未完成灰勾 / **今日红色标记**）；
  - 游戏卡片展示**排名徽章（No.1 / No.2）或时间（`1 hour ago`）**；
  - **右上角 `Leave Team`（退出组队）**。

### 4. 发起挑战 → PK → 结算

- 发起挑战后进入 **PK 页面，复用目前 PK 的动画，但是顶部展示游戏名称**（图 11：`Word Battle: Who knows more?` + VS + 双方昵称）。
- **右上角展示同桌的最佳成绩**；⚠️ **「如果比较难，可以不展示，直接在最后展示结果」**（本期做法未拍板）。
- 挑战结局：**复用目前挑战课的结局动画，背景直接用游戏的**；三态 —— **挑战成功 / 挑战失败 / 平局**（图 13：`VICTORY` + `You Smashed {同桌}'s High Score!`）。

### 5. 组队成功后的首页入口

| 场景 | 表现 |
|---|---|
| **复制验证码进入 app 时** | 左下角图标不变，**入口展示在任务旁边**（图 15：路径左下角「任务」图标与「宝箱」图标并排） |
| **组队成功后** | 展示**当前级别的宝箱**；进度展示**我和同桌中学习最慢的那个人的进度** |

### 6. 数据埋点（内嵌 Sheet `oEffR1`，6 个事件，均为客户端 / Event）

| 事件名 | 显示名 | 触发时机 | 触发位置 | 属性 |
|---|---|---|---|---|
| `studybuddy_invite_click` | 点击发起分享 | 活动页点击【发起邀请】 | 活动页 | — |
| **`deskmate_invite_share`** | 分享邀请（**2026/8/13 修改**） | 在发起弹窗点分享渠道 | 发起邀请弹窗 | `share_channel`：`whatsapp` / `wechat` / `copy_link` |
| `studybuddy_chest_click` | 同桌宝箱点击开启 | 双方完成同一 Level 后宝箱变为可点击，用户点击开启 | 组队成功首页-宝箱 | `reward_giggles`：数值（本次获得 giggles 数） |
| `studybuddy_pk_challenge_start` | 同桌 PK 挑战发起 | 在「我和同桌最近玩的 3 个游戏」列表点击某游戏，发起对同桌最高分的挑战 | 组队成功首页-游戏列表 | `game_name`：`word_pk_endless` / `naming_match` / `tray_packing` / `fishing_hook` / `listen_runner` |
| `studybuddy_pk_result` | 同桌 PK 挑战结果 | PK 挑战结束，结算页展示挑战成功/失败/平局 | PK 结算页 | `game_name`（同上）；`pk_result`：`win` / `lose` / `draw` |
| `studybuddy_entry_click` | 同桌入口点击 | 用户点击 App 首页的同桌功能入口图标 | App 首页-同桌入口图标 | `pairing_status`：`unpaired` / `paired` |

- ⚠️ **前缀不统一**：5 个 `studybuddy_*` + 1 个 `deskmate_invite_share`。

### 7. 待确认项

1. **三套叫法并存**：埋点里 `studybuddy_*` 与 `deskmate_invite_share` 混用；UI 上标题写 `Invite a studybuddy`、分享弹窗第 3 步写 `Enters it in **Deskmate**`、中文写「同桌」。上线前需统一（尤其埋点前缀，会直接影响分析口径）。
2. **原文自带的两个待定**：① **双方 level 不一样时宝箱怎么算**（宝箱条件是「双方都完成同一个 Level」）；② **开宝箱动画是否直接复用扭蛋动画**。
3. **宝箱 50 Giggles 的归属歧义**：「开宝箱后，**一人获得 50giggles**」—— 是每人各得 50、还是共 50 由一人得？**双方是否都要各自点开**？一方点开后另一方的宝箱状态如何同步？
4. **进度条口径两处不同**：组队成功页写「**当前 Level 的进度条**（已学课程数/总课程数）」，首页入口又写「进度展示**我和同桌中学习最慢的那个人**的进度」—— 同一个宝箱进度在两处含义不一致。
5. **微信分享卡片与 WhatsApp 文案缺失**：原文只有「微信分享卡片和 Whatsapp 的文案！」一句，无标题/描述/缩略图规格（对比同版本《游戏大厅》给了完整 Open Graph 规范）。
6. **背景数据点出的最大卡点没被解决**：漏斗显示「卡点：**登录，90% 的用户流失**」，但本期改的是轮播文案与分享渠道，**登录环节不在需求范围内** —— 发起成功率 4% 能否被本期改动拉起来，需产品确认预期。
7. **5 个可挑战游戏全部依赖《游戏大厅 2.0》上线**（单词 PK 无尽模式 / 点名连连看 / 托盘打包台 / 钓鱼钩卡 / 听音跑酷）。若游戏大厅延期或砍量，本篇挑战功能无从测起；两篇的提测顺序需绑定。
8. **挑战对局机制完全未定义**：是**异步挑战对方历史最高分**（类似竞技场真人回放）还是实时对战？**对方没玩过该游戏（无最高分）**时如何展示、能否发起？挑战**是否消耗 20 Giggles**（游戏大厅规定所有游戏统一 20/次）？挑战结果是否计入该游戏的全国/全球榜？
9. **「最近在玩的 3 个游戏」的取数与展示规则不全**：是否只统计这 5 个可挑战游戏、**不足 3 个时如何展示**、时间文案边界（正好 6 小时算哪种）、双方列表是否可能为空。
10. **「右上角展示同桌最佳成绩」本期做不做未拍板**（原文「如果比较难，可以不展示，直接在最后展示结果」）。
11. **设计稿里有正文完全没提的元素**：**`Leave Team`（退出组队）** —— 退出后宝箱进度、挑战记录、已获得的服装奖励如何处理，全无定义；**`14 days together` 与一周打卡圆点**也未在正文描述（是新增还是沿用既有）。
12. **受邀者链路「本期不做修改」与新增 H5 落地页存在衔接问题**：发起侧改成分享 H5 链接后，受邀者从落地页 → 下载 → 注册 → 在 Deskmate 输码，这条路径是否等同于旧链路、邀请码是否有有效期，需确认。
13. **无验收标准**；无分享失败、未安装 WhatsApp/微信、H5 链接失效、组队中一方注销/退出的兜底描述。
