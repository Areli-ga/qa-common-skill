## 摘要

V1.38.0 把 Hello 课的跟读换成**全 App 统一的标准跟读组件**（Max 左下头像领读 + 紫色边缘波纹 + 自动收音），并在孩子第一次遇到它之前插一段**开口引导小窗动画**教它「轮到我说了」；同时用**同一课程包内的 A/B**（kid ID 之和奇偶分桶）比较 Hello 课的两种开口形态：A 多朋友 3 次开口 vs B 原版单次开口。

## 功能信息（逻辑/状态/边界/字段）

### 基本信息与背景

- 产品 Owner：**Cloud**；优先级：高；**版本号 v1.38.0**；修订记录 2026-08-27「新增包内 AB 测试」。
- 背景数据：**Hello 课程首轮开口率只有 54.6%** —— 孩子在 App 第一个开口时刻近一半保持沉默；**第二轮自然回升到 70%**，说明「孩子看一轮就会，缺的是第一轮就看懂『轮到我说了』的信号」。
- 背景问题：Hello 课的跟读与 Color 等课程的**标准跟读组件**（Max 左下头像领读 + 紫色边缘波纹）**不是一套信号**，孩子在第一课学到的交互语言到 Color 课要重新认知。
- 背景决策：Hello 课该用哪种开口形态没有结论 —— 现调整版拆成三个朋友、孩子开口三次；原版只开口一次，更短更轻但少两次练习机会。**与其拍板，不如把两版一起做进课程包跑一次 A/B，组件与引导两组固定，只比内容。**
- 目标：① 全 App 只有一套「轮到你说」的信号；② 第一次遇到前用小窗动画教会它，并让 Hello 课角色动画更好懂；③ 用课程包内 A/B 定出 Hello 课的开口形态。
- ⚠️ **资源列表（UI 设计稿 / 动画文件 / 声音文件 / 其他资源）全部为空**，只标注了「（Google 网盘）」。

### 需求范围（2 项）

1. **课程 - Hello 课 / Colors1**：
   - Hello 课接入**标准跟读组件**（Max 左下头像领读 + 紫色边缘波纹 + 自动收音）；
   - **Hello 课 / Colors1 跟读前自动播放开口引导小窗动画**；
   - **Colors1 课中 VAD 未检测到开口导致语音识别失败，则重播 5s 精简版**；
   - **鹦鹉、Tom 动画优化**。
2. **课程 - Hello 课 A/B（课程包内）**：同一课程包内并存两版流程，kid ID 之和奇偶分桶，首次进课锁定，弱网/异常兜底不卡课，分桶属性 `hello_variant` 作为数据回收口径。

### A/B 两组定义

| 项 | **A 组 · 多朋友多轮开口（`a_multi`）** | **B 组 · 原版单次开口（`b_single`）** |
|---|---|---|
| 课程内容 | 现调整版：**鹦鹉 / Lily / Tom 依次入场，每人一轮，孩子开口 3 次**；末轮合庆 → 击掌 → 扭蛋 → 结算（**三张 Hello 录音卡**） | 换回原版流程，**孩子在课内只开口 1 次** |
| 角色动画 | **鹦鹉、Tom 重做动画后替换** | **原版动画不动** |
| 语音识别 | 标准跟读组件（本期改动点） | 标准跟读组件（本期改动点，**原版原本不是这套组件**） |
| 开口引导小窗 | 有，第一轮语音识别前 | 有，唯一一轮语音识别前 |
| 结算页开口次数 | **3** | **1** |

**变量控制**

| 变量 | 状态 |
|---|---|
| 标准跟读组件 | 两组相同（固定） |
| 开口引导小窗 | 两组相同，**同一支视频、同一 `guide_key`**（固定） |
| 识别引擎 / 阈值 / 分年龄档 | 两组相同 |
| 奖励结构（能量、扭蛋、结算） | **各自沿用本版原逻辑，不为了对齐而改** |
| 课程内容形态与角色动画 | **唯一自变量** |

### A 组一轮跟读的完整时序（以第一轮鹦鹉为例）

1. 鹦鹉从右侧飞入中央，和 Max 一起说 `Hello!`；紧接着**鹦鹉单独说 `Your turn, Say Hello!`**，然后 Max 与鹦鹉呈现**聆听姿势**。
2. **场上 Max 淡出**，语音识别组件（左下角 Max 头像的版本）调起，**左下角 Max 说 Hello**，然后进入聆听态；**紫色光波亮起，自动收音**。
3. **【首次】语音识别组件调起前画面冻结，弹开口引导小窗；播完关窗，光波亮起开始收音。**
4. 同 Hello 课当前处理，**无论用户是否读对都结束语音识别**；组件内读对读错反馈均按标准逻辑走；组件结束后走原逻辑发放开口奖励等。
5. 鹦鹉离场，Lily 入场（依次进入第 2、3 轮）。

### B 组时序

1. 原版流程照走，直到**唯一一次跟读回合**。
2. **【首次】语音识别组件调起前画面冻结，弹开口引导小窗；播完关窗。**
3. 语音识别组件调起：左下角 Max 说 Hello → 进入聆听态 → 紫色光波亮起，自动收音。
4. 同 A 组：**无论用户是否读对都结束语音识别**；组件结束后走原版原逻辑。
5. 原版后续流程与结算页照走，**结算页开口次数如实显示 1，不与 A 组对齐**。

### 开口引导小窗动画（交互规格）

| 项 | 规格 |
|---|---|
| 触发时机 | **Hello 课第一个跟读回合开始前**（朋友打完招呼、Max 头像弹出前） |
| 呈现 | **居中小窗卡片（约屏宽 70%，16:9）**，背景课程画面**冻结轻压暗**；**播放期间暂停语音识别组件以及 Unity 内容** |
| 时间轴 | **时长待定，不得超过 12s**；播完**自动关窗 → 0.5s 后 Max 头像弹出**开始第一轮 |
| 触发范围 | **仅在 Hello 课程与 Colors1 课程内的第一轮语音识别时触发** |

**引导动画分镜（给 Alice，AIGC 生成用）**

| 镜 | 时长 | 画面与动作 | 镜头 | 音频 |
|---|---|---|---|---|
| 1 语音识别组件调起 | ≤2.5s | 一台手机中播放 Hello 课画面，手机边上能看到少部分儿童手指；手机中语音识别组件调起，**Max 头像在左下角说 `Hello!`**，随后 Max 进入聆听态 | 手机几乎占满全屏 | Max `Hello!` |
| 2 语音识别开始 | ≤4s | 镜头从满屏手机**拉到能看到孩子拿着手机的侧视角**，**手机麦克风位置高亮**，孩子把嘴靠近麦克风 | 侧视角 | 高亮音效、孩子靠近音效 |
| 3 靠近大声说 | ≤1s | 孩子张大嘴说 `Hello!`；**彩色音波从嘴部飘向设备麦克风** | 侧面中景，小幅拉近到聚焦手机与孩子的嘴 | 童声清晰 `Hello!` |
| 4 识别成功 | ≤2.5s | 镜头拉回满屏手机，**语音识别组件识别成功的画面** | 全景 | 成功音效 |

> 分镜时长合计 ≤10s，与「不得超过 12s」的约束一致。

### 鹦鹉、Tom 动画优化

- 动画重做鹦鹉与 Tom 的动画后，**开发替换**（无更多规格）。

### 分桶规则

- **kid ID 级：ID 之和为奇数 → 命中 A 桶；ID 之和为偶数 → 命中 B 桶。**
- **课程标识：两版共用同一 `lesson_id` / `course_id`，只靠 `hello_variant` 属性区分。**
  - 原文强调：**不要拆成两个 `lesson_id` 或两个 `course_id`** —— 上次 pathway A/B 就是因为课程标识拆开，漏斗和留存要靠 `course_id` 反推，**口径脏且难对**。
- **首次进课锁定**；**弱网 / 异常兜底不卡课**。

### 数据埋点

| 事件 | 触发时机 | 参数 |
|---|---|---|
| `speak_guide_view` | 引导小窗曝光 | `guide_key`：`hello_speak_v1` / `Colors1_speak_v1` |
| `speak_guide_close` | 引导结束 | 无 |
| `hello_abtest` | 进入 Hello 课程时触发 | `group`：`a_multi` / `b_single` |

### ⚠️ 待确认（写用例前需拉齐）

1. **「kid ID 之和」的定义不明（最关键，直接决定分桶用例怎么写）**：是单个 kid ID 各位数字相加？还是账号下多个 kid 的 ID 相加？若是后者，**新增/删除 kid 会改变分桶结果**，与「首次进课锁定」如何配合？ID 若是 UUID 之类的非纯数字串又怎么算？
2. **「弱网/异常兜底不卡课」没有具体策略**：分桶接口失败时默认进哪一组？默认组是否上报 `hello_variant`？兜底后是否仍锁定？
3. **Colors1 的「5s 精简版」内容未定义**：分镜只给了完整版（≤12s，4 镜），精简版是完整版剪出来的哪几镜、是否单独出片、重播是否重新上报 `speak_guide_view`，全未写。
4. **重播规则只覆盖 Colors1**：「VAD 未检测到开口导致识别失败则重播 5s 精简版」只写在 Colors1，**Hello 课首轮无声时是否也重播**没写 —— 而 Hello 课首轮开口率 54.6% 正是本需求要解决的靶子。
5. **小窗是否只播一次、以什么维度记录**：写了【首次】和 `guide_key`，但**重学 Hello 课 / 换 kid / 重装 App 后是否再播**没定义；Hello 与 Colors1 是两个 key，是否各播一次也需明确。
6. **小窗能否跳过 / 中断**：`speak_guide_close` 无任何参数，无法区分「播完自动关」与「被中断」；文档也没写是否给关闭按钮、播放中点击屏幕会怎样。
7. **AB 两组奖励不等价**：A 组开口 3 次、B 组 1 次，且「奖励结构各自沿用本版原逻辑，不为了对齐而改」——**开口奖励、扭蛋、结算录音卡数量都不同**，留存对比会掺入奖励差异，需确认产品接受该混淆。
8. **开口率怎么算**：核心指标是「首轮开口率」，但埋点只有小窗曝光/关闭和进课分组三个事件，**没有开口成功/失败事件** —— 是否复用现有 `lesson_speech_recognition_*`（并按 `hello_variant` 拆分）需要明确，否则 A/B 无法结论。
9. **`hello_variant` 与 `hello_abtest.group` 两个名字**：分桶属性叫 `hello_variant`，埋点参数叫 `group`，取值都是 `a_multi`/`b_single` —— 是否为同一字段的两处叫法，是否需要作为用户属性长期上报，需确认。
10. **资源全部缺失**：UI 设计稿、动画文件、声音文件三项资源列表为空（只写「Google 网盘」），引导小窗为 AIGC 生成、鹦鹉与 Tom 动画待重做，**提测前需确认资源到位时间**。
11. **小窗时长「待定」**：只给了上限 12s 与分镜上限，最终时长未定；而「播完自动关窗 → 0.5s 后 Max 头像弹出」是硬时序，需要最终值才能验收。
12. **「暂停 Unity 内容」的范围**：小窗播放期间要暂停语音识别组件与 Unity 内容 —— 暂停期间的背景音乐、角色动画、计时器如何处理未写；若此时用户切后台再回来，冻结态如何恢复。
13. **鹦鹉/Tom 动画优化无验收标准**：只写「重做后替换」，没有对照标准或验收点。
14. **B 组「原版」的具体流程无文档**：B 组定义为「换回原版流程」，但原版流程本身在本篇没有描述，测试需要另找原版课程文档。
