## 唯一有候选的地方:抓取层

| | 优 | 劣 |
|---|---|---|
| **A. 自维护零依赖脚本** + `config-loader` 凭证 ⭐**选定** | 探针已跑通;零第三方依赖(守依赖红线);精确拿表格+图;能固化进流水线、能批量 | 飞书 API 变更要自己跟(逻辑很薄) |
| B. 依赖 `giggle:lark-docs` skill | 公司现成、复用凭证 | 交互式通用工具,不适合做 ingest 固定环;常用示例走 `raw_content` 会丢图 |
| C. 官方 SDK `lark-oapi` | 封装全 | 要装依赖、过重;AI 对裸 HTTP 比对 SDK 版本更熟 |

## 架构隐含、必须配套的三个点

1. **`taxonomy.md`(边 ingest 边长)**:功能模块清单 + 标签体系。**不预先穷举**——Claude ingest 时判断:新功能 → 新建一级模块;已属某模块 → 归为其二级;新模块追加回 `taxonomy.md`。⑤打标签 和 索引模块视图都读它,保证模块名统一。
2. **索引是 derived 数据**:脚本扫 notes 幂等重建。index 坏了不慌,一键重生成。
3. **Claude 是编排器**:①–⑦ 不写状态机,写进 SKILL.md 当规则,Claude 读着执行(fuxi 同款)。

## 已定的关键决策

- 凭证:走 `config-loader`
- 读图范围:**全读**(MVP 不做关键图筛选,先简单不漏)
- 抓取层:方案 A(自维护零依赖脚本)
- 功能模块:**边 ingest 边长**(不预先穷举;新功能新建一级、已有归二级,统一命名)
- 关联 ⑥(双向 `related`):**v1 就做**,不推迟
- 飞书接入:先**手动一篇篇丢链接**(单篇 ingest);批量需 wiki 空间读权限,暂缓(当前应用无权限,报 permission denied)
- ingest 触发:一次一篇

## v1 最简清单(能不用就不用)

```
要做:
1. Python 标准库(零第三方依赖)
2. 抓取脚本:正文 + 表格 + 下图(urllib + 飞书接口 + config-loader)
3. Claude:读图 + 提炼功能信息 + 打模块标签 + 检索综合
4. 存:Markdown + frontmatter,目录 raw/ + notes/ + index/
5. 索引脚本 → INDEX.md(模块 | 版本 | 标题 | 链接 | 一句话摘要)
6. 关联脚本:标签 + 模块/标题重叠打分,双向写 related
7. 检索:grep / ripgrep + 读 related 字段
8. SKILL.md:ingest + 检索规则
9. 凭证:config-loader

v2 再加:编译层(模块主题页)
坚决不用:数据库 / 向量库·RAG / 服务器 / 飞书 SDK / OCR
```
