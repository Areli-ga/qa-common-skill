## 一、进 — 东西从哪来

| 维度 | 内容 |
|---|---|
| 来源 | 飞书产品需求文档(wiki / docx),一篇一个链接 |
| 触发 | 手动丢链接,一次一篇(不定时、不自动拉) |
| 格式 | 飞书文档链接 → 加工成:结构化正文、保行列的表格、图片原图、图转文字 |

进来后走一条加工流水线(动作,非工具):

```
链接 → ①完整抓取(正文 + 表格保行列 + 图片)
     → ②下载所有图片留底
     → ③读图:把 UI 状态/流程图/字段表转成文字
     → ④提炼:带「功能模块」的结构化摘要 + 结构化功能信息(逻辑/状态/边界/字段)
     → ⑤打标签(功能模块标签 + 内容类型标签)
     → ⑥算关联:与已有笔记比对,双向写 related
     → ⑦落笔记 + 更新索引
```

关键:①必须保表格行列、②③必须把图变成文字——否则测试金矿(UI 状态、字段规则)会丢。

## 二、存 — 分几层、每层放什么

四层,生 → 熟排列。前三层 v1 就做,第四层 v1 只留空位。

### ① 原料层 raw(只读 · 事实来源)
飞书文档的完整保真存档:原文 + 表格(保结构) + 图片原图 + 原始链接 + 抓取时间。**只读、永不改**。AI 判断错了能翻回核对——数据上保险。

### ② 笔记层 notes(加工成品 · 一篇文档一篇笔记)
每篇需求 → 一篇结构化笔记,含:
- 所属**功能模块**、版本号
- 带模块的结构化摘要 + **结构化功能信息(逻辑/状态/边界/字段)**
- **图转文字**结果(UI 各状态、流程、字段表)
- 标签、`related`(相关笔记双向链接)、原链接、日期

### ③ 索引层 index(导航)
两个视图(测试场景的关键设计):
- **全库目录**:每篇笔记一行(标题 + 模块 + 摘要 + 链接)
- **功能模块视图**:`模块 → 该模块下所有相关笔记`。让"按模块查往期相关功能"直接走索引,不扫全库;也为 v2 编译层铺好聚合入口。

### ④ 编译层 wiki [v1 预留空位,v2 填]
功能模块主题页(同模块多篇合成一页"当前完整逻辑")。v1 不做,但分层结构先留好——v2 往上长,前三层一动不动。

## 三、取 — 谁取、何时取、什么形式

都是我、写用例前取,三种场景三条流:

1. **模块/关键词检索流** — "跟这个新需求相关的历史需求有哪些?"
   → 走索引(模块视图/关键词)→ **相关往期需求笔记列表**(标题 + 模块 + 摘要)。

2. **模块历史问答流** — "X 模块历史上有哪些功能/边界/坑?"
   → 读索引定位该模块所有笔记 → 跨多篇**综合** → 自然语言综合回答。

3. **新需求关联流(核心 · 最贴目标)** — 丢一篇新需求文档进来
   → 抓取理解 → 找相关往期功能 → **相关往期功能清单明细 + 该重点回归的点明细**(要"明细":每条带具体逻辑/边界,不只标题)。
   > 注:**回归点是「取」时现算的**——存笔记时无法预知未来需求,所以不在 ingest(④)时存,而由 Claude 在这一步拿"新需求 ✕ 历史功能信息"对比算出。

## 四、数据流 + 两条隐线

```
【进】                  【存】 只读 ↑ / 加工 ↓              【取】
飞书需求链接
   │(手动丢)         ┌────────────────────────────┐
   ▼                 │ 原料层 raw  原文+表格+图(只读)│
[抓取·下图·读图]──────►├────────────────────────────┤──► ① 模块/关键词检索
   │                 │ 笔记层 notes 摘要/功能点/     │       → 相关需求列表
[提炼·标签]──────────►│   图转文字/标签/related      │──► ② 模块历史问答
   │                 ├────────────────────────────┤       → 跨篇综合回答
[算关联]─────────────►│ 索引层 index 全库目录+模块视图│──► ③ 丢新需求
   │                 ├╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┤       → 相关功能明细
   └─往回织─►related  │ 编译层 wiki  [v2 预留·空]    │         + 回归点明细
     双向回写         └────────────────────────────┘
```

**隐线一 · v1 的往回织**:每进一篇新笔记,旧笔记的 `related` 也回写指向它——v1 的"往回织"停在**关联级**。v2 升级为**编译级**(回头重写模块主题页、标出新旧逻辑冲突)。

**隐线二 · 架构算两条**:
- **能长大**:预留编译层位置;笔记留"来源"字段(将来接 Figma/往期用例不推翻);标签体系可扩展。
- **不会塌**:原料层只读保真,错了能翻回;每步加工不覆盖原料,笔记可重新生成;索引可由笔记层重建。

## 五、v1 / v2 边界

| | v1(本期) | v2(以后) |
|---|---|---|
| 存 | 原料 / 笔记 / 索引三层 | 加编译层(模块主题页) |
| 往回织 | 关联级(related 双向回写) | 编译级(重写主题页 + 标冲突) |
| 输入 | 仅飞书需求文档 | 可扩展(Figma / 往期用例…) |
