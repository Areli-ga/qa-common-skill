# QA 测试用例知识库 · Skill

把飞书产品需求文档「编译」成结构化笔记,解决写用例时"往期相关功能找不全、历史逻辑遗忘、回归遗漏"。设计依据见 `docs/`(01 MVP / 02 架构 / 03 选型)。


## 启动步骤（先读）

1. 先读本文件，再读 `RESUME.md` 了解当前进度、已入库清单和待办。
2. 需要改知识库规则或目录约定时，先读 `AGENTS.md` / `CLAUDE.md`；规则调整先改文档，再改实践。
3. 脚本与数据都在本目录下，命令默认从 `qa-knowledge-base/` 目录运行。
4. 凭证由脚本自动从公司 config 拉取（需 VPN），或由环境变量提供。

## 常用命令速查

- **录入一篇**（用户给「版本 + 飞书链接」）：`python3 scripts/fetch.py "<飞书链接>" <版本>` → 读图 → 提炼落 `notes/` → `python3 scripts/relate.py --write` → `python3 scripts/build_index.py`
- **写用例前检索**：`python3 scripts/search.py <关键词>` · `python3 scripts/search.py --module <模块>` · `python3 scripts/search.py --version <版本>`
- **要看超大图**（`.read` 副本不在时）：`python3 scripts/read_cache.py <slug>`;看完 `python3 scripts/read_cache.py --clean <slug>`

## 目录(本 skill 根 = `qa-knowledge-base/`)

- `raw/` — 原料层(只读:原文 + 正文表格 + 内嵌表格 `sheets.json` + 图片原图 + 抓取元信息)
- `notes/` — 笔记层(每篇需求一份 Markdown)
- `index/INDEX.md` — 索引(`模块 | 版本 | 标题 | 链接 | 一句话摘要`)
- `taxonomy.md` — 功能模块清单 + 标签体系(**边 ingest 边长**)
- `scripts/` — 机械活脚本(抓取 / 关联打分 / 索引生成 / 检索 / 读图副本重建 / 图片去重)
- `wiki/` — 编译层(v2,先空)
- `docs/` — 设计文档

## 分工原则

- **【脚本】** 机械活:抓取、下图、关联打分、写文件、生成索引。
- **【Claude】** 语义活:读图、判断模块、提炼功能信息。

## ingest:收到一个飞书需求文档链接,按这个流程处理

> **多篇批量时**:可一次抓取多篇(第 1 步),但第 2–3 步**必须逐篇独立处理**(读完一篇全文+图、落盘,再开下一篇,严禁多篇揉一起读 → 防串味、防注意力稀释);全部落盘后第 4–5 步**统一各跑一次**即可。
> **fetch 调用纪律**:输出量大时勿用 `| tail`/`| grep` 接管道(SIGPIPE 会假报 exit 1,文件其实已写完),重定向到文件再看;图多的篇(20+ 图)单次可能超 2 分钟,单独跑给足超时。

1. **【脚本】抓取**:拉正文 + 正文表格(保行列)+ **内嵌 Sheet / 多维表** + 下载文档里所有图片,原样存进 `raw/`(只读存档,事实来源)。
   - **版本来源**:输入优先「版本号 + 链接」(如 `V1.31 <链接>`),给了就用你的(权威);没给则脚本从文档提取候选(基本信息"版本号"字段 + figma 链接 + 正文 `VX.X`)。
   - **内嵌表格**:`block_type=30`(Sheet)/`18`(多维表)的内容**既不在 `content.txt` 也不在 `blocks.json`**(块里只有 token),由 fetch 单独抓进 `raw/<slug>/sheets.json`。meta 的 `tables` 只数正文表格,**别用它判断"有没有表"** —— 看 `embedded_sheets` / `embedded_bitables`。
2. **【Claude】读图(智能读)**:**≤ 6 张图 → 全读**;**> 6 张 → 只读可能含独有信息的关键图**(UI 状态 / 流程时序 / 数据·字段图),其余只存档 + 链接、不逐张读。读到的图转成文字。**超大图(>1900px)读 `*.read.png` 缩放副本**(原图保留)。
   - ⚠️ **读图前先看 `ls raw/<slug>/images/`:凡有同名 `img-NN.UNREADABLE.txt` 标记的,直接跳过,连原图都不要打开** —— 读图工具会把原图自动压到 ~2000px,结果和糊掉的缩放副本一样,打开只会诱导你去猜。
   - ⚠️ **fetch 标为「❌ 不可读」的图:不读、不猜、不生成副本,并就地落 `.UNREADABLE.txt` 标记**。判据是**缩放比例**(`1900 ÷ 长边`)< 15% —— 文字按比例缩小,缩到 13% 时 24px 的字只剩 3px,**只剩布局轮廓**。
     这类图必须在图说明里**如实写**:「原图 W×H,缩放后仅 X%,文字不可读,**未读取**(原图存档:`images/img-NN.png`)」。
     **严禁从布局形状推断内容** —— 实测老笔记里就有「整体流程长图:完课 → 超越动效 → 排名上升 → Continue 回首页」这种描述,是看形状猜的,丢掉了图里真实写着的「新人首次触发在第 2 课学习完成」「排名上升至前 3 名」等触发条件与分支。
   - ⚠️ **标为「存疑」的图(缩放 15–25%)**:读得清就写,读不清就按上面的格式如实标注,同样不许猜。
   - **判据只看缩放比例**,不看长宽比、也不看短边像素 —— 实测 `2086×220`(极扁但几乎不缩,91%)完全可读,`3568×750`(缩到 53%)清晰,而 `15146×2316`(缩到 13%)一个字读不出。
   - 归档格式是 **WebP q80**(原图转换后即删,事实来源是飞书,`blocks.json` 存着 token 可重下);派生副本 `.read.png` 统一是 PNG —— `sips` 能读 WebP 但**只能写 PNG**。
   - ⚠️ **`.read` 副本是可重建缓存,平时不留存**(实测常驻会占 123MB / 全库 23%)。fetch 后紧接着读图时它还在;**事后复核/重读**若发现文件不在,跑 `python3 scripts/read_cache.py <slug>` 就地重建(`sips -Z 1900`,实测字节级精确一致,路径与笔记/meta 记录完全相同)。

3. **【Claude】判断 + 提炼 + 落笔记**(⚠️ **落笔记是 Claude 手写,没有"落笔记脚本"**;脚本只管抓取/关联/索引):
   - ⚠️ **fetch 摘要报了「内嵌表」就必须先读 `raw/<slug>/sheets.json` 再提炼** —— 埋点表、三语文案表、数据回收表常常整段只存在于内嵌表里,只读正文会漏掉核心内容(实测有正文仅 402 字符、内容全在内嵌表的需求文档)。
   - 定模块:先查 `taxonomy.md`——能归已有模块就用已有名;新功能 → 新建一级模块;已有模块的子功能 → 归二级;新模块写回 `taxonomy.md`。
   - 定版本:**用户给了版本就用用户的(权威)**;文档"版本号"字段常是**模板残留值**(实测见过 V1.0、比实际低或高的版本号),不可轻信。仅当**用户没给、且候选冲突**(文档字段 ≠ 正文上线版本)时,标 `版本: 待确认` 并提示用户,不臆测。
   - 手写 `notes/日期-模块-标题.md`:
     - frontmatter:`标题 / 模块 / 版本 / related: []`(留空占位,第 4 步脚本回写)`/ 原链接 / 日期`
     - 正文:`## 摘要`(一句话)、`## 功能信息(逻辑/状态/边界/字段)`、`## 图说明`(每张图带**本地链接** + 读到的图转文字)
     - ⚠️ 本地链接里的目录名是 **fetch 清洗后的 slug**(标题空格转 `-`,特殊字符可能保留如 `—`/中文括号),不是原标题 —— 写链接/读图前先 `ls raw/` 确认实际目录名。
4. **【脚本】算关联**:`python3 scripts/relate.py --write` —— 读 `notes/` 比对(**同二级模块 或 共享功能标识符**),双向回写 `related`(新指老,老也回写指新)。
   - ⚠️ **一级模块不算关联**(2026-08-28 改):同一级模块的篇由 `INDEX.md` 与 `search.py --module` 覆盖,再写进 related 只会让大模块内部全互连(实测 AI Tutor 17 篇彼此全连)。改用**二级模块**,连的是同一功能的历次迭代。
   - 不参与关联的:通用词、埋点公参,以及**按命名模式识别的参数字段**(`*_id / *_name / *_type / *_count …`)—— 用规则而不是手工黑名单,因为黑名单已失守三次(`level_number` → `image_count` → `block_type`)。
5. **【脚本】更新索引**:`python3 scripts/build_index.py` 重建 `index/INDEX.md`(`模块 | 版本 | 标题 | 链接 | 一句话摘要`)。
6. **【脚本】收尾省空间**(每批 ingest 落盘后跑一次,**顺序不能乱**):
   - ① `python3 scripts/read_cache.py --clean --all` —— 清掉读图缩放副本(derived,要时重建)。
   - ② `.venv/bin/python scripts/compress_images.py --write` —— 原图转 **WebP q80** 归档;判定不可读的图直接降为 1900px 占位。
   - ③ `python3 scripts/dedupe_images.py --write` —— 转换会改写文件、打断硬链接,要重新去重。
   > ⚠️ **转换必须在第 2 步读图之后**:首次提炼永远用刚下载的无损 PNG,有损只影响事后复核(已实测复核质量无损失)。
   > 依赖:`compress_images.py` 需要 Pillow(项目级 `.venv/`)。`fetch.py` / `read_cache.py` / `search.py` 等**保持零依赖**,同事装 skill 不受影响。

## 取:检索(写用例前用)

【脚本】`search.py` 做机械检索;【Claude】做跨篇综合。

1. **模块/关键词检索** —— "跟这个新需求相关的历史需求有哪些?"
   - `python3 scripts/search.py <关键词…>` 或 `--module <模块名>` → 命中笔记列表(模块/版本/标题/摘要/related)。
   - 英文/数字关键词按**词边界**匹配(中文仍是子串);正文命中按该词**库内覆盖率降权**,高覆盖词(如「埋点」覆盖 75%)自动沉底;多词查询**全中的排前**;默认只列前 15 条,要全量加 `--all`。
   - Claude 整理给用户;要细节就读对应 `notes/`。

2. **模块历史问答** —— "X 模块历史上有哪些功能/边界/坑?"
   - `python3 scripts/search.py --module X` 列出该模块所有笔记 → Claude 逐篇读 → **按版本排成时间线**综合:功能演进、边界、坑、⚠️ 标注项。

3. **新需求关联 + 回归点(核心)** —— 丢一篇新需求链接
   - `python3 scripts/fetch.py <链接> [版本]` 抓取 → Claude 读懂新需求 → 用 `search.py`(关键词)/ 同模块 / 共享埋点 找出相关往期笔记 →
   - Claude 综合输出:**① 相关往期功能清单**(带逻辑/边界,引用具体笔记)+ **② 该重点回归的点**(= 新需求 ✕ 历史功能 的交叉判断,**此刻现算,不预存**)。
   - 可选:这篇本就是新需求,顺手 ingest 入库(走"进")。

4. **按版本列需求** —— "V1.31 这版有哪些需求要测?"
   - `python3 scripts/search.py --version V1.31` → 列出该版本所有需求(贴 2 周一迭代:本次要测的全集;`V1.31` 也匹配 `V1.31.x`)。
