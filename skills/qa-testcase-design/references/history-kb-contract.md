# qa-knowledge-base 历史知识只读契约

本文件定义 `qa-testcase-design` 接入 `qa-knowledge-base` 时的读取、筛选和合并规则。**v2 已启用**：出例前（工作流步 3.5）只读检索 qa-knowledge-base，检索用现成 `qa-knowledge-base/scripts/search.py`。下文"v2 启用时"即指当前默认行为。

## 只读契约

- v2 启用时，只能把 `qa-knowledge-base` 当历史需求知识来源读取。
- 不修改 qa-knowledge-base 知识库本体。
- 不 ingest 新文档，不回写新缺陷，不更新索引，不迁移目录。
- 不复制本次生成的测试用例到 qa-knowledge-base；执行后发现的新缺陷/回归点只在交付末尾提示用户后续可单独回流。

## 何时读

v2 启用时，在需求理解与待确认整理完成后读取，位置在 SKILL 工作流第 3 步之后、第 4 步风险判断之前。

只为补足通用覆盖清单补不到的历史上下文：

- 历史逻辑：同一模块过去已经定义过的业务规则、状态含义、展示口径。
- 旧边界：旧需求里出现过的阈值、异常分支、端差异、兼容限制。
- 相邻入口：同功能在其他入口、其他端、其他课程/活动形态下的触发路径。
- 回归线索：本次改动可能影响的旧链路、配置、埋点、资源、跨端状态。

## 检索输入

从本次 PRD 提炼检索词，不让模型自由发散：

- 模块名、版本号、需求标题、核心功能名。
- 关键页面、入口、状态、配置名、AB 名、接口/字段、埋点事件。
- 课程类型、端范围、Unity/H5/Flutter/backend 等技术边界。
- PRD 中的专有词、枚举值、阈值、资源名。

## 最小检索词组

每次 v2 历史编译至少覆盖以下检索词组；没有对应信息时，在 `history-hits.md` 写明缺失原因。

| 词组类型 | 来源 | 示例 |
|---|---|---|
| 模块词 | PRD 所属模块、标题中的核心模块 | `语音识别`、`奖励中心` |
| 功能词 | 本次新增/改动的功能名、入口名、玩法名 | `跟读组件`、`练习提醒` |
| 埋点或字段词 | 埋点事件、接口字段、配置名、AB 名、状态名 | `word_review_*`、`reminder_enabled` |
| 相邻入口词 | 可能共用逻辑的入口、端、课程形态、容器 | `课程详情页`、`Unity`、`Android` |

可补充版本词（如 `V1.33.0`）和 PRD 专有词，但不能用泛词替代上面四类。

## 检索证据文件

每次启用 qa-knowledge-base 时，在本次输出目录旁生成/维护 `history-hits.md`，作为交付附录；它不写入 qa-knowledge-base，也不进思维导图。用户明确不想要独立文件时，把同样内容放进 `testcases.md` 末尾的「历史检索摘要」。

`history-hits.md` 必须记录每组检索词和每条有效命中取舍：

| 检索词组 | 命中笔记 | 判定 | 理由 | 编入位置 |
|---|---|---|---|---|
| 模块词：语音识别 | notes/...md | 保留 / 丢弃 / 待确认 / 未命中 | 保留理由或丢弃理由 | P0-01 / Q2 / 风险判断 / 覆盖自检表 / - |

- 保留理由：说明它为什么影响本次测试，例如同模块、共享字段、共享入口、旧边界会被本次改动触发。
- 丢弃理由：说明它为什么不影响本次测试，例如只命中泛词、模块不同且无共享标识符、旧功能已被 PRD 明确替代。
- 编入位置：必须写最终落点；保留但没有落点的历史线索视为未完成。

## 深读规则

`search.py 输出只是召回`，不能只看 search.py 摘要就把历史线索写进用例。所有判定为保留或待确认的命中，必须深读对应 `notes/*.md`；未深读的命中不能作为用例依据，只能标为丢弃或待读。

深读 `notes/*.md` 时至少提取：

- 历史逻辑：旧业务规则、状态含义、展示口径。
- 旧边界：阈值、异常分支、端差异、兼容限制。
- 相邻入口：同功能在其他入口、端、课程形态下的触发路径。
- 回归线索：本次改动可能影响的旧链路、配置、埋点、资源、跨端状态。

### 高风险原料回看

对 Top 1-3 个高风险历史命中，如果 `notes/*.md` 信息不足，必须回看 `raw/` 原料或原飞书链接，不能只依赖摘要笔记。这里的“信息不足”包括：影响 P0/P1 的接口字段、AB/配置口径、埋点事件/属性、阈值边界、端差异、图表细节或与本次 PRD 冲突的规则在 notes 中没有写清。

- 优先回看知识库本地 `raw/` 原料（正文、表格、图片、meta）；本地原料不足或不可定位时，再按笔记里的原链接只读打开/读取原飞书链接。
- 上限是 Top 1-3 个，按“对本次风险影响”排序，不按 search.py 分数机械排序；普通低风险命中仍以 notes 深读为准。
- 回看后只把确认出的历史逻辑、旧边界、相邻入口、回归线索编入用例；仍然不能覆盖本次 PRD。
- 回看结果必须写入 `history-hits.md` 的理由或编入位置说明，例如“已深读 notes；notes 未写明阈值，已回看 raw 表格后编入 P1-03”。如果 raw/原飞书链接不可达，写入「风险与待确认」或丢弃理由。

如果保留笔记的 frontmatter `related` 指向明显相关的旧需求，继续读相关笔记；若不读，必须在 `history-hits.md` 标为待读/丢弃并写明原因。

## 命中筛选

保留命中必须满足至少一个条件：

- 同模块。
- 共享功能标识符，例如同一入口、配置名、状态名、接口字段、埋点事件、资源类型、课程形态。

排除通用词命中：登录、首页、按钮、弹窗、正常、失败、level_number、unit_number 这类跨需求高频词不能单独作为相关依据。

## 合并规则

- 历史命中不是用例，只是用例设计素材；必须再结合本次 PRD、覆盖清单和测试设计方法重新编译。
- qa-knowledge-base 不覆盖 PRD；PRD 与历史资料冲突时，冲突进入待确认，不静默选择其中一边。
- 历史知识不能新增叶子字段；叶子仍保持 `[P0-01] 标题｜前置｜步骤｜期望`。
- 历史线索必须转成以下之一：风险判断、showcase（提测准入）、用例设计（业务功能用例）、APP 常驻维度补充、风险与待确认、覆盖自检表说明。
- 每条保留历史线索都要能说明“为什么影响本次测试”；说不清影响的命中丢弃。

## 待确认规则

以下情况不追问，直接写入第 6 块「风险与待确认」：

- 历史资料只提示低频边界，但不影响 P0 主链路。
- 历史资料提示可能存在端差异，但 PRD 没给端范围。
- 历史资料提示旧配置/旧埋点，但本次 PRD 没明确复用。

以下情况停下问用户：

- 冲突会影响 P0 主链路是否可发版。
- 冲突会影响接口、配置、AB、测试环境前置。
- 历史资料显示旧逻辑可能与本次 PRD 目标相反。

## 自检

v2 启用后，交付前检查：

- 是否明确写了“已读 qa-knowledge-base / 未读 qa-knowledge-base / 未命中相关历史”。
- 是否产出 `history-hits.md` 或等价「历史检索摘要」，且记录检索词组、保留/丢弃理由、编入位置。
- 是否对所有保留/待确认命中深读了 `notes/*.md`；不能只看 search.py 摘要。
- Top 1-3 个高风险命中若 notes 信息不足，是否已回看 `raw/` 原料或原飞书链接，并在 `history-hits.md` 记录结果。
- 每条保留历史线索是否都落到用例、风险、待确认或覆盖自检表。
- 覆盖自检表是否有 `历史回归` 维度；未命中时状态写 N/A，并说明未命中。
- 是否没有修改、写入、迁移 qa-knowledge-base 知识库本体。
