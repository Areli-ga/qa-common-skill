# 出例核心手册（单文件装载版）

> 本文件把 `coverage-dimensions.md`（覆盖维度）、`case-schema.md`（用例结构）、`test-design-methods.md`（测试设计方法）的**全部硬规则**合并为一次读取，供工作流步 4-7 使用。三个原文件保留作深度参考：本文件与原文件冲突时以原文件为准并回报修正本文件。校验失败排查或需要完整样例时，再读 `example-testcases.md`。

## A. 覆盖维度（逐维过闸，每维只能 已覆盖 / N/A / 待确认，禁止默默跳过）

### 产品链路

- 启动：冷启动、杀进程重启、首装、升级、热更检查、资源下载、失败重试。
- 账号：游客、登录、注册、新老用户、会员/非会员、儿童档案、国家码、权限弹窗。
- 学习：地图、推荐课、进课、课中互动、完课、退出、重进、结算、奖励、进度同步。
- 内容：课程资源、故事书、挑战课、报告、证书、明日预告、搜索、多语言文案。
- 运营：ABTest、后台开关、弹窗、Banner、活动、奖励中心、扭蛋、配置灰度。

### 技术端覆盖

| 端/模块 | 必测关注 |
|---|---|
| Android 原生 | 权限、返回键、生命周期、低端机、安装升级、系统版本、网络切换 |
| iOS 原生 | 权限、前后台切换、弱网恢复、内购/登录态、不同机型安全区 |
| Unity | 资源加载、场景切换、动画/Spine、性能、内存、崩溃、课中状态恢复 |
| H5 | WebView 判定、Bridge 时序、登录态/语言、路由、缓存/离线包、资源 CDN、语音/音频、埋点、旧 WebView 兼容 |
| Flutter | 页面状态、路由栈、原生桥、渲染、键盘/安全区、异步加载 |
| 后端 | 接口入参/出参、错误码、幂等、超时、重试、数据一致性、灰度配置 |

### 通用场景

- 主流程：按 PRD 用户路径从入口到结果完整走通。
- 反向/中断：中途退出、断网、杀进程、切后台、重复点击、快速切换。
- 状态矩阵：新/老用户、未/已解锁、未/已完成、有/无奖励、有/无配置。
- 弱网：无网、2G/3G、超时、资源下载中断、接口失败后恢复。
- 兼容：不同系统、屏幕、低端设备、横竖屏/安全区。
- 数据一致性：客户端展示、后端记录、进度、奖励数量、埋点与配置命中一致。
- 回归：受影响模块老路径、相邻入口、历史缺陷路径、提测说明关联模块。

### 代码风险库（按端命中才读，不全量灌入）

| 风险库 | 什么时候读 |
|---|---|
| `code-risk-backend.md` | 接口、奖励、计数、每日/连续、档案隔离、异步生成、多语言兜底 |
| `code-risk-unity.md` | Unity 玩法、课程资源、热更、动画、视频音频、低端机、Unity↔原生通信 |
| `code-risk-native.md` | Android/iOS 容器、权限、录音、推送、深链、网络、登录态、容器切换 |
| `code-risk-h5.md` | H5/WebView、bridge、离线包、缓存、i18n、音频、神策/Sentry、分享/上传 |

读取规则：只编入命中本需求的风险点；不涉及的端标 N/A；风险库不覆盖 PRD，冲突进「风险与待确认」；不沉淀敏感值。

### 风险提示

- 多端联动易漏端间状态同步；Unity 资源/动画变更易白屏、卡死、内存上涨。
- 后台配置/AB 未写清必须标待确认，并要求测试前固定配置。
- 热更/资源/启动链路失败必须验证可恢复和用户可理解的失败状态。
- PRD 只有视觉稿时，补问交互、接口、边界、空态、异常和灰度策略。

## B. 测试设计方法（出例前给每个功能点挂 1-2 个方法）

### 从 PRD 到用例 6 步

拆对象（用户/入口/页面/端/接口/配置/埋点）→ 拆规则（条件/状态/阈值/枚举/异常）→ 建模型（状态表/判定表/因子表/基本流）→ 选方法（按决策表）→ 选数据（用 PRD 真实入口、词、字段、阈值；没有就写待确认）→ 写叶子（能执行、能判定、能追溯）。

### 需求拆解检查单（容易漏的用例）

| 拆解项 | 容易漏 |
|---|---|
| 用户/身份 | 未登录、切换孩子、会员过期、权限不足 |
| 入口 | 深链、Push、活动入口、旧入口复用、冷/热启动再进 |
| 状态 | 中断恢复、非法事件、重复触发、状态回滚 |
| 数据 | 前端展示与后端落库不一致、缓存脏数据、重复提交 |
| 配置/AB | 命中/未命中、配置缺失、旧版本兼容 |
| 端范围 | 单端通过但跨端回调、容器生命周期、端差异 |
| 失败恢复 | 只测报错不测重试/跳过/恢复后数据状态 |
| 埋点 | 事件重复、失败分支不上报、字段空/null/旧值 |
| 历史回归 | 旧入口、旧配置、旧埋点、旧资源被本次改动影响 |

### 充分性标准

- 每条业务规则 ≥1 正向路径；有明确反向/异常规则必须覆盖反向。
- 每个状态覆盖进入、退出、关键中断；状态机覆盖合法迁移 + 关键非法迁移。
- 每个数值/次数/长度/时间阈值覆盖 边界内、正好边界、越界 1 点。
- 每个配置/AB 覆盖 命中、未命中、缺失/关闭；口径未写进「风险与待确认」。
- 每条核心数据链路覆盖 展示、写入、刷新/回访、跨端或下游消费一致性。
- 每个失败分支验证 提示 + 重试/跳过/返回 + 恢复后继续。

### 可执行用例标准

前置写清 账号/端/版本/配置/权限/网络/历史状态；步骤用真实动作和真实数据；预期可判定（页面反馈、状态、数据、埋点）；待确认不藏在用例里，标题标「（待确认）」+ 原因进「风险与待确认」。反例：「验证 XX 功能正常」「检查埋点正常」「测试弱网」这类无入口、无数据、无判定的叶子禁止出现。

### 方法速查（触发 → 要点 → 陷阱）

1. **等价类**：输入/参数/枚举/身份态 → 有效类 + 无效类各 ≥1 → 陷阱：漏无效类。
2. **边界值**：数值/数量/长度/次数/时间 → 边界内/正好/越界+1，含 0、空、超长 → 陷阱：只测中间值。
3. **判定表**：多条件组合决定结果（开关/权限/AB×国家×身份） → 列条件桩×动作桩每规则 1 例 → 陷阱：漏组合。
4. **状态迁移**：状态机/生命周期/计数器 → 每状态、每合法迁移、关键非法迁移 → 陷阱：漏非法事件与中断恢复。
5. **场景法**：端到端流程 → 基本流 + 备选流 + 异常流（异常要闭环到恢复） → 陷阱：只走 happy path。
6. **正交/Pairwise**：机型×系统×网络×语言兼容矩阵 → 两两覆盖 + 必测强组合 → 陷阱：盲目全组合或只测默认。
7. **错误推测**：收尾兜底 → 空值/超长、重复提交、连点、并发、杀进程、断网重连、权限拒绝、时区/多语言、缓存脏数据 → 陷阱：当唯一方法用。

### 特征 → 方法决策表

| 特征 | 优先用 |
|---|---|
| 输入框 / 参数 / 枚举 / 状态 | 等价类 + 边界值 |
| 数值 / 数量 / 长度 / 次数 / 时间范围 | 边界值 |
| 多条件组合决定结果（开关/权限/AB） | 判定表 |
| 状态机 / 生命周期 / 计数器 | 状态迁移 |
| 端到端用户流程 | 场景法 |
| 多端 / 多环境兼容 | 正交 / Pairwise |
| 收尾兜底、历史易错点 | 错误推测 |

方法只用于设计推导；输出时不展开方法论，只在覆盖自检表「说明」短标 `方法=xxx`。

## C. 输出结构（testcases.md 的 7 块骨架，顺序固定）

1. 需求理解（目标/入口/用户路径/状态/端/接口/AB/埋点/验收口径）
2. 风险判断
3. showcase（提测准入）
4. 用例设计（按业务功能 / 需求类目组织）
5. APP 常驻维度补充
6. 风险与待确认
7. 覆盖自检表

P0/P1/P2 只是 `priority` 属性，体现在用例 ID、自检表和执行优先级；**禁止作为正文一级目录**。

### ⚠️ 机器校验硬规则（写例前必看，违反则 `validate_output.py` 直接 FAIL、无法自动发布）

以下 4 条是脚本逐字解析的规则，差一点用例就不被识别、校验失败、卡在发布前：

1. **用例行必须写在 ` ```text ` 代码块内**——校验只在代码块里找用例。写成裸列表 `- [P0-01] …` 不会被识别（报 `no executable case lines found`、`showcase … found 0`）。
2. **行首必须直接是 `[P0-01]` 编号，不带 `- ` 前缀**（ID 形如 `P0-01`/`P1-02`/`P2-03`，两位数字）。
3. **七块标题必须与上方清单逐字一致**——尤其第 4 块必须写全称 `用例设计（按业务功能 / 需求类目组织）`，缺括号后缀会报 `missing section`；标题前可带 `## 4. ` 序号，序号会被自动忽略。
4. **同一分组的多条用例放进同一个 ` ```text ` 块**；`showcase（提测准入）`、第 4 块、第 5 块的用例都这样写，业务分组用块外的 `###/####/#####` 多级标题区分（分解树，见下方第 4 块规则）。
5. **粒度闸（2026-07-08 起）**：第 4 块单个 `###` 组下用例 >4 条且无 `####` 细分 → FAIL；单条用例期望 >140 字 → FAIL（>90 字告警）。showcase 的场景式演示 case 不受分组闸限制，但期望同样受长度闸约束。

最小骨架（照抄结构、替换内容即可过校验）：

```text
[P0-01] 用例标题｜前置：…｜步骤：…｜期望：…
[P1-01] 用例标题｜前置：…｜步骤：…｜期望：…
```

每条用例必须同时含 `｜前置：`、`｜步骤：`、`｜期望：` 三段；依赖未确认信息的标题加「（待确认）」并在第 6 块补对应 `Q` 项。

### 需求理解写法

必须用 `- ` 无序列表，至少包含 `目标`、`入口`、`端范围` 三项；可按需求补 `用户路径`、`数据/埋点`、`配置/AB`、`验收口径`、`待确认`。不要写成长段落，飞书发布后会降低可扫读性。

### 风险判断写法

一句话点题「本次最该测什么」+ **3-5 个 `- ` 要点**（每点一句：牵动模块/状态联动/历史风险/数据一致性）。保持判断性表述（"最该测""最容易崩在"），不要中性复述，不要长段落。

### showcase（提测准入）

- 从核心主路径抽 **1-5 条**演示 case（validate 强制）；标准=不通过就不达提测标准；优先覆盖「入口→核心操作→核心反馈→核心数据」闭环。
- 用同一套叶子格式与稳定 ID（可用 P0 ID）；同一 ID 不在第 4 块重复写；不是完整回归集。
- 覆盖自检表必须有 `showcase（提测准入）` 维度。

### 用例设计（第 4 块）—— 先树后例（2026-07-08 起为硬规则）

写用例行之前，先在本块用 `###/####/#####` 多级标题把需求拆成**分解树**，用例只挂在树的叶层。思维导图直接由这棵树长出来——**树有多深图就有多深，结构塞进用例行文字里=结构直接丢失**（渲染层永远无法从一行字里恢复层级）。

- 树的形态：`###` 业务功能 → `####` 状态机 / 分支矩阵 / 数值组 / 交互面 → `#####` 更细的状态 / 分支（按需继续加深，转换器支持任意深度）。每层要有真实区分度，禁止「功能点」「其他」这类占位名。
- **分解粒度硬要求**（这是导图质量的源头，validate 有对应闸门）：
  - PRD **数值设定逐项成节点**：血量公式、每档伤害、触发次数、上限阈值……各自一个 `####`/`#####` 或独立用例，禁止合并进一条用例的期望里；
  - **分支表/反馈表逐行成节点**：正确 / 错1 / 错2 / 保底 / 超时 各自一个子节点，每行的演出、数据、后续各自成例；
  - **每个结局/状态各自成节点**：触发条件、演出明细、结算结果分开验证；
  - 一个 `###` 组下用例超过 4 条却没有 `####` 细分 → validate 直接 FAIL。
- **原子用例**：一条用例只验证**一个可判定断言**。期望里出现两个独立断言（两个数值、两条链路、两种状态）必须拆成两条。期望超过 90 字 validate 告警、超过 140 字 FAIL。反例：「初始血量分别为2与7；每读对−1；两者同步下降」——这是三条用例。
- 同一叶层分组的多条原子用例放同一 ` ```text ` 块，挂在对应标题下。
- 表格到方法的映射不变：状态表→状态迁移；新旧差异表→回归对比；多分支流程→判定表/场景法；行为绑定数据→行为+埋点成对校验。

### APP 常驻维度补充（第 5 块）

常驻一级维度：**边界/兼容、跨端联动、后端/配置、AB、埋点、多语言兼容**。

- 已在第 4 块充分覆盖的维度写 `无补充，已在 P0-xx 覆盖`；完全不涉及写 `无` 且自检表标 N/A；不为凑维度写空泛用例。
- 后端摆放：与本需求业务强绑定的后端用例进第 4 块；通用后端面（幂等/字段兼容/灰度回退）进第 5 块；同一条只放一处。

### 用例叶子格式

```text
[P0-01] 用例标题｜前置：...｜步骤：...｜期望：...
```

- ID 每优先级内从 01 递增；正文、自检表、history-hits.md 引用同一 ID；思维导图默认隐藏 ID。
- **一例一断言**（原子用例，见第 4 块规则）：期望只写一个可判定结果；多个数值/链路/状态拆成多条，靠分解树标题组织，不靠一行长期望打包。
- 步骤具体可执行，禁「验证功能正常」类空泛叶子；不编造产品逻辑/接口字段/AB 策略/视觉标准。
- 标题写可判定行为，不写「测试 XX 功能」；前置/步骤/期望用 PRD 真实入口、状态、词、配置名、字段、示例数据。
- **标题禁带来源/归属括号标注**（「历史回归」「后端风险」「端差异」等会污染思维导图并被校验拦截）；唯一允许的括号是「（待确认）」。
- 依赖未确认信息的用例标「（待确认）」，原因统一进第 6 块 Q 项（validate 强制关联）。
- 不在叶子里塞 `来源/待确认` 字段；历史/风险库来源只写进自检表「说明」与 history-hits.md。

### 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 不通过不能发版：主链路、启动、登录、奖励、学习进度、热更、核心接口/配置 |
| P1 | 重要路径：常用分支、配置/AB、跨端状态、异常恢复、弱网恢复 |
| P2 | 边界、兼容、探索、低频状态、文案/视觉细节 |

### 风险与待确认（第 6 块）

表格：`编号 | 问题 | 影响`；Q 项写明影响哪些用例 ID；历史资料与 PRD 冲突进这里，不静默取舍。低频边界不追问直接写入；只有影响 P0 主链路 / 接口配置 AB 发版口径 / 测试环境前置时才停下问用户。

### 覆盖自检表（第 7 块，validate 硬规则）

格式：`维度 | 状态 | 对应用例 | 说明`。

- 每条用例 ID 必须至少出现一次；状态只能 `已覆盖 / N/A / 待确认`。
- `已覆盖` 必须关联 ≥1 个用例 ID；`N/A` 不关联 ID 且写理由；`待确认` 关联受影响用例或 Q 项。
- 必含维度：`showcase（提测准入）`、`历史回归` + 六个 APP 常驻维度（边界/兼容、跨端联动、后端/配置、AB、埋点、多语言兼容）；无关写 N/A 不删除。
- `历史回归`：有线索标已覆盖/待确认并关联 ID；未命中标 N/A 注明「qa-knowledge-base 未命中」；未读注明「未读 qa-knowledge-base」。
- 说明列可短标 `方法=xxx` 与历史来源；禁止只写「已检查」。

### 历史补充（qa-knowledge-base）

历史命中不是用例，必须重新编译落到：风险判断 / showcase / 第 4 块用例 / 第 5 块补充 / 风险与待确认 / 自检表说明。不新增块、不改叶子格式、不把 qa-knowledge-base 原文贴进来；qa-knowledge-base 不覆盖 PRD。检索证据记录在 `history-hits.md`（规则见 `history-kb-contract.md`）。

### 思维导图映射边界

第 4/5 块标题层级 + 3 块（需求理解/风险与待确认/覆盖自检表）不进导图；showcase 是导图第一个一级节点；由 `md_to_mindmap.py` 确定性转换，不手写 PlantUML。
