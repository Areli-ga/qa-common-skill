# 测试用例设计方法（出例前必读）

覆盖清单解决"测哪些**面**"，本文件解决"每个面里**怎么专业地设计**"。二者是「面 × 方法」：先用覆盖清单定面，再按下方「特征→方法」决策表给每个面挂方法，再展开用例。不是每个方法都用，按特征选 1–2 个。

## 从 PRD 到用例的 6 步

1. 拆对象：识别本次影响的用户、入口、页面/组件、核心对象、端、接口、配置、埋点。
2. 拆规则：把 PRD 正文、表格、流程图里的条件、状态、阈值、枚举、异常分支抽出来。
3. 建模型：多状态用状态迁移表；多条件用判定表；多环境用因子水平表；端到端路径用基本流/备选流。
4. 选方法：按「特征→方法」决策表给每个功能点挂 1–2 个测试方法，不要只凭感觉列场景。
5. 选数据：用 PRD 的真实入口、词、参数、配置名、字段名、阈值；没有真实数据就写待确认，不用“某数据”糊弄。
6. 写叶子：每条用例必须能执行、能判断、能追溯到需求规则或历史风险；写完进覆盖自检表。

## 需求拆解检查单

| 拆解项 | 要问的问题 | 容易漏的用例 |
|---|---|---|
| 用户/身份 | 谁能看到/操作？登录态、会员态、儿童档案是否影响？ | 未登录、切换孩子、会员过期、权限不足 |
| 入口 | 从哪些入口进？冷启动/热启动/返回后再进是否一致？ | 深链、Push、活动入口、旧入口复用 |
| 状态 | 功能有哪些状态？状态之间靠什么事件切换？ | 中断恢复、非法事件、重复触发、状态回滚 |
| 数据 | 数据从哪里来、写到哪里、哪里展示？ | 前端展示和后端落库不一致、缓存脏数据、重复提交 |
| 配置/AB | 开关、灰度、国家、语言、版本怎么命中？ | 命中/未命中、配置缺失、旧版本兼容 |
| 端范围 | Android/iOS/Unity/H5/backend 哪些参与？ | 单端通过但跨端回调、容器生命周期、端差异 |
| 失败恢复 | 接口失败、识别失败、资源失败、弱网如何恢复？ | 只测报错不测重试/跳过/恢复后的数据状态 |
| 埋点 | 哪个行为触发哪个事件，字段从哪里取？ | 事件重复、失败分支不上报、字段空/null/旧值 |
| 历史回归 | qa-knowledge-base 命中过哪些旧规则、旧边界、相邻入口？ | 旧入口、旧配置、旧埋点、旧资源被本次改动影响 |

## 充分性标准

- 每条业务规则至少覆盖 1 条正向路径；有明确反向/异常规则时必须覆盖反向路径。
- 每个状态至少覆盖进入、退出和关键中断；状态机需求必须覆盖合法迁移和关键非法迁移。
- 每个数值/次数/长度/时间阈值至少覆盖边界内、正好边界、越界 1 点。
- 每个配置/AB 至少覆盖命中、未命中、配置缺失/关闭；PRD 未写口径时进「风险与待确认」。
- 每条核心数据链路至少覆盖展示、写入、刷新/回访、跨端或下游消费的一致性。
- 每个失败分支不能只验证错误提示，还要验证能否重试、跳过、返回、恢复后继续。

## 可执行用例标准

- 前置要写清账号/端/版本/配置/权限/网络/历史状态。
- 操作步骤要写真实动作和真实数据，例如目标词、入口名、开关名、阈值、接口模拟条件。
- 预期结果要能判定：页面反馈、状态变化、数据写入、埋点、后续入口刷新，至少命中本用例核心断言。
- 待确认不藏在用例里；用例标题标「（待确认）」即可，原因统一放「风险与待确认」。

## 方法速查（定义 / 触发特征 / 操作要点 / 常见陷阱）

### 1. 等价类划分
- 定义：把输入/输出域划成若干"等价"子集，每类取一个代表值；**有效类 + 无效类都要**。
- 触发：输入框、参数、枚举、账号/会员/权限状态、分类返回。
- 操作：列有效等价类 + 无效等价类 → 每类 ≥1 用例。
- 陷阱：只测有效类漏无效类；类划得太粗。

### 2. 边界值分析
- 定义：缺陷聚集在边界，取 min−1 / min / min+1 … max−1 / max / max+1。
- 触发：数值范围、数量、长度、次数、时间、血量/分数这类。
- 操作：每个边界取"上/正好/下"三点；含 0、空、超长、最大+1。
- 陷阱：只测中间值；忽略"恰好边界"和"越界+1"。

### 3. 判定表
- 定义：多个条件组合决定不同结果，列条件桩 × 动作桩，覆盖有效组合。
- 触发：多开关/多条件规则、权限矩阵、AB × 会员 × 国家 命中逻辑。
- 操作：列条件 → 枚举组合（可按规则合并）→ 每条规则 1 用例。
- 陷阱：漏组合；条件间有依赖时未化简。

### 4. 状态迁移
- 定义：覆盖状态、事件、**合法迁移 + 非法迁移**。
- 触发：状态机、生命周期、计数器、登录态、播放/下载态。
- 操作：画状态-事件表；覆盖每个状态、每条合法迁移、关键非法迁移（该状态下不该响应的事件）。
- 陷阱：只测正常路径，漏非法事件、漏中断后回到某状态。

### 5. 场景法
- 定义：基本流 + 备选流 + 异常流，串成端到端用户路径。
- 触发：端到端流程、多步骤操作。
- 操作：先基本流，再逐个分支点派生备选/异常流。
- 陷阱：只走 happy path；异常流不闭环（没验证恢复）。

### 6. 正交 / Pairwise
- 定义：多因子多水平、全组合爆炸时，用两两覆盖压缩。
- 触发：机型 × 系统 × 网络 × 语言 × 分辨率 这类兼容矩阵。
- 操作：列因子和水平，取 pairwise 组合，再补必测强组合。
- 陷阱：盲目全组合（测不完）或只测默认组合。

### 7. 错误推测
- 定义：凭经验和历史缺陷列易错点，针对性设计（是补充，不替代前面系统方法）。
- 触发：任何功能收尾都过一遍；尤其接历史坑。
- 操作：空值/0/超长、重复提交、快速连点、并发、杀进程、断网重连、权限拒绝、时区/多语言、缓存脏数据。
- 陷阱：当成唯一方法用。

> 因果图：输入间有逻辑依赖时，先画因果图再转判定表，不单列。

## 特征 → 方法 决策表（逐维过闸时挂载）

| 需求出现这种特征 | 优先用 |
|---|---|
| 输入框 / 参数 / 枚举 / 状态 | 等价类 + 边界值 |
| 数值 / 数量 / 长度 / 次数 / 时间范围 | 边界值 |
| 多条件组合决定结果（开关 / 权限 / AB） | 判定表 |
| 状态机 / 生命周期 / 计数器 | 状态迁移 |
| 端到端用户流程 | 场景法 |
| 多端 / 多环境兼容 | 正交 / Pairwise |
| 收尾兜底、历史易错点 | 错误推测 |
