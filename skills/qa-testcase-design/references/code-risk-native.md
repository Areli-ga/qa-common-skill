# 原生端代码风险库（按需读取）

用途：当 PRD 涉及 Android/iOS 原生容器、权限、录音、推送、深链、网络、登录态、容器切换时，用本文件补充端差异与生命周期测试点。它是测试启发，不替代 PRD。

读取后只编入命中本需求的风险点；不涉及原生端时标 N/A，不要硬塞。

## 常见高风险面

| 风险面 | 触发条件 | 用例补充方向 |
|---|---|---|
| 登录态与档案态 | 入口依赖登录、儿童档案、会员态、家庭账号 | 未登录、登录过期、切换孩子、会员过期、跨端状态刷新 |
| 权限 | 麦克风、相册、通知、存储、相机 | 首次授权、拒绝、系统设置关闭后返回、权限弹窗被打断 |
| WebView/H5 容器 | 原生打开 H5、桥接、导航、分享、上传 | bridge 缺失、返回栈、刷新、关闭、登录态注入、页面崩溃兜底 |
| Unity 容器 | 原生拉起 Unity、传参、回调、退出 | 入参缺失、加载失败、返回首页、切后台、Unity 结果回传丢失 |
| 网络与缓存 | 弱网、断网、接口缓存、离线包 | 超时提示、重试、缓存过期、恢复网络后刷新、重复请求 |
| 推送/深链 | 通知点击、活动入口、外部链接 | 冷启动/热启动、未登录跳转、目标页不存在、参数被截断 |
| iOS/Android 差异 | 系统权限、后台策略、音频焦点、WebView 内核差异 | 两端同一场景分别验证；差异进入覆盖自检表说明 |

## 本产品已知规律（截至 2026-07 代码扫描；端差异是重点，命中即补）

- **离开首页再回来，两端行为根本不同**：Android 销毁重建 Unity（状态全丢 + 重载黑屏），iOS 只暂停常驻内存（秒恢复但有 OOM/音频残留风险）。几乎影响所有「回首页」类用例，两端分开测。
- Android 家长改系统字体/语言 → 首页重建、Unity 从零重载（儿童设备家长常调字体，高频触发）。
- iOS 跟读要过麦克风 + 苹果语音识别两道系统权限，任一被拒都跳过语音；Android 只一道 RECORD_AUDIO。必须单独测 iOS「只拒语音识别」这一态。
- **来电/别的 App 抢麦：iOS 自动暂停并恢复，Android 无音频焦点监听 → 录音静默失败**（孩子对着麦讲但没录进去）。Android 侧最易线上出事的点。
- 弱网/「假 WiFi」（连上但无外网）判定两端相反：Android 校验外网可达、会判离线；iOS 不校验、可能判在线到请求才失败。同一环境两端表现相反。
- iOS 音频会话与 Unity 抢 category：音乐播放中启动识别、识别后恢复音乐易出「识别中无声」死局，iOS 高危回归点。
- 登录态是「原生推、容器不拉」：登录态变化后原生要主动推给各容器；token 过期(401)后原生不回推新 token 给已打开的容器 → 容器拿旧 token；登出后已打开的 Unity/Flutter 页不刷新，可能还显示上个账号。
- **登出清理两端不对等**：Android 清 token + WebView 缓存，iOS 不清 → A 登出 B 登录，iOS 可能残留 A 的 WebView 缓存（安全相关）。
- 冷启动点推送/深链，硬延迟约 5–6.5 秒才跳目标页（等引擎就绪）：会先看到首页再跳，别当卡死。
- FCM token 主动刷新只 iOS 有：Android 卸载重装/Google 服务重置后 token 轮换可能不自动补报，测 Android 换 token 后能否收到推送。
- 深链 open-redirect 白名单只 iOS 实现：Android 带外部 url= 参数的 H5 深链可能被 WebView 直接加载（安全相关）。
- 原生给容器发消息：容器还没加载完就发会直接丢、不重发（推早了 token/用户信息）；单条超 5MB 被丢弃不回错误；30 秒无响应超时。
- 多参数深链（同时带 inviteCode+bookId 等）会同时触发多个动作，测不该开多个页/发多条消息。

## 设计用例时的抓手

- 所有入口类需求补充：冷启动、热启动、已在目标页、返回后再次进入。
- 所有权限类需求补充：允许、拒绝、拒绝后重新授权、系统设置关闭。
- 所有容器类需求补充：原生入参、容器内行为、容器回传、返回栈、异常页兜底。
- 所有端差异不要写成泛泛“Android/iOS 兼容”，要写明具体设备状态、系统权限或容器行为。
